## 2. 변경 내용과 **회귀가 아닌 근거**

`layerControls` 를 **계정별 persist 스토어**로 옮기고 **셀렉터로만** 읽는다.

    store/useSatongMapPrefsStore.ts
      persist((set) => ({ controlsByLayer: initialLayerControls(), setControlsByLayer, resetControls }),
              { name: "propai-satong-map-prefs", storage: createAccountScopedStorage<State>() })

    SatongMapShell
      const layerControls   = useSatongMapPrefs((s) => s.controlsByLayer);      // 셀렉터
      const setLayerControls = useSatongMapPrefs((s) => s.setControlsByLayer);  // 셀렉터

- **회귀 아님**: 초기 상태가 `initialLayerControls()` 그대로다. 저장된 값이 없으면 **지금과 동일**.
- **하이드레이션 안전**: 셀렉터 전용(P5). `useState` 지연 초기값을 **없앤다**(P6 회피).
- **계정 격리**: P2·P3 — 실저장키가 `__<uid>` 라 계정 전환 시 섞이지 않는다.

## 3. ★검증하지 못할 것 / 미리 정할 것

- **저장 스키마 변경 시 마이그레이션** — 컨트롤 id 어휘가 두 벌인 것(`selected` ↔ `selected-parcel`)이
  저장분에 들어간다. 어휘 통합을 나중에 하면 **저장된 옛 id 를 어떻게 할지**가 남는다.
  → `version` 을 두고 **미정임을 명시**한다.
- **브라우저 눈 확인** — 배포 후에만.
- ★★**적대 리뷰가 이 §3 을 무색하게 만든 축 넷**(전부 반영했고, 여기 남긴다 —
  «계획서가 잠갔다고 선언한 것» 과 «실제로 잠긴 것» 이 갈렸던 기록):
  ①**계정 전환 시 재수화 누락** — 소프트 전환에서 다음 계정이 **이전 계정 값을 보고**,
    새 계정의 변경이 **어느 키에도 안 써졌다**(리뷰 실행 실증). 목록형 락이 3에 고정돼 있었다.
    → 등록 + **파생형으로 전환**. ★그 파생형이 **리뷰가 못 본 나머지 절반**(메모리 와이프
      누락)까지 즉시 짚었다.
  ②**얕은 merge** — 저장분 하나가 나머지 8개 레이어 기본값을 **통째로 지웠다**.
    ★내 테스트가 정확히 그 픽스처를 쓰면서 그 파괴를 **못 봤다.** → `merge` + `version`/`migrate`.
  ③**`skipHydration` 변이가 185건을 통과** — 내 「새로고침 시나리오」가 `rehydrate()` 를
    **손으로** 불렀다. 그건 rehydrate 테스트지 새로고침 테스트가 아니다. → 모듈 재임포트 경로.
  ④**컴포넌트→저장 배선 무잠금** — 셋터를 no-op 으로 바꿔도 이 PR 의 락 37건이 전부 통과.
    → 화면 클릭 → `pagehide` → 계정별 키 내용까지 태우는 테스트.
- ★**비대칭 영속(미해결)**: `enabledLayers`(레이어를 켰는지 자체)는 **여전히 `useState`** 다.
  같은 툴바의 절반은 영속되고 절반은 초기화된다. 이 PR 범위 밖으로 두지만 **적어 둔다** —
  리뷰가 «계획서에 언급이 없다» 고 지적했고 그 지적이 맞다.
- ★**되돌리기 UI 미노출**: 액션은 스토어에 있으나 화면 버튼이 없다(소비처 0). 지금은 툴바에서
  각 컨트롤을 다시 켤 수 있어 막다른 상태가 아니지만, 위 ②가 없었으면 **보이지 않는 상태**에
  갇힐 수 있었다.
- ★★**하이드레이션 identity — 이 서술이 틀렸었다(2차 리뷰 MAJOR-1).**
  초판은 *"**저장분이 있는 사용자는**…"* 이라고 **범위를 좁혀** 적었다. 실제로는
  zustand 가 hydrate 에서 merge+set 을 **무조건** 부르고 내 merge 가 객체를 **항상 새로**
  만들었으므로 **저장분이 없는 사용자까지 전부** 새 identity 를 받았다.
  ★그 identity 가 `mapLayerState` memo → `layerState` 로 흘러가고, 이 저장소는 그 귀결을
  **명문으로** 적어 뒀다(«오버레이·POI effect 전량 파괴·재생성 — 깜빡임의 근원»).
  **그 자리는 참조 동일 조기반환까지 넣어 방어하던 곳인데, 내 봉합이 그 방어를 깼다.**
  → 저장분이 없으면 **현재 참조를 그대로** 돌려주도록 고치고, **두 모집단으로 잠갔다**
    (없으면 `toBe`, 있으면 `not.toBe`).
  ★**미측정으로 남는 것**: 저장분이 **있는** 사용자의 한 번 재생성이 브라우저에서 체감되는지.
- ★**빈 컨트롤이 이제 영속된다**(2차 리뷰 지적 · 계획서에 없던 절충). 사용자가 한 레이어의
  컨트롤을 전부 끄면 그 상태가 **새로고침해도 유지된다**(종전에는 리로드로 초기화됐다).
  툴바로 되돌릴 수 있어 막다른 상태는 아니지만 **동작 변화이므로 적어 둔다.**
- ★**「기본으로 되돌리기」가 없으면 갇힌다**(유료·비가역 규율 §5 의 형제). 저장된 상태가
  나쁘면 사용자가 초기화할 길이 필요하다 → `resetControls` 를 **UI 에 노출할지**는 이 PR 범위 밖으로
  두되, **스토어에는 둔다**(없으면 나중에 추가가 배선까지 필요해진다).
