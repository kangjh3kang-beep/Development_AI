## 2. 변경 내용

### 2-1. `apiClient` 에 **blob 경로**를 신설한다 (원인 제거)

    ApiRequestOptions 에 `responseType?: "json" | "blob"`
    request() 429행의 단일 파싱 지점에서 분기
    apiClient.download(path, opts) 편의 메서드

★**같은 `request()` 를 타므로 401→refresh→재시도가 자동으로 붙는다.** 이것이 이 변경의 전부다 —
새 재시도 로직을 만들지 않는다(그러면 그 새 구조가 다음 결함의 서식지가 된다).

★**오류일 때는 blob 으로 읽지 않는다.** 서버는 오류를 **JSON** 으로 준다 —
blob 으로 읽으면 `ApiClientError.payload` 가 쓸모없어지고 **사유가 사라진다.**

### 2-2. 신고된 증상 파일을 이관한다

`RegistryRightsReportButton.tsx` → `apiClient.download`.

### 2-3. ★재발 잠금 — **래칫**

`apps/web/**` 에서 «`propai_access_token` 직접 읽기 ∧ 생 `fetch` ∧ `Authorization: Bearer`» 를
하는 파일을 **파생**시켜, **알려진 목록보다 늘어나면 실패**한다.
★한 번에 29개를 이관하지 않는다 — **목록은 줄어들기만 하는 래칫**으로 두고 단계적으로 뺀다.
(대규모 일괄 이관은 이 저장소가 반복해 데인 «새 구조가 새 서식지» 를 부른다.)

## 3. ★검증하지 못한 것

- **P7**: `Signature has expired` 문자열을 **직접 재현하지 못했다**(서명 비밀 부재).
  기전(`jwt_handler.py:118` 이 jose 예외 메시지를 그대로 싣는다)은 확인했고,
  그 문자열은 python-jose 의 표준 만료 메시지다 — **승계한 사실**로 표기한다.
- **115필지 분석이 실제로 60분을 넘는가** — **미측정.** 사용자 화면이 113/115 였다는 것만 안다.
  넘지 않았다면 다른 경로(리프레시 토큰 7일 만료 등)일 수 있다.
- **29개 중 몇 개가 진짜 우회인가** — 스윕은 «세 조건 동시 충족» 으로 뽑았을 뿐,
  **인증이 불필요한 호출**이나 **이미 재시도를 자체 구현한 것**이 섞여 있을 수 있다(트리아지 필요).
- **`/api/proxy` 경로의 동작** — `baseUrl` 이 비면 `/api/proxy` 로 떨어지는데 그 경로의
  인증 처리는 안 봤다.

## 5. 잠금

- **두 모집단**: blob 요청이 401 에서 **재시도되는가** ↔ JSON 요청이 **종전과 같은가**
- **오류 경로**: 실패 시 `payload` 가 **JSON 으로 파싱되어 사유가 남는가**
- **래칫**: 우회 파일 수가 **늘어나면 실패** · 신고된 파일은 **목록에서 빠져 있어야** 한다
- 변이로 각 축 CAUGHT 확인 후 **적대 리뷰**
