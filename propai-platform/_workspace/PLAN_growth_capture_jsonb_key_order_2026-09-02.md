| # | 전제 | 확인 방법 | **결과(실측)** |

## 2. 변경 내용과 **회귀가 아닌 근거**

판별 3종을 **짧은 이름**으로 싣는다(`depth`·`lost`·`build`). 원본 전체는 **그대로 유지**하고
같은 사실이 두 이름으로 갈리지 않게 중복만 뺀다.

- **회귀 아님**: 종전에도 `queue_depth` 는 **화면에 안 보였다**(P5). 값은 API 응답에 그대로 있다.
- **소비처 0**(P7)이라 이름 변경이 아무것도 깨지 않는다.

## 3. ★검증하지 못한 것

- **`jsonb` 정렬 규칙을 Postgres 문서로 확인하지 않았다.** 근거는 **라이브 관측과 모델의 일치**뿐이다
  (앞 6키). 규칙이 다른 판본에서 다르면 이 처방의 전제가 흔들린다 →
  그래서 **모델 자체를 라이브 관측과 대조하는 락**을 따로 뒀다.
- **배포 후 화면을 눈으로 보지 않았다** — 렌더는 소스 규칙에서 파생해 흉내 냈다.
- 프론트의 4키 상한이 바뀌면? → 락이 **TSX 에서 파생**하므로 따라간다(손으로 안 적었다).

## 4. 되돌리기 경로

이름 셋을 원래대로 돌리면 끝난다(읽기 경로·저장 경로 무변경). 그러면 **결함이 그대로 돌아온다** —
그 사실을 락이 잡는다(변이로 확인: CAUGHT).

## 5. 잠금

| 축 | 락 |
|---|---|
| **저장 후 순서** | 렌더 흉내가 `_as_stored`(jsonb 정렬)를 **거친 뒤** 그린다 |
| ★**모델 자신** | 그 정렬 모델을 **라이브 관측 앞 6키**와 대조한다(모델도 검증 대상) |
| 판별 필드 도달 | ①과 ②가 **화면 문자열로 달라야** 한다 |
