## 3. ★검증하지 못한 것

- **jsdom 의 `sendBeacon` 은 실제 브라우저가 아니다.** 이 락이 잠그는 것은 *"우리 코드가 그 분기를
  타고 올바른 본문을 만든다"* 이지 *"브라우저가 실제로 보낸다"* 가 아니다. 후자는 `#919` 에서
  독립 렌즈가 **서버측 DB 도달 10/10** 으로 따로 쟀다 — **두 층은 다른 명제다.**
- **64KiB 예산 초과 자체는 재현하지 않았다.** B 케이스는 `sendBeacon` 이 `false` 를 줄 때의
  **폴백 동작**만 잠근다. 실제 예산 절벽에서 `fetch keepalive` 도 실패해 **DB 0행**이 되는 것은
  `#919` 계획서가 적은 별건 부채이고 **여전히 미해결**이다.
- **`flush()` 가 보내기 전에 링을 비워 재시도가 없다**는 성질은 이 PR 이 **안 잠갔다**(런타임을
  안 건드리기로 했으므로). 별건.
- 라이브 확증 불필요(테스트 전용).

## 3-c. 추가로 검증하지 못한 것 (H3 — **잠갔다고 선언한 축 안**)

- **`navigator` 스텁의 실제 형상**: `{...globalThis.navigator}` 는 jsdom 에서 **빈 객체**를 만든다
  (Navigator 속성이 프로토타입 접근자다). 스텁 navigator 에는 `sendBeacon` **하나뿐**이며,
  오늘 무해한 이유는 `flush()` 가 다른 속성을 안 쓰기 때문이다 — **그 사실에 의존하고 있다.**
- **Blob 크기·64KiB 경계는 안 잰다.** B 케이스는 `sendBeacon` 이 `false` 를 줄 때의 **폴백 동작**만
  잠근다. 실제 절벽에서 `fetch keepalive` 도 실패해 **DB 0행**이 되는 것은 여전히 미해결(별건).
- **`sendBeacon` 호출 인자의 타입**은 Blob 여부만 본다(크기·인코딩 미검).
- **jsdom 의 `sendBeacon` 은 실제 브라우저가 아니다** — 이 락은 *"우리 코드가 올바른 본문을
  만든다"* 를 잠그지 *"브라우저가 실제로 보낸다"* 를 잠그지 않는다(후자는 `#919` 에서 독립 렌즈가
  **서버측 DB 도달 10/10** 으로 따로 쟀다. **두 층은 다른 명제다**).
- **셔플 순서 의존 hang**: `--sequence.shuffle` 로 디렉토리 전체가 timeout 된다. ★대조군으로
  **신규 파일을 뺀 `early-error-capture` 단독도 timeout** — **기존 부채**이고 이 PR 무관(별건 보고).
