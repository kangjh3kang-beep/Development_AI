## §1-B ★2차 실측 — 내 처방 A·C 는 **이미 구현돼 있었다**

계획서 초판의 처방 A(용도지역 층)·C(거래별 시점수정)를 짓기 전에 코드를 읽으니 **둘 다 있었다.**

| 처방 | 실제 상태 |
|---|---|
| A 용도지역 층 | **이미 있다** — `LAYERS` 에 `dong_zone_jimok`·`dong_zone`·`sigungu_zone`. 심지어 **지목을 앞에 둔 근거가 실측으로**(강남 동+지목 66% vs 동+용도 15%) 적혀 있고 **왜곡 사례**(논현동 1-1 공시지가 0.54배)까지 기록돼 있다 |
| C 거래별 시점수정 | **이미 있다** — `_time_factor(ym, now_ym, series)` 로 거래별 환산 |

★그런데 **둘 다 이 필지에서 발화하지 않는다**:

    sigungu_zone 표본  6개월  0건  · 12개월 3건  → MIN_SAMPLE=5 미달
    rate_series 를 넘기는 소비처  **0건**(정의 파일 밖 git grep 0) → 시점수정 항상 꺼짐

### ★★시점수정은 **결함이 아니라 의도된 결정**이었다

`nearby_map_service:611` 이 명문으로 적어 뒀다:

> *"시점수정은 **하지 않는다** — **하는 척하지 않기 위해** `now_ym` 도 넘기지 않는다.
>  … `now_ym` 만 넘기면 «시점수정 인자를 넘겼다»는 **외형만 남는다**.
>  ★창이 6개월이라 보정 없이도 왜곡이 작다(**30개월 창을 쓸 때 다시 판단할 것**)."*

**그 근거를 반증하려 재보니 작성자가 옳았다:**

| 창 | 시점수정 효과(경기 연 2.2%) |
|---|---|
| 6개월 | **+0.55%** |
| 12개월 | +1.09% |
| 30개월 | +2.76% |

**대비**: 용도지역 불일치로 인한 실측 괴리 **−24%** · 표본 구성 월별 진폭 **2.25배**.
→ 6개월 창에서 시점수정은 **두 자릿수 작은 문제**다. **우선순위가 아니다.**

### ★★★ 그러나 두 축은 **결합**돼 있다

용도지역 층이 서지 못하는 **이유가 창이 좁아서**다(6개월 0건 · 12개월 3건).
**창을 넓히면 용도지역 층이 서고, 그때 시점수정이 필요해진다** — 작성자 주석이
*"30개월 창을 쓸 때 다시 판단할 것"* 이라고 **예고한 그대로**다.

→ **창 확대와 시점수정 활성화는 한 쌍으로 간다.** 하나만 하면 다른 쪽이 결함이 된다.

## §2 근본원인 — 넷

1. **묶는 축이 「지목」이다.** 개발 사업지의 가치는 **용도지역**이 지배하는데 지목으로 묶어
   개발제한구역 40%가 섞였다. `landUse` 는 **마스킹되지 않는데 안 쓴다.**
2. **거래사례비교법을 통째로 포기한다.** 사유는 「개별 필지 위치 확인 불가」인데, 필요한 것은
   개별 매칭이 아니라 **같은 조건 통계**다. 모듈은 그 통계를 **내면서도 방법으로 승격 안 한다**
   → `methods` 1개 → 교차검증 불가 → 신뢰도 보류.
3. **시점수정이 방법1에만 있다**(비대칭). 거래는 최대 12개월 흩어져 있다.
4. **「그밖의요인 1.2」의 근거가 없다.** 손 목록이고 rationale 은 현실화율을 **단정**한다.

### ★안 하기로 한 것

- **「수도권 3배」 일괄 적용 기각.** 실측 배수는 이 필지에서 **1.45배**다. 3배면 8,367,000원/㎡
  인데 화도읍 일반상업 실거래에 그 대역이 없다. ★다만 **n=3** 이라 1.45도 강하게 주장하지

## §4 ★검증하지 못한 것

- **일반상업지역 표본 n=3.** 12개월 전체에서 이만큼이다. 승격된 방법2는 **표본수를 반드시
  표면에 싣고**, 하한 미달이면 «참고» 로만 표시한다.
- **R-ONE 실데이터로는 검증 못 함**(`reb_ready()=False`). 근사테이블 경로만 태웠다.
- 화면 렌더 미측정.
- 지목·형상·접도 개별요인의 타당성은 **재지 않았다**(형상 0.9 가 적용 중이다).

## §7 실행 결과 (2026-09-07 마감)

### ★계획의 처방 A·C 는 **둘 다 기각**됐다 — 실측이 다른 곳을 가리켰다

| 계획 처방 | 판정 | 근거 |
|---|---|---|
| A 용도지역 층 추가 | **이미 있었다** | `LAYERS` 에 `dong_zone`·`sigungu_zone` 실재 |
| 창 24개월 확대 | ★**만들고 → 라이브로 재고 → 기각·삭제** | 6개월 층=sigungu_jimok 786,502 / 24개월 **같은 층** 631,272(**−20%**). 창이 아니었다. 사용자 판단도 같다(*"6개월 이내여야 실효성"*) |
| C 거래별 시점수정 | **이미 있었다 + 우선순위 아님** | 창 6개월 효과 **+0.55%** ↔ 진짜 괴리 −24%. `nearby_map_service` 의 *"하는 척하지 않는다"* 판단이 옳았다(반증 실패) |

### ★★진짜 원인은 **한 줄짜리 비교**였다

    MOLIT umdNm  "화도읍 마석우리"  ↔  타깃 "마석우리"  ·  `_matches` 는 `==`
    → 정확일치 **0건** · 동 계열 **네 층 전부 실패** → 시군구 층 폴백

실해 범위: 남양주 3개월 표본에서 `umdNm` 의 **81.5%가 읍·면 접두**. 시(동) 지역은 멀쩡했고
**읍·면만 조용히 깨져 있었다.**

### 라이브 효과

    봉합 전  sigungu_jimok  n=102    732,245원/㎡  (개발제한구역 40.2% 혼입)
    봉합 후  dong_jimok     n=  6  3,855,297원/㎡  (1종주거 83.3%)   **5.3배**

별도로 잰 화도읍 실거래(같은 용도지역 12개월 중앙 4,038,261)와 **−4.5%** 근접.

### 미완 (별도 PR)

- **B 방법2 승격** — 재료는 갖춰졌다(두 값이 3,057,000 ↔ 3,855,297, 26% 차이).
  신뢰도 산출 로직을 건드려 범위가 다르다.
- **E 「그밖의요인 1.2」** — 근거 없는 단정(*"현실화율 약 83%"*) 미수정. 실측 배수 1.45배이나
  **n=3** 이라 값을 바꾸지 않았다.
- **F R-ONE 미구성 표면화** — `reb_ready()=False` 가 근거 문자열에만 있고 화면에 없다.
- 화면 렌더 미측정.

### 남긴 것

`land_price_index.monthly_rate_series_async`(R-ONE → 근사 폴백, **출처 라벨 동반**)를
넣어 두었다. ★**소비처는 아직 없다**(창 6개월에서 불필요) — 그 사실을 독스트링에 적었다.
시점수정 구현 자체는 **락으로 고정**했다: 나중에 창을 넓힐 때 «있는 줄 알았는데 꺼져
있었다»가 반복되지 않게.
