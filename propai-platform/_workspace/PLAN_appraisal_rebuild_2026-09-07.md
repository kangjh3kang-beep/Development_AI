작성 2026-09-07 · sid=d67f8fff

사용자 요구: *"AI 예상시세 추정보고서는 감정평가 대체로 합법적인 감정평가보고서를 제공하기

## §1-0 ★내 앞선 진술을 정정한다 — R-ONE 은 **살아 있다**

세션 중 여러 번 *"R-ONE 미구성(`reb_ready()=False`)"* 이라 적었는데 **틀렸다.**

    docker exec <컨테이너> python -c "reb_ready()"   → False   ← ★새 프로세스
    라이브 API 응답 market_stats.rone_available      → **True**  ← 실행 중 서버

시크릿이 **DB(platform_settings)에서 기동 시 주입**되므로, `docker exec` 로 띄운 **새
프로세스는 그것을 못 본다.** ***"내가 잰 것이 사용자가 실제로 쓰는 그것인가"*** 를 어겼다.
볼트·보드에도 그대로 적었으므로 함께 정정한다.

## §2 근본원인 — 여섯

### R1 ★시점수정 값이 **거짓**이다 (가장 급함 — 돈이 걸린다)

`rate_series_from_rows(rows, "경기")` 의 **지역 필터가 작동하지 않아** 같은 달(202607)의
여러 지역 값이 시계열로 들어왔다. 그 24개를 `∏(1+r/100)` 로 곱해 **1.0414** 를 만들고,
그것이 **채택 단가에 그대로 곱해진다** → 토지가액이 근거 없이 **+4.14%** 부풀어 있다.
연도별 합계는 같은 오염이 증폭돼 **+80%** 라는 물리적으로 불가능한 값을 낸다.

### R2 화면이 **출처를 거짓으로** 말한다

프론트가 `— R-ONE 실데이터` 를 **조건 없이** 쓴다. 백엔드는 `source` 를 구분해 주는데
소비처가 안 읽는다. 근사값이어도 «실데이터»로 보인다.
★이 저장소가 반복해 데인 **「모름을 유효값으로 표현」** 의 라벨 판이다.

### R3 「교차검증」이 **교차검증이 아니다**

자기 가정(그밖의요인)을 ±5% 흔든 민감도를 **제목이 「복수 시나리오 교차검증」** 이라 부른다.
본문은 정직하게 *"교차검증이 아닙니다"* 라고 적어 **제목과 본문이 정면 모순**이다.
읽는 사람은 **제목을 믿는다.**

### R4 감정평가 규칙의 **필수 절차가 빠졌다**

| 「감정평가에 관한 규칙」 | 현재 | 판정 |
|---|---|---|
| §14 **비교표준지 선정**과 이유 | 없음 — 개별공시지가 직접 사용 | ✘ |
| §14 시점수정 | 있으나 **값이 거짓**(R1) | ✘ |
| §14 **지역요인** 비교 | 없음 | ✘ |
| §14 개별요인 비교 | 접도·면적·형상 | △ |
| §14 **그 밖의 요인 보정** 근거 | *"현실화율 약 83%"* **단정** — 평가선례·거래사례 격차율 없음 | ✘ |
| §12 주된 방법 + **다른 방법 검토** | 거래사례비교 미적용(사유는 밝힘) | △ |
| **가액 결정 및 그 이유**(시산가액 조정) | 「채택」이라고만 | ✘ |

### R5 재료를 만들어 놓고 **안 쓴다**

`land_market_stats` 가 **3,855,297원/㎡**(읍·면 봉합 후)를 내는데 `methods` 에 안 들어간다.
→ 방법 1개 → 교차검증 불가 → 신뢰도 **보류**. 채택가는 시장통계 대비 **−21%**.

### R6 물건표시 **정합 검증이 없다**

지목 **답** · 이용상황 **업무용** · 용도지역 **일반상업**. 셋이 동시에 참일 수 있으나
(지목은 미변경, 현황은 업무용) **모순일 수도 있고**, 지금은 **아무도 확인하지 않는다.**
감정평가는 «현황 기준»이 원칙이라 이 셋의 관계가 **평가 전제**다.

## §3 재구성 — 감정평가 **스토리라인 = 파이프라인**

「감정평가에 관한 규칙」의 절차를 그대로 파이프라인 단계로 삼는다. **각 단계가 산출물과
「못 한 이유」를 함께 낸다**(현재 강점인 정직 고지를 유지·확장).

    ① 대상 확정      Subject      주소→PNU→토지특성. **정합 검증**(지목↔이용상황↔용도지역)
    ② 자료 수집      Evidence     공시지가 · 실거래 · 지가변동률 · 임대. **각 항목 신선도·출처**
    ③ 방법 적용      Methods      공시지가기준 / 거래사례비교 / 원가 / 수익환원 — **각각 독립 산출**
    ④ 시산가액 조정   Reconcile    방법 간 불일치 → 가중·채택 **이유**
    ⑤ 가액 결정      Conclusion   채택가 + 범위 + **신뢰도(교차검증으로 산출)**
    ⑥ 보고          Report       ①~⑤ 를 순서대로. **미확보는 미확보라고**

★현재 응답은 ③④⑤가 뭉쳐 있고 ①의 정합·④의 이유가 없다.

### 단계별 계약(신규 키 — 기존 키는 **불변**)

    subject.consistency   = {ok, conflicts:[{field_a, field_b, note}], basis}
    evidence[]            = {kind, value, source, as_of, freshness_days, ok, why_not}
    methods[]             = {method, unit_price, applicable, why_not, factors, rationale, weight}
    reconciliation        = {spread_pct, adopted, weights:[], reason}
    conclusion            = {unit_price, range, confidence, confidence_basis}

★`methods[].applicable/why_not` 이 핵심이다 — **적용 못 한 방법도 목록에 남긴다.**
지금은 아예 빠져서 «4방법»이라 해 놓고 1개만 보인다.

## §5 가독성·직관력 재구성

현재 보고서는 **결론 뒤에 근거가 평평하게 나열**되고, AI 해석이 *"데이터 없음"* 을 길게
반복해 **무엇이 문제인지 안 보인다**.

| 원칙 | 적용 |
|---|---|
| **결론 먼저, 신뢰도 옆에** | 채택가 · 범위 · 신뢰도 배지를 한 블록에. 신뢰도가 «보류»면 **왜**를 한 줄로 |
| **단계 진행 표시** | ①~⑥ 스토리라인을 **진행바**로. 각 단계 ◎완료 / △부분 / ✘미확보 |
| **못 한 것을 접지 않는다** | 미확보 항목을 **별도 카드**로 모아 «이것만 채우면 신뢰도가 오른다»를 명시 |
| **방법 비교는 표 하나** | 4방법 × (단가 · 적용여부 · 사유 · 가중) 한 표. 지금은 1행뿐이라 표로 안 보인다 |
| **숫자에 축을 붙인다** | 「원/㎡」와 「만원/평」 병기(이 세션의 면적표기 SSOT 재사용) |
| **AI 해석은 요약 3줄 + 접기** | 지금은 «데이터 없음» 문단이 화면 절반. **핵심만 위로** |
| **거짓 라벨 제거** | 「R-ONE 실데이터」·「교차검증」을 **조건부**로 |

## §6 ★검증하지 못한 것

- **비교표준지 데이터원**: 저장소에 없음(§0). 확보 가능성 **미조사**.
- **평가선례**: 공개 데이터원 존재 여부 **미조사**.
- 물건표시 정합 규칙(지목↔이용상황 조합)의 **법적 근거** 미확인 — 실무 관행으로만 안다.
- W8 격차율의 **표본 하한** 미정(현재 일반상업 n=3, 동·지목 n=6).
- 화면 렌더 미측정(이 계획의 변경 후).

## §8 되돌리기

W1~W4·W7 은 **국소**(필터·라벨·제목·검증 추가)라 커밋 단위 revert 로 복구.
W5·W6·W8 은 응답에 **키를 추가**할 뿐 기존 키를 안 바꾼다 — 소비처가 안 읽으면 무변화.
`MARKET_MULTIPLIER_MAP`·`unit_standards` 등 전역 상수는 **건드리지 않는다**.
