# 검증 상한과 3층 설계 — "100% 는 가능한가"에 대한 답 (2026-08-24)

> 방법: `/insight-loop` — 오늘 확증 결함 9건 분류 · 재발 과정 시뮬레이션(모델) ·
> 변형관계 라이브 실증 · 업계 표준 대조.

## 0. 답 — **아니다. 그러나 지금 위치는 달성 가능한 상한보다 한참 아래다.**

"100%"를 셋으로 갈라야 정직해진다.

| 층위 | 100% 가능? | 이유 |
|---|---|---|
| **정확성**(현실과 일치) | **원리적 불가** | 오라클이 **현실**이다 — 실제 인허가 결과·실제 분양가는 나중에야 안다 |
| **잠금 커버리지** | **실질 불가** | 조회습관·판단 같은 클래스는 CI 로 못 잠근다(훅이 일부만) |
| **일관성·출처·정직** | **≈가능** | 정답을 몰라도 판정된다 ← **오늘 결함 9/9 가 전부 여기 속했다** |

★**핵심 사실**: 오늘 확증한 9건 중 *"정답을 알아야만 잡히는 것"* 은 **0건**이었다.
전부 내부 모순·출처 누락·정직 규칙 위반이다. 즉 **우리를 막고 있는 것은 원리적 한계가 아니다.**

## 1. 왜 100% 가 불가능한가 — 세 가지 서로 다른 벽

1. **오라클 문제** — "이 부지의 적정 사업모델"의 정답은 시스템 밖(현실·행정청)에 있다.
   테스트로 판정 불가. 표준 대응은 **변형관계 검사**(§3-L3).
2. **잠글 수 없는 클래스** — "0건은 부재가 아니다" 같은 **조회 습관**은 CI 대상이 아니다.
   훅이 일부 잡지만 100% 는 아니다.
3. **상류 데이터 상한** — 조례 미확보(플랫폼 스스로 *"71개 필지는 조례 실효 용적률 미확보로
   법정상한 폴백"* 이라 고지), 공시지가 시차, 지적도 형상 부재.
   ★이건 **결함이 아니라 사실**이다. 처방은 제거가 아니라 **정직한 전파**다.

## 2. 시뮬레이션 — 어디에 레버가 있나

★**모델이지 측정이 아니다.** 실측은 전환율(11%)뿐이고 나머지는 가정이다.
값의 정밀도가 아니라 **모양**을 본다.

| 레버 | 세션당 재발 | 현재 대비 |
|---|---|---|
| 현재 | 4.96 | 100% |
| ① 신규 교훈 전환율 11%→100% | 4.03 | **81%** |
| ③ **기존 산문 백로그 100% 락화** | 2.61 | **53%** |
| ⑤ ①+③ | 1.71 | 34% |
| ⑥ ⑤ + 락 부패 제거(비현실 가정) | 0.63 | 13% |
| ⑦ ⑥ + 훅(잠글수없는것 60% 차단) | **0.25** | **5%** |

★★**내 처방이 시뮬레이션으로 반증됐다.** 처음에 *"신규 교훈의 전환율을 올려라"* 라고 했는데,
그것만으로는 **19% 밖에** 못 줄인다. **지배항은 기존 산문 백로그**다.
민감도도 같은 방향: 산문 재발률 ±50% → 결과 **±47%**, 락 부패율 ±50% → **±1%**.

→ **우선순위 교정**: 신규 전환율보다 **기존 137건의 락화**가 먼저다.

## 3. 설계 — 3층 (각 층이 서로 다른 결함을 잡는다)

### L1. 전제 감사 (입력 교차 불변식) — *구현 시작(#813)*

계산 **전에** 입력의 교차 정합을 본다. 오늘 D1·D2·D3·D8 이 여기서 잡힌다.
★**값을 몰래 고치지 않는다** — 고지하고 등급을 강등한다. 자동 교정은 어느 쪽이 옳은지
단정하는 것이고, 그 단정이 틀리면 **더 조용한 결함**이 된다.

### L2. 계약·파생 락 (CI) — *부분 존재(11%)*

두 곳에 사는 표·화이트리스트·라벨을 **SSOT 에서 파생**시켜 대조. D7 이 여기서 잡힌다.
(#796 법정한도표 · #797 이벤트 화이트리스트 · #808 인사이트 카탈로그가 이 형태.)

### L3. **변형관계 검사(Metamorphic)** — *신설 제안 · 오늘 라이브 실증*

정답을 몰라도 **입력↔출력의 관계**로 판정한다. 오라클 문제의 표준 해법이며
컴파일러·DB·자율주행·분류기에서 확립된 기법이다.

라이브 응답에 실제로 돌린 결과:

    MR-A 면적 보존       zone_mix합 11,533 == per_parcel합 11,533        ✔
    MR-B 우세 정합       dominant == argmax(zone_mix by area)            ✔
    MR-C 경로 무관성     site zone(제2종) vs top3 zone(자연녹지)          ✘ **위반**
    MR-D 필지수 보존     투입 8 vs top3.parcel_count 1                   ✘ **위반**
    MR-E 통합 단조성     통합 >= 최대 단일필지                            ✔
    MR-F 한도 자기정합   top3 far 100 은 **자기 zone 과는 정합**          (그래서 MR-C 가 필요)

★**MR-C·MR-D 가 오늘의 P0 를 정답 없이 잡았다.** 그리고 A·B·E 는 통과 —
**무차별 경보가 아니다**(특이도 실증). MR-F 가 함정을 보여준다: 단일 경로 자기검사로는
**절대 안 잡힌다** — 각각은 정상이고 **조합**이 틀리기 때문이다.

#### 도입할 MR 후보(도메인)

| MR | 관계 | 잡는 결함 |
|---|---|---|
| 경로 무관성 | 같은 부지를 두 경로로 → 같은 한도 | D1 |
| 보존 | 면적·필지수·표본수가 단계마다 보존 | D1·D9 |
| 단조성 | 용도지역 상향 → 실효 용적률 **감소 안 함** | D4 |
| 단조성 | 표본 추가 → 신뢰도 **감소 안 함** | D5 |
| 커버리지 | 지표 추가 → 등급 신뢰구간 **좁아짐** | D6 |
| 멱등성 | 같은 입력 2회 → 같은 출력(난수 금지) | D5(난수 신뢰도) |

★마지막 것이 특히 강력하다 — **멱등성 검사 하나가 "난수로 만든 신뢰도"를 구조적으로 금지**한다.

## 4. 업계 대조

표준 스택은 **데이터 계약(contract) + 단언형 품질검사 + 계보(lineage/provenance)를
파이프라인에 상시 내장**하는 것이다. 요지는 *"조용한 실패를 실행 가능한 신호로 바꾼다"* 이고
*"상류에서 계약으로 막아 하류 모델에 애초에 안 들어가게 한다"* 이다.

우리와의 격차: **계약·단언은 부분 존재**(L2), **계보가 가장 약하다** —
D2·D3(저장본과 라이브가 한 화면에 섞이는데 어느 쪽이 권위인지 안 밝힘)가 정확히 그 증상이다.
→ **모든 표시값에 `source` + `fetchedAt` 필수화**가 단일 최대 레버다.

## 5. 실행 순서 (시뮬레이션이 정한 우선순위)

1. **기존 산문 백로그 락화**(지배항 · 53%) — 원장 ③ 137건을 클래스로 묶어 일괄 락 설계
2. **표시값 provenance 필수화**(계보 격차 · D2·D3 동시 해소)
3. **L3 변형관계 6종**(오라클 없는 정확성 · D1·D4·D5·D6·D9)
4. 신규 전환율(부차 · 19%) — 훅으로 가시화는 이미 배치
5. 락 신선도 관리(부패 ε) — 락 자체가 대상을 태우는지 주기 점검

## 6. ★정직한 한계

- §2 는 **모델**이다. `P_PROSE`·`EPS_LOCK`·`NEW_PER_S`·`HOOK_CATCH` 는 **가정**이고
  단일 세션 관측에서 왔다. 결론은 **순위**(백로그 > 전환율)까지만 신뢰하고 **절대값은 신뢰하지 말 것**.
  ★첫 판 모델은 `UNLOCKABLE` 을 출력만 하고 계산에 안 넣어 **"0 도달 가능"이라는 거짓 결론**을
  냈다 — 교정 후 바닥이 0.25 로 드러났다.
- §3-L3 의 MR 은 **6종을 설계했고 2종만 라이브로 돌렸다**(MR-C·MR-D). 나머지는 미실증.
- §4 는 웹 조사 요약이다 — 우리 도메인(부동산 인허가)에 그대로 적용된다는 **검증은 안 했다**.
