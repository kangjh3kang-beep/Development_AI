## 2. 변경 내용

### 2-a. `lib/pnu.ts` — 유효성 SSOT 를 정체성 SSOT 에 배선

1. `parcelDedupKey` → `normalizePnu` 경유. 가짜면 **주소로 떨어진다**(원래 폴백 경로).
2. **신설** `projectParcelIdentityKey(p, index)` — 패널의 인라인 규칙을 함수로 꺼낸다.
   *"유효 PNU 가 있으면 그것, 없으면 인덱스를 섞어 접히지 않게"*. P6 의 두 벌 구현을 없앤다.

### 2-b. 같은 클래스 전역 스윕(P7)

| # | 자리 | 가짜 PNU 가 하는 일 | 수정 |
|---|---|---|---|
| 1 | `lib/pnu.ts` `parcelDedupKey` | 가짜가 그대로 정체성 키 | `normalizePnu` 경유 |
| 2 | `ParcelSurveyQuotePanel.tsx:134` | truthy → 접힘 방지 탈출구 **우회** → 동 단위 주소 공유 시 **77→1 부활** | `projectParcelIdentityKey` |
| 3 | `lib/satong-mass-seed.ts:151` | 한쪽만 가짜면 `≠` 로 갈라져 **정당한 주소 매칭이 차단**된다(주소 분기에 도달조차 못 함) | 양쪽 `normalizePnu` |
| 4 | `lib/parcel-rows.ts:120` | 가짜를 **백엔드로 전송**(볼트 실측 ③ 그대로) ★**#933 에서 내가 쓴 코드** | `normalizePnu` 후 전송 |
| 5 | `components/operations/LandShareModal.tsx:78` | `pnu.length >= 19` 만 봐서 **26자 가짜를 진짜로 전송** | `normalizePnu` |
| 6 | `lib/orchestration/node-body-builders.ts:237` · `components/orchestration/PersonaPanel.tsx:496` | `pnu.length >= 10 ? pnu.slice(0,10)` → **`"store-rep-"` 를 법정동코드로 날조**. 백엔드는 `bcode[:5]`=`"store"` 를 `lawd_cd` 로 쓴다 | `normalizePnu` 후 slice |

★#6 은 **주석이 "pnu(19자리) 앞 10자리" 라고 적는데 가드는 `>= 10`** 이다 — 선언과 구현의 어긋남.

### 회귀가 아닌 근거

- `normalizePnu` 는 **19자리 숫자만** 통과시키고 나머지를 `null` 로 만든다. 진짜 PNU 의
  거동은 **바이트 단위로 동일**하다(§3 의 대조 모집단 A 가 이것을 잰다).
- 가짜였던 값은 전부 **기존 폴백 경로**(주소·인덱스·`bcode=null`)로 떨어진다 —
  새 경로를 만들지 않았다. 폴백은 이미 테스트가 있는 길이다.
- **값을 지어내지 않는다**: 가짜를 지울 뿐 없는 PNU 를 합성하지 않는다(무날조).

## 3. 잠금 — 세 모집단을 **서로 다른 결과**로 가른다

| 모집단 | 입력 | 기대 |
|---|---|---|
| **A 진짜 PNU** | 같은 주소 · 서로 다른 19자리 PNU 2건 | 키 **2개**(갈린다) — 이게 무너지면 77→1 재발 |
| **B 가짜 PNU** | 주소 파생 가짜(`store-rep-<동주소>`) 3건 + 동 단위 주소 동일 | `projectParcelIdentityKey` 로 **3개**(안 접힌다) / `parcelDedupKey` 로는 **1개**(주소 폴백이 맞다) |
| **C 앵커 없음** | PNU 없음 · 동 단위 주소 | 기존 계약 유지 |

★A 와 B 가 **같은 결과를 내면 배선을 끊어도 통과한다** — 그래서 다름을 못 박는다.
★락은 **소스 문자열이 아니라 동작**을 태운다(§0 에서 문자열 grep 은 기각됐다).
★패널 규칙은 이제 **실제 함수**를 태운다(P6 의 재구현 제거).

## 4. ★검증하지 못한 것

- **P8 — 오늘 라이브에서 실제 붕괴는 0건이다.** 이 PR 은 **잠재 결함**을 닫는 것이고,
  *"사용자가 지금 겪는 붕괴를 고쳤다"* 고 주장하지 **않는다.** 도달 조건은
  「가짜 PNU + 동 단위 주소 공유」이며 생산자(P2)가 주소 파생이라 **동시 발생이 구조적으로 보장**되지만,
  그 조합을 가진 프로젝트가 **오늘은 없다**.
- **개인 성명이 PNU·주소 칸에 들어간 상류(토지조서 파싱)** 는 **미측정**이다. 이 PR 은 하류만 막는다.
  `'◀ 전성결'` 의 `◀` 가 어느 파서의 잔재인지 특정하지 못했다.
- **이미 저장된 오염 데이터의 정리(마이그레이션)** 는 하지 않는다. 코드는 고쳐도
  **저장된 가짜 PNU 는 남는다** — 다만 이제 **읽는 쪽이 전부 무해화**한다.
- `LandShareModal`·`PersonaPanel`·`node-body-builders` 의 수정은 **라이브 프로브로 확인하지 않았다**
  (해당 화면을 태우려면 실제 프로젝트 조작이 필요). 단위 테스트로만 잠갔다.
- **`healParcelPnu`**(볼트 결과 ②)는 이 PR 범위 밖이다 — 같은 클래스일 수 있으나 **재보지 않았다.**
