## 2. 변경 내용과 **회귀가 아닌 근거**

### P1. 없는 sha 를 「수렴」이 아니라 「모름」으로 (전제 5)
`runtime_delta` 와 `CD` 계산 앞에 `git cat-file -e "<base>^{commit}"` 가드를 둔다 → `?` → 기존 `DEAD=1` 경로.
**회귀 아님**: 유효 sha 경로의 반환값이 그대로다(전제 5 대조군 2 유지). 새로 걸리는 것은 **원래 판정 불가였던 입력**뿐이다.

### P2. 「주석만」을 위반이 아니라 **관측 이상(exit 4)** 으로 강등 (전제 2·3·4)
⑤-2 에서 요청이 있고 델타가 남았을 때, 그 델타가 **전부 「주석만」이면 `OBS=1`**(exit 4), 아니면 종전대로 `VIOL=1`.
판정은 **AST**(파이썬)로 한다 — 주석·독스트링을 제거한 `ast.dump` 비교.
`.py` 가 아닌 변경이 하나라도 있거나 python3 부재·파싱 실패면 **「미분류」 → 종전대로 VIOL**(안전한 쪽).
**회귀 아님**: 코드가 바뀐 경우의 판정(VIOL)이 그대로다(전제 4). **초록으로 만들지 않는다** — 4는 「이상 없음」이 아니다.

### P3. `runtime_delta`·새 함수를 `--verdict-lib` 게이트 **위로** 이동 (전제 8)
그래야 락이 **사본이 아니라 실물**을 태운다(형제 락이 «사본을 태우지 않는다» 를 명문으로 금지).
**회귀 아님**: 정의 위치만 바뀌고 호출 순서·부작용이 없다(순수 함수).

## 3. ★검증하지 못한 것

- **`.py` 아닌 파일의 「주석만」 판정** — 하지 않는다(TS/JSX/CSS/bash). 그 경우는 **미분류 → VIOL 유지**로 남긴다.
  즉 이 처방은 **api 축의 파이썬에만** 효력이 있다. web 축의 같은 상황은 **여전히 위양성**이다(부채, `it.todo` 로 남긴다).
- **파일모드 변경·rename·binary·빈 파일 삭제**는 줄이 0이지만 배포가 필요할 수 있다. AST 축은 `.py` 내용만 보므로
  **그 4종을 「주석만」으로 오분류할 수 있다** → `--diff-filter`/`--numstat` 으로 걸러야 하는데 **이번 범위 밖**이다.
  ⇒ 완화: 「주석만」 판정은 **수정(M) 상태의 `.py`** 로 한정하고, 그 외 상태가 하나라도 있으면 미분류.
- **컨테이너 소스와 git 의 괴리** — 이 저장소는 컨테이너 소스를 표식으로 grep 한다(계기판 자신이 :174 에서 한다).
  「주석만이라 안 구움」이 지속되면 **컨테이너에 #1018 이 거짓이라 판정한 문장이 남는다.** 이 계획은 그것을 **해결하지 않는다** —
  exit 4 로 **보이게** 만들 뿐이다. 해소는 다음 api 배포가 한다.
- `exit 2` 가 ⑤-2 이외 경로(④ 옛 스택·④-2 디스크)에서도 났는지는 **이번 실행에서는 아니었다**(전제 2). 일반화하지 않는다.
