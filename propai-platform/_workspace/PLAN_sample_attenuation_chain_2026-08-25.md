## 0. 옵시디언 조회(계획 게이트 §0)

`감쇠|사전컷|표본 손실|nearby_map` 로 볼트 510개 md 조회(대조군 확인). 선행 기록 없음.

## 1. 관측 — 라이브 실측(2026-08-25 · `POST /api/v1/zoning/nearby-map` · 역삼동 736 · 1000m)

| 단계 | 그룹 수 |
|---|---|
| 원본(카테고리별 `groups_before` 합) | **2,350** |
| 지오코딩 사전컷 | −1,761 |
| 좌표 미확보 | −35 |
| 반경 밖 | −306 |
| 표시 상한 절단 | −39 |
| **지도 표시** | **209** |

**91% 가 깎인다.** 그런데 화면 라벨은 `radius_filtered_out_count` **한 갈래(306)만**
말하고 있었고, **가장 크게 깎인 사전컷 1,761곳은 화면 어디에도 없었다.**

★**"숫자가 없다"가 아니라 "합쳐서 말하는 자리가 없다"** 였다 — 사유는 응답에 다 있었지만
**여섯 군데**에 흩어져 있어(최상위 4키 + 카테고리별 `precut` + `display_cap_impact`)
사용자가 조립할 수 없다.

### 자기검산 — 두 갈래가 독립적으로 일치했다

    카테고리별 groups_cut  합 1,761  ==  최상위 geocode_precut_count 1,761
    카테고리별 groups_before 합 2,350  ==  precut 1,761 + evaluated 554 + unresolved 35

### ★단위 (여기서 틀리면 그럴듯하게 맞는 거짓말이 된다)

사슬에 쓴 네 카운터는 **전부 그룹 단위**임을 소스에서 확인했다
(`geocode_precut` 553·583 / `groups_evaluated` 756·783 / `coords_unresolved` 758·780 /
`filtered_out` 757·793). 같은 응답의 `geocode_failure_breakdown`·`geocode_attempted_count`
는 **질의 단위**라 **섞지 않았다** — 서비스 주석(≈1903행)이 바로 그 혼동을 경고한다.

## 2. 처방

- `sample_attenuation.py` **순수 함수** 신설 — 이미 조립된 응답에서 **읽어 엮기만** 한다
  (재계산 0). 판단을 순수 함수로 꺼내고 배선 락을 따로 둔다.
- 응답에 `sample_attenuation` 추가(additive — 기존 키 불변).
- 화면에 **한 줄** + 단계별 사유를 `title` 로.
- ★검산이 어긋나면 **조용히 맞추지 않고 신고**한다(`reconciles=false` + 화면 표기).
  맞춰 버리면 계기 고장을 "깨끗함"으로 읽는다.
- 원본 수는 **추정하지 않는다** — `groups_before` 합이 권위값이다. 없으면 `None`(무목업).

## 3. 락

- 백엔드 6건 — **실제 프로덕션 응답을 픽스처로**(합성 아님) 검산 일치 · 문구가 원본 수를
  말함 · 단계마다 사유 · **불일치 신고**(표시 수는 안 건드림) · 두 모집단 분리 · 근거 없으면 None
- 프론트 5건 — 렌더 경로 실측(1,761 이 화면에 있는지) · 사유 title · 불일치 표기 ·
  특이도 2건(**공허 방지 가드 포함**)

★프론트 첫 판은 **공허했다** — `payload` 가 컴포넌트 **내부 상태**인데 prop 으로 넘겨
무시됐고, 음성 2건이 "요소가 없다"는 이유로 트리비얼하게 통과했다. `apiClient.post` 스텁으로
실제 조회 경로를 태우고, 음성 케이스에 **조회 완료 확인**을 먼저 넣었다.

## 4. 검증 못한 것 (정직)

- 이 사슬은 **그룹 단위**다. 사용자가 세는 "거래 건수"(deal)와 다르며, 건수 축 사슬은 **미구현**.
- 라이브 검증은 **역삼동 736 한 지점**이다. 좌표 미확보가 지배적인 지역(지번 마스킹 다수)에서
  비율이 어떻게 달라지는지는 **미측정**.
- `display_cap` 은 `in_radius − shown` 으로 **역산**한 값이다(전용 카운터가 아니다).
  검산이 맞으므로 현재는 정합하나, 상류에 새 필터가 생기면 이 항으로 **흡수**된다 —
  그때 `reconciles` 는 여전히 참이라 **이 항의 증가로만 드러난다.**
