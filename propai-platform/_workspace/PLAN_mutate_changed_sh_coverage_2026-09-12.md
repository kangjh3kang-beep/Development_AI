## §3 ★검증하지 못한 것

1. **`.sh` 변이가 「설명 불가 생존」을 실제로 몇 건 드러내는가** — 미측정. 이 PR 은 **모집단을 넣는 것**까지이고,
   드러난 생존을 봉합하는 것은 **별건**이다(그 봉합을 이 PR 에 끌어들이면 범위가 두 개가 된다).
2. **루트 `scripts/` 5건**(`coord.sh` · `mutate_manual.sh` 등)은 **여전히 배제된 채로 둔다.** 그 게이트의 사유
   (*"도구 자신은 이 테스트들의 대상이 아니다(오탐)"*)가 지금도 참인지 **미측정** — 이유는 **장치 부재가 아니라
   「안 쟀음」**이다. 이 PR 의 범위를 넘으므로 부채로 **초록 안에 드러낸다**(`it.todo` 대응 = `xfail`).
3. **heredoc 내부 줄이 변이 대상으로 들어온다** — 초판은 *"미측정"* 이라 적었으나 **이제 쟀다**:
   실행 파일 기준 **87줄**(`a1-backend-workers.sh` 27 · `verify-toss-live.sh` 14 · …).
   `.py` 는 `_docstring_line_nos` 가 걸러 주지만 셸에는 대응물이 없다. 구문 게이트가 **일부**를
   잡지만 전부는 아니다(heredoc 안 텍스트 변경은 구문상 유효하다).
   ⇒ 다른 두 부채와 **대칭이 되게** `xfail(strict)` 로 초록 안에 드러냈다(종전엔 산문만이었다).
   ★단 **소음은 작다**: 전수 적용 시 판정 불가는 **122/2,441 = 5.0%** 다(내가 걱정한 「범람」은 반증됐다).

4. **`exit` 규칙이 아직 전수가 아니다.** 확장 후 실행 줄의 `exit N(N≠0)` **126 토큰 중 118줄**을
   본다(초판 55줄). 남은 것은 여러 토큰이 한 줄에 있거나 동적 생성인 경우다.
   ★**이 수를 적는 이유**: 이 표기가 없으면 *"셸도 이제 기계 감사된다"* 로 읽힌다.

5. **구문 게이트가 `.py` 판정을 어떻게 바꾸는지 전수로는 미측정.**
   이유는 **「안 쟀음」**(장치는 있다 — 돌리면 된다). 알고 있는 것: `.py` 줄삭제 변이의 약 **12%**가
   구문을 깬다(독립 리뷰 실측). 새 설계(C6)에서는 그중 **테스트까지 실패한 것만** 판정 불가가 되므로
   신호 손실은 그보다 작지만, **얼마나 작은지는 안 쟀다.**

6. **드러난 생존을 봉합하는 것은 별건**이다. 이 PR 은 모집단을 넣는 데까지다.
