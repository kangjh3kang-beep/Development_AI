## §3 ★검증하지 못한 것

1. **`.sh` 변이가 「설명 불가 생존」을 실제로 몇 건 드러내는가** — 미측정. 이 PR 은 **모집단을 넣는 것**까지이고,
   드러난 생존을 봉합하는 것은 **별건**이다(그 봉합을 이 PR 에 끌어들이면 범위가 두 개가 된다).
2. **루트 `scripts/` 5건**(`coord.sh` · `mutate_manual.sh` 등)은 **여전히 배제된 채로 둔다.** 그 게이트의 사유
   (*"도구 자신은 이 테스트들의 대상이 아니다(오탐)"*)가 지금도 참인지 **미측정** — 이유는 **장치 부재가 아니라
   「안 쟀음」**이다. 이 PR 의 범위를 넘으므로 부채로 **초록 안에 드러낸다**(`it.todo` 대응 = `xfail`).
3. **heredoc 내부 줄이 변이 대상으로 들어온다** — 초판은 *"미측정"* 이라 적었으나 **이제 쟀다**:
   실행 파일 기준 **87줄**(`a1-backend-workers.sh` 27 · `verify-toss-live.sh` 14 · …).
   `.py` 는 `_docstring_line_nos` 가 걸러 주지만 셸에는 대응물이 없다. 구문 게이트가 **일부**를
   잡지만 전부는 아니다(heredoc 안 텍스트 변경은 구문상 유효하다).
   ⇒ 다른 두 부채와 **대칭이 되게** `xfail(strict)` 로 초록 안에 드러냈다(종전엔 산문만이었다).
   ★단 **소음은 작다**: 전수 적용 시 판정 불가는 **122/2,441 = 5.0%** 다(내가 걱정한 「범람」은 반증됐다).

4. ★★**«남은 8건은 여러 토큰이 한 줄에 있거나 동적 생성»이라고 적었는데 — 재지 않은 추론이었고

   줄을 JSDoc 이어짐으로 보고 **셸의 거부 경로를 통째로 버리고** 있었다
   (`safe-deploy.sh:165` · `coord.sh:38` — 둘 다 배포 게이트의 **거부 경로**다).
   ⇒ 셸 분기를 주석 가드 **앞으로** 옮기고 셸 주석(`#`)만 적용. **`exit` 커버리지 126/126.**

5. **구문 게이트가 `.py` 판정을 어떻게 바꾸는지 전수로는 미측정.**

### R3 종결 검증 — 또 `REVISE`. ★**「감사되지 않은 일」의 네 번째 얼굴**

R2 를 반영하며 나는 *«감사되지 않은 일은 얼굴이 셋(판정 불가 · 건너뜀 · 절단)이니 하나를
rc 에 실었으면 나머지를 같은 함수에서 파생시켜라»* 라는 **일반형까지 적었다. 그러고도
네 번째를 놓쳤다.**

**범위 불일치로 조용히 빠진 파일** — 변경 파일이 지정 테스트와 종류가 안 맞으면 배제되고
그 변경은 **한 번도 변이되지 않는데**, `rc` 에도 `::AUDIT=` 에도 안 실렸다. 실측:

    변경 2파일(g.sh + a.ts) · 테스트는 pytest 하나만 지정
      (테스트와 짝이 맞지 않는 파일 1개는 대상에서 제외)     ← a.ts 가 통째로 빠짐
    ::AUDIT=… undecided=0 skipped=0 truncated=0
    생존 0 — 판정된 1건이 전부 테스트에 걸린다.              rc=0   ← **거짓 초록**

★그리고 **이 PR 이 `.sh` 를 바로 그 스코핑 경로(`want_back`)에 새로 편입시켰다.**
★★부수 발견: 그 수를 담던 변수 이름이 `--max` 절단과 **같아서**(`dropped`) 값이 덮여
  사라지고 있었다 — **이름 충돌 자체가 이 결함의 운반체**였다.

⇒ **조용한 배제(`scoped_out_files`)와 선언된 배제(`only_out_files`)를 가른다.**
  전자는 rc 에 싣고(3), 후자는 `--only` 로 **사용자가 의도를 밝힌** 것이라 안 싣는다
  (형제 도구가 `MUTATE_ALLOW_SHELL` 로 «사유를 남기면 통과»시키는 것과 같은 자리).
  두 모집단 실측: 배제 있음 `rc=3` ↔ 없음 `rc=0`. 손 변이 Z1·Z2·Z3 전부 `::VERDICT=CAUGHT`.

> ★**세 판에 걸쳐 같은 클래스가 네 번 나왔다.** 매번 «지적된 자리»를 고치고 형제 축을
> 남겼다. 그래서 `_audit_exit` 락을 **네 얼굴이 한 표에 서는** 파라미터 표로 바꿨다 —
> 다섯 번째가 생기면 그 표에 줄을 더하게 된다.

### R4 범위한정 검증 — `APPROVE`. 단 **내가 주석으로 금지한 불변식이 무잠금**이었다

R3 의 MAJOR 는 **해소 확인**(재현 실측 + 손 변이 CAUGHT). 그런데 R4 가 **내가 안 넣은
형태**(첨가형)로 두 가지를 더 찾았다:

1. ★**단위 혼동 — 양방향 모두 뚫림.** `judged`(변이 수)에 `scoped_out_files`/`only_out_files`
   (**파일 수**)를 섞는 변이가 **둘 다 `SURVIVED`**. 그런데 **바로 그것을 금지한다고 코드
   주석에 선언**해 두었다 — *«섞이면 항등식이 거짓이 되고 다음 사람이 단위를 오독한다»*.
   원인: 내 파라미터 표가 `scoped`/`only` 를 **항상 0 으로** 넘겨 **차이를 못 만들었다**.

   ⇒ 0 이 아닌 세 행을 추가. 재판정 W1·W2·W3 전부 `::VERDICT=CAUGHT`.
2. **다섯 번째 얼굴** — 스코프는 통과했는데 **추가된 줄이 어떤 변이 규칙에도 안 걸려 변이
   0건**인 파일은 어디에도 안 잡히고 `rc=0` 이다. 이 PR 의 선언 범위(**파일 단위** 감사의
   네 얼굴) **한 층 아래**(줄 패턴 커버리지)라 고치지 않고 **`xfail(strict)` 로 초록 안에**
   세웠다. ★산문으로만 두면 재발 저수지에 들어간다.

> ★**다섯 번째가 생겼다는 사실 자체가 «목록이 아니라 자리를 만들라»의 근거**다.
