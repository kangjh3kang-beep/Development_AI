## 2. 변경 내용

### A. 커버리지 — ★네 단지, **원인이 셋**이다 (뭉치면 처방이 틀린다)

| 단지 | 원인 | 처방 |
|---|---|---|
| 남양주두산위브트레지움 | **반경밖**(1km 밖·3km 내) | C-1 거리정렬 + 하드컷오프 제거 |
| 마석주공 | **매매 0 · 전월세에만 존재** | A-2 «이 단지는 전월세에 N건» 교차 고지 |
| 경향아파트 | **원천 무자료**(3km 내 0건) | A-3 정직 고지(«거래 없음»)로 종결 — 만들지 않는다 |
| 도뮤토라운지아파트 | 동일 | 동일 |

- **A-1 사전컷 정렬에 거리 프라이어**: 현재 `(동일치, -건수)`. 동(화도읍)은 너무 거칠다.
  **동 중심점 기반 개략거리**를 2순위로 넣는다(동 좌표는 이미 보유 — 외부호출 0).
  ★단, P3(캡 비구속)에서만 효과가 있다. **캡 구속 regime 에서는 효과 0**이므로
  그 조건을 코드 주석과 지표에 명시한다(M-4 기각 범위를 되살리지 않기 위해).
- **A-2 교차 kind 고지**: 매매 0인데 전월세에 있으면 말한다. 지금은 **침묵**한다.
- **A-3 «없음»과 «못 봄»을 가른다**: 사용자에게 둘은 같은 모양이다(이번 신고의 본질).

### B. 금액 병기 — 전체금액 + 평당금액

- **B-1 실거래**: `either/or` → **병기**. 예 `중흥S클래스 3.6억 · 1,415만/평`.
  면적 결측이면 평당을 **생략**하고 총액만(현행 정직 규약 유지 — 0으로 채우지 않는다).
  토글 `unit-price` 는 **강조 대상 전환**으로 의미를 바꾼다(제거하지 않는다).
- **B-2 분양**: 현재 **금액 0**. 분양가 총액·평당을 같은 포맷으로 싣는다.
- ★공용 포맷터 하나로 뽑는다(`won()` 재사용). 두 곳이 각자 포맷하면 갈린다(선례 있음).

### C. 반경 — ★제거가 아니라 **의미 전환**

볼트 판단을 승계하되 **다시 측정한 뒤** 적용한다.

| 층 | 반경 | 근거 |
|---|---|---|
| **표시**(마커·목록) | **하드 컷오프 제거 → 거리순 + nearest-N** | 사용자 불만은 «전국을 보여달라»가 아니라 «가까운데 숨기지 마라» |
| **계산**(AVM·탁상감정·비교표본) | **유지** | 반경 없는 표본이 감정단가를 **36배** 부풀린 사고 전력 |
| **인프라**(POI 800m·개발 1km) | **유지** | «도보권» 같은 의미 있는 반경 |

- **C-1 캡 정렬 1순위를 거리로**: `(-건수)` → `(거리, -건수)`. **이것이 변경의 본체다.**
  P7 로 `distance_m` 이 이미 있으므로 프론트·백엔드 모두 추가 비용 0.
- **C-2 마커·목록에 거리 병기** — 사용자가 스스로 판단하게 한다.
- **C-3 문구 개정** — 「반경 N 안」이 **전부 거짓**이 된다. 동시 개정하지 않으면 거짓 고지가 된다.
- ★**C-4 선결조건**: 상한을 올리려면 **클러스터링이 먼저**다(P10). 클러스터링 없이 상한만
  올리면 마커 폭주로 이번에 고친 «가독성» 결함이 재발한다. **본 계획은 상한을 올리지 않는다.**

### 회귀가 아닌 근거

- A·C 는 **정렬과 고지**를 바꾼다. 계산층 payload 소비 경로는 **건드리지 않는다**(볼트 Risk 2).
- B 는 **표시 문자열만** 바꾼다.
- 어느 것도 반경 필터를 **계산층에서** 제거하지 않는다.

## 3. ★검증하지 못한 것

- **경향아파트·도뮤토라운지아파트가 왜 0건인지**: 거래가 실제로 없었는지, MOLIT 가 지번을
  가렸는지, 단지명 표기가 다른지 **구분하지 못했다**. A-3 고지 문구는 이 구분이 서기 전까지
  «우리 데이터에 없음»으로만 쓴다 — «거래가 없었다»고 쓰면 거짓일 수 있다.
- **A-1 의 순효과**: 동 중심점 거리 프라이어가 실제로 수율을 올리는지 **미측정**.
  구현 전 오프라인 재현으로 먼저 재고, 음수면 착수하지 않는다(M-4 전례).
- **클러스터링 비용**: 미측정. C-4 를 실제로 하려면 별건 계획이 필요하다.
- **사용자 화면의 실제 반경 설정**: 화면은 1km 로 보이나 사용자가 바꿨을 수 있다.

## 5. 잠금

| 축 | 락 |
|---|---|
| A-1 | 사전컷 정렬이 **거리 프라이어를 실제로 쓰는지** — 두 모집단(가까운 동 ↔ 먼 동)이 **다른 순서**를 내야 한다 |
| A-2 | 매매 0 + 전월세 N > 0 인 픽스처에서 **고지가 발화**하고, 둘 다 0이면 **발화하지 않는다**(양방향) |
| A-3 | «없음»과 «미조회»가 **다른 문구** — 같은 문구면 락이 공허하다 |
| B-1 | 총액·평당이 **둘 다** 문자열에 실린다. ★면적 결측 픽스처에서 평당이 **생략**되고 0이 **찍히지 않는다** |
| B-2 | 분양 라벨에 금액이 실린다(현행 0건 → 회귀 시 즉시 빨강) |
| C-1 | 캡 정렬이 **거리 1순위** — 거래건수는 많지만 **먼** 그룹이 가까운 그룹에 밀리는 픽스처 |
| C-3 | 문구에 「반경 N 안」이 **남아 있지 않다**(정직성 락) |

★모든 락은 **변이로 CAUGHT 를 확인한 뒤** 커밋한다. 특히 C-1 은 **거리 항을 제거하는 변이**가
반드시 잡혀야 한다(«정렬키에 이름만 있고 값이 안 실리는» 형태를 이 저장소가 반복해서 겪었다).
