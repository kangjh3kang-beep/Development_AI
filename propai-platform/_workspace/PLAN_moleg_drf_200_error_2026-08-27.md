## 1. 전제 표 — **라이브 실측**(읽기 전용·무과금)

| # | 전제 | 확인 방법 | 결과 |
|---|---|---|---|
| 1 | 법제처가 오류를 어떻게 주나 | `lawSearch.do` 직접 호출 | **HTTP 200 · `application/json`** + `{"result":"사용자 정보 검증에 실패하였습니다.","msg":"…IP주소 및 도메인주소를 등록…"}` |
| 2 | 키가 틀린 건가 IP 인가 | ★**대조군** — 실제 키 vs **가짜 키** | **바이트 동일한 오류** → 키가 아니라 **IP 미등록** |
| 3 | `raise_for_status()` 가 잡나 | 코드 독해 + 실측 | ❌ **200 이라 통과** |
| 4 | `search_admrule` 이 무엇을 반환하나 | 코드 경로 추적 | 루트키 매칭 실패 → `results=[]` → **`available=True`** |
| 5 | `detect_gosi_update` 가 무엇을 단정하나 | 코드 경로 추적 | **`checked=True, changed=False`** = *"확인했고 고시 안 바뀜"* ← **거짓** |
| 6 | `check_law_updates` 는 안전한가 | 코드 독해 | ❌ `공포일자=""` → `recent=False` → **"변경 없음"**. `failures=0` 이라 **RuntimeError 가드 발화 불가** |
| 7 | 소비처가 몇 개인가 | 파생형 grep | `GosiSearchService` 소비처 **1**(`basic_building_cost`) · DRF 직접호출 모듈 **3** |
| 8 | `ordinance_service` 도 같은가 | 코드 독해 | ⚠️ 같은 봉투에 뚫리지만 **4단 폴백이 문서화**돼 있어 거짓 *단정*은 안 한다 → **이 PR 범위 밖**(별도) |
| 9 | 내 스캐너가 이걸 셀 수 있나 | ★**대조군** | ❌ **못 센다** — 세 파일 모두 0건이 나왔고 **내가 아는 결함 파일도 0** 이었다(죽은 대조군) → **grep 아닌 코드 독해로 판정** |

★**전제 2·9 가 이 계획의 뼈대**다. 대조군이 없었으면 ②는 *"키를 새로 받자"* 로,
 ⑨는 *"세 모듈 다 안전하다"* 로 갔다.

## 2. 변경 내용과 **회귀가 아닌 근거**

- 신규 `app/services/legal/moleg_drf_envelope.py` — 봉투 판별 **한 자리**.
  `drf_error_reason(payload) -> str | None` · `raise_if_drf_error` · 전용 예외 `MolegDrfError`.
  ★**`result` 하나로 판정하지 않는다** — *"정상 루트키가 하나도 없고"* + *"오류 키가 있다"* 를
  **함께** 본다(정상 응답에 `result` 가 있어도 오탐하지 않게).
- `gosi_search_service` 두 통로(`search_admrule`·`fetch_admrule_text`)에 배선 →
  `available: False` + **사유를 표면까지** 싣는다.
- `regulation_monitor.check_law_updates` 에 배선 → 전건 200-오류면 **기존 RuntimeError 가드가
  비로소 발화**한다(새 가드를 만드는 게 아니라 **있는 가드를 살린다**).

**회귀가 아닌 근거**: 정상 응답(0건 포함)은 판별을 **통과**하고 종전과 동일 경로를 탄다.
바뀌는 것은 **오류일 때의 표기**뿐이며, 그 경로는 지금 **거짓을 말하고 있다.**
★**금액 영향 0** — 이 PR 은 값을 만들지 않는다.

## 3. ★검증하지 못한 것

1. **정상 응답의 실제 루트키를 라이브로 못 봤다** — 이 환경은 **IP 미등록**이라 성공 응답을
   한 번도 못 받았다. `_OK_ROOT_KEYS` 는 **코드가 이미 방어하던 목록에서 파생**했고
   픽스처도 그 형태다. **프로덕션(158)에서 성공 응답을 받아 대조해야 완결**된다.
2. **IP 등록 여부 자체가 미측정** — 프로덕션에서도 실패 중인지 모른다.
   ★그렇다면 **기본형건축비 개정 감지가 실제로 죽어 있는지**가 이 PR 로 **비로소 보이게 된다**
   (종전에는 `checked=True` 라 보이지 않았다).
3. `ordinance_service` 는 **손대지 않았다**(전제 8) — 폴백이 문서화돼 있어 별건.
   다만 *"법제처 실시간 조회"* 가 **조용히 한 번도 안 될 수 있다**는 사실은 남는다.

## 4. 되돌리기 경로

`raise_if_drf_error` 호출 3줄. 되돌리면 즉시 원복.
★**트리거**: 배포 후 `detect_gosi_update` 가 **`checked=False` 로 바뀌면** 그것은 회귀가 아니라
**이 PR 이 드러낸 사실**이다 — 종전 `checked=True` 가 거짓이었다. 그때 할 일은 되돌리기가 아니라
**법제처에 서버 IP 를 등록**하는 것이다.
