## 2. 왜 이것이 필요한가 (라이브 증상)

`e56fc2a0` 화면에서 헤더는 **자연녹지지역**이라 단정했는데, 같은 페이지의 용도별 구성은
**제2종일반주거 91%** 였다(라이브 서버 판정). 헤더 값은 **낡은 저장 스냅샷**에서 왔고,
사용자에게는 **그것이 언제 것인지 알 방법이 없었다.**

★값이 **틀린 것**은 `#813`(전제 감사)이 잡는다. 이 PR 은 **언제 것인지 말하지 않는 것**을 고친다.
  둘은 다른 결함이다.

## 3. 변경 (최소)

`deriveContextHeaderData` 가 `fetchedAt` 을 함께 반환하고, `ContextHeader` 가 **기존 `basis`
문자열 뒤에** `(YYYY-MM-DD 기준)` 을 덧붙인다.

★**새 UI 를 만들지 않는다** — 이미 있는 근거 표면을 재사용한다(레이아웃 위험 0).
★**임의 임계(며칠이면 낡음)를 두지 않는다** — 낡음 판정은 사람이 한다. 시스템은 **사실만** 말한다.
★값이 없으면 아무것도 덧붙이지 않는다(무목업 — 가짜 시각 금지).

## 4. ★검증하지 못한 것

- 시각적 배치(문자열이 길어져 줄바꿈이 생기는지) — **jsdom 으로는 확인 불가**. 배포 후 확인 필요.
- 다른 로케일(en/zh)에서의 문구 — 이번 범위 밖(한국어 문자열만 다룬다).
