## 2. 변경 내용과 **회귀가 아닌 근거**

워커의 flush 루프가 주기적으로 자기 `capture_status()` 를 `platform_settings` 에 **발행**한다.

- **새 표면을 만들지 않는다** — 기존 `set_setting` → `active_flags` 통로를 **그대로 탄다**(§7 형식 이식).
- **읽기 경로 무변경** — `/heal-log` 는 코드 변경 없이 그 행을 이미 그린다(P4·P5 로 확인).
- 발행 실패는 **삼키고 로그만** — 관측이 배수를 죽이면 안 된다(기존 flush 루프와 같은 규율).

## 3. ★검증하지 못한 것

- **프로덕션 워커가 실제로 초당 몇 건을 쌓는지** — 여전히 **미측정**. 이 표면이 그것을 재는 도구다.
- **워커가 이 발행을 실제로 하는지**는 **배포 후에만** 확인된다(로컬은 arq 런타임이 없다).
  → 배포 판정 프로브를 §5 에 적는다.
- `analysis_coverage` 부채 · 프론트 렌더 — **범위 밖**(3중 경합).

## 4. 되돌리기 경로

발행 호출 한 곳을 지우면 끝난다(읽기 경로를 안 건드렸으므로 잔재 없음).
행은 남지만 `updated_by`/`at` 이 멈추므로 **모집단 ②로 스스로 드러난다**.

## 5. 잠금 — 이 변경을 지키는 검사

| 축 | 락 |
|---|---|
| **세 모집단 판별** | 깊이 0+최신 / 깊이 N+정지 / **행 부재** 가 서로 **다른 답**을 낸다 |
| **순환 금지** | 발행 경로에 `record_event` 가 **없다**(AST · 음성 대조군 포함) |
| **시각이 값 안에** | `updated_at` 이 아니라 **payload** 에 있다(P6) |
| **배수를 안 죽인다** | 발행이 예외를 던져도 flush 가 계속된다 |

★**모집단은 손으로 고르지 않는다** — `capture_status()` 키에서 **파생**해 계약을 잠근다
(오늘 `#901` 에서 손 목록이 상한이 되어 **HTTP 500 을 놓쳤다**).
