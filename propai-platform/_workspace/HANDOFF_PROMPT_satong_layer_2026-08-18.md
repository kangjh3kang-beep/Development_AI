## 4. 라이브로 확증된 것 / 안 된 것

**확증됨**

- **P1** — `e2e/satong-pane-ladder.spec.ts` 를 `BASE_URL=https://4t8t.net` 로 실행 → **2 passed**.
  변이(평탄화 재주입)로 **CAUGHT** 확인(진단까지 정확: `{"map":1,…,"popup":1}`).
- **P4** — 배포 전/후 같은 프로브:

  | 단계 | 배포 전 | 배포 후 |
  |---|---|---|
  | 레일 클릭 | clickMenu(470) + dialog(430) **동시 개방** | 동일 |
  | **ESC 1회** | **둘 다 닫힘** | **clickMenu 만** 닫힘 |
  | ESC 2회 | — | 레일 팝오버 닫힘 |

  ★닫힌 **순서**도 설계대로(470 먼저) — 등록 순서가 아니라 **값이 정한다.**

★**배포 전에 결함을 먼저 재현해 둔 것**이 핵심이다. 그래야 배포 후 초록이
*"프로브가 아무것도 못 열어서"* 가 아님이 보장된다.

**확증 안 됨(정직)**

- **Leaflet 팝업 인스턴스** 층위 판정은 여전히 **없다**. `#676` 의 소유권 상호배제로
  `/precheck` 폴리곤 경로엔 팝업이 안 생긴다 → **마커 표면**(분양·실거래·경매)이 다음 자리.
- 확인카드↔코너도크 겹침은 **없애지 않고 보이게** 했다. `bottomBar` 무충돌은
  **12px vs 64px 간격 하나에 의존**한다 — 높이가 커지면 다시 닿는다.
- ESC 조정은 **외부 포인터다운 미포함**(검색 콤보박스 `onKeyDown` 도 범위 밖).
- `e2e-nightly.yml`·`deploy-cloudflare.yml` 의 corepack 은 **패턴 동일성으로만** 보증된다
  (`#689` 의 CI 는 `ci.yml` 만 태웠다). **첫 나이틀리·첫 배포가 그 검증**이다.

| 판본 | 무엇을 잘못 쟀나 |

| 범위 | 조상 판정 생략 · 낡은 체크아웃 · **로컬 회귀 범위를 좁게** |
| 대상 | 다른 파일을 grep |

| 응답 코드 무시 | `rc=1` 에러 응답을 본문으로 읽음 |
| **자기 텍스트** | 내가 방금 쓴 **주석을 내 패턴이 집음**(한 PR 안에서 3회) |

**최종 규율 한 줄:**

> **조회할 수 있는 것을 추론으로 대체하지 않는다.**
> 조회가 가능한지 **먼저 묻고**, 가능하면 추론을 쓰지 않는다.

## 7. 실전에서 값을 한 절차 (그대로 재사용하라)

1. **배포 전에 결함을 먼저 재현**해 둔다 — 그래야 배포 후 초록이 의미를 갖는다.
2. **의사결정에 폴백 조건을 함께 적는다** — `#689` 에서 *"실패하면 그때 캐시를 제거한다"* 를
   커밋에 적어 뒀기에, 실패 순간 **재논의 없이** 실행으로 갔다.
3. **판별 지표를 여러 개 잡는다** — `#688` 배포에서 4개 중 **3개가 0**이었고 그게 정상이었다
   (상수 인라인·모듈 경로 소멸·트리셰이킹). 하나만 잡았으면 **미반영으로 오판**했다.
4. **"제거"는 층마다 따로 확인한다** — 빌드 산출물 · 런타임 주입 · 설정 파일.
5. **변이는 커밋 후에, 주입 성공을 확인하고** — `sed` 주입 실패를 "생존"으로 읽을 뻔했다(2회).
6. **파생형 > 목록형** — 손으로 센 밴드 점유자 2건이 파생 검사에서 **3건**으로 나왔다.
