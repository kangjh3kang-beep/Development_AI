## 2. 변경 내용과 **회귀가 아닌 근거**

1. **패널이 공용 헬퍼를 쓴다**(`ComprehensiveAnalysisPanel`) — 손수 map 제거.
   · `parcels`(표시·게이트) = `parcelDisplayAddress` 로 주소만 구분. **면적 필터 없음**(종전과 동일).
   · `parcelRows`(전송) = `parcelDataToRows`. **면적>0 의미론은 종전과 동일**(같은 필터).
   ★두 값을 **한 헬퍼로 뭉치지 않았다** — `parcelAddressList` 는 면적>0 을 상속하므로
     그것으로 `parcels` 를 만들면 *"외 76필지 선택됨"* 표시가 **줄어드는 회귀**가 된다.
2. **백엔드가 붕괴를 말한다** — `requested_parcel_count`(중복제거 **전**)·`collapsed_parcel_count`
   추가, `area_is_partial` 에 붕괴 경로 포함. **기존 키·계약은 그대로**(additive).
3. **화면이 붕괴를 구별해 말한다** — 종전 문구를 쓰면 붕괴 후엔 분모도 1이라
   「1필지 중 1필지만 조회됨」이라는 **무의미한 말**이 된다.

### ★하지 않은 것과 이유

**`_merge` 를 PNU 로 중복제거하도록 바꾸지 않았다.** `_merge` 는 **주소 목록**을 반환하고
하류(`one(a)`·`supplied`)가 **주소를 키로** 쓴다. PNU 로만 중복제거하면 같은 주소 문자열이
두 번 남아 **같은 필지를 두 번 조회·합산**한다(더 나쁜 결함). 정체성 교정은 **주소를 구분되게
만드는 쪽**(처방 1)이 옳고, 백엔드는 **붕괴를 보고**하는 데 그친다.

## 3. ★검증하지 못한 것

1. **사용자 스토어의 77필지 `address` 가 literally 동일한지 못 봤다**(localStorage 접근 불가).
   근거는 ①44.0㎡ 정확 재현 ②패널이 `pnu` 를 버려 지번 파생이 없음 ③중복제거 기전 확인의 **결합**이다.
   확정 명령: 그 화면 콘솔에서
   `new Set(useProjectContextStore.getState().siteAnalysis.parcels.map(p=>p.address)).size`
2. **스토어 필지에 `pnu` 가 실제로 채워져 있는지** 라이브로 못 봤다. 비어 있으면 이 처방은
   **증상을 못 고친다**(대신 백엔드 붕괴 고지가 뜬다 — 그래서 2·3층을 함께 넣었다).
3. **다른 소비처는 안 고쳤다** — `PreCheckWorkspace`·`AutoRecommendPanel` 등도 `parcels` 를
   넘긴다. 같은 결함이 있는지 **미측정**.
4. **라이브 화면 확증은 배포 후에만** 가능하다.
5. PNU 가 없는 필지는 여전히 붕괴한다(P3 이 그 동작을 **의도로 못 박았다** — 지어내지 않는다).

## 4. 되돌리기 경로

`git revert <머지커밋>`. 백엔드는 **additive 키 2개**뿐이고 패널은 헬퍼 호출로의 교체라 위험 낮음.
되돌리기 트리거: 시뮬 카드에 붕괴 경고가 **정상 다필지에서도** 뜨면(위양성).
