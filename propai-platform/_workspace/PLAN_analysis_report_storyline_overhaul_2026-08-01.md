## 1. 근본 문제 정의

현재 보고서는 **"값의 나열"**이고 사용자가 요구하는 것은 **"판단 가능한 서사"**다. 격차 4종:

1. **변경 원인 부재** — 값이 왜 달라졌는지 모르니 어느 쪽을 믿을지 판단 불가(P1~P3)
2. **신빙성 미표면화** — 어떤 수치가 추정이고 어떤 게 공식인지 화면에 없음(P7)
3. **실행 구조 한계** — 한 번에 다 못 돌려서 사용자가 버튼을 나눠 눌러야 함(P4·P5)
4. **전문가 언어** — 원시 키(`effective_far.zone_mix[*].area_sqm`)·영문 severity·"판정불가"가 그대로 노출

## 2. 웨이브 (의존순)

### W1 — 변경 원인 분류 엔진 ★최우선·자립
"모순"을 **원인 분류**로 대체. 순수함수 + 표면.
- 분류: `INPUT_CHANGED`(필지·주소 변경) / `PLATFORM_IMPROVED`(로직·버전 변경) / `SOURCE_UPDATED`(외부데이터 갱신) / `TRUE_CONTRADICTION`(같은 입력·같은 버전인데 값 상이)
- 판별 근거: `signature_parts` 대조(P2 — 이미 있는 데이터), 원장 `schema_version`·규칙 버전
- **`TRUE_CONTRADICTION`만 경고색**. 나머지는 중립/개선색 + 사유 문장
- 표면: 원시 키 제거, "무엇이·왜·어느 쪽이 신뢰도 높은지" 3문장 구조
- 불변식: 입력 지문이 다르면 절대 `TRUE_CONTRADICTION`으로 분류될 수 없다(변이 테스트로 잠금)

### W2 — 섹션 단계분할 실행 파이프라인
스토리 단계별 개별 호출 + 점진 렌더. CF 문제 근본 소멸.
- 단계: 부지확정 → 규제·법규 → 개발 가능성 → 입지 인프라(POI 자동) → 시장·시세 → 사업성(시뮬 자동) → 리스크·종합
- 각 단계 <100초 보장(초과 후보는 job_store로 위임 — P6)
- 실패는 그 단계만 "확인 실패" 정직표기, 나머지 생존(무음 낙관 금지)
- POI·시뮬 버튼 제거 → 파이프라인 단계로 편입(사용자 요청 #1 충족)

### W3 — 신빙성·근거 표면화
field_audit(P7)을 사용자 언어로 표면화.
- 각 수치에 출처 배지: 공식(법령·대장) / 실측(실거래) / **추정(계산식 명시)**
- "추정 시세 5.2억 = 공시지가 × 1.2" 처럼 **산식과 한계**를 그 자리에서
- field_audit findings → 해당 섹션 인라인 고지(계층 A 차단 / B 주의 / C 정직)

### W4 — 비전문가 언어 공용화
- 용어 사전 SSOT(원시 키 → 한국어 라벨) — 한 곳 고치면 전역 반영
- 수치 표기 규칙(단위·자릿수·반올림) 공용 포매터
- "판정불가"·`NEEDS_OFFICIAL_SURVEY` 등 → 사유 + 다음 행동 문장으로 치환

### W5 — 페르소나별 스토리라인 배치
설계사(규제·가능규모) / 디벨로퍼(사업성·리스크) / 시공사(공사비·공정) / 금융(수지·담보·회수) —
같은 데이터의 **강조 순서와 요약문**을 페르소나별로. 공통 본문 1벌 + 관점 레이어.
