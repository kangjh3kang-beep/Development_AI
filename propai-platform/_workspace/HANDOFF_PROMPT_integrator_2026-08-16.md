1. **자기 범위를 자기가 넓히지 못한다.** 두 세션이 독립적으로 셌고 결과가 같았다 —

2. **기록은 준수를 대체한다.** *"기록만으로는 안 온다"*(수동)가 아니라 **"기록하는 행위가
   준수를 밀어낸다"**(능동). 규율을 **인용하는 커밋일수록** 그 규율의 실제 확인을 따로 밟아라.
   실증: 나는 `#642` 교훈을 PR 본문에 써 놓고 **바로 다음 PR `#650`** 에서 어겼다.

3. **"0건"은 셋 중 하나다 — 미배포 / 잘못된 대상 / 잘못된 패턴.**
   보안·과금처럼 오보 비용이 큰 건은 **정본(origin/main)에 있는지부터** 대조하라.

4. **성공 신호와 빈 결과가 같은 값인 도구는 검증에 쓰지 마라.**
   실증 5종: `| head -1 && echo` 파이프 종료코드 · `[ -r /mnt/d ]` · `git grep -c | awk` ·
   **401 을 빈 목록으로 파싱** · 잘못된 파일 grep.

5. **손으로 세면 목록이 된다 — 사람이든 에이전트든.**
   감사 에이전트가 센 "8건"을 파생 술어로 재니 14건(넓은 술어)/6건(좁힌 술어)이었다.
   ★동시에 **위양성도 결함**이다 — 넓은 술어는 면적계산·층수추정·진행률을 위반으로 신고했다.

6. **전달이 불확실성을 떨어뜨리면 원 저자의 정직성이 무효가 된다.**
   에이전트가 "정적 근거만·라이브 미확인"을 명시했는데 옮기며 한정을 뗐다.

7. **사용자의 근거가 틀려도 결론은 맞을 수 있다.** 지도 z17 건이 그랬다 —
