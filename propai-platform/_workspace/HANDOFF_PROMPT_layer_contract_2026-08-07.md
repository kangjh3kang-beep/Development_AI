## 3. 이 저장소의 층위 계약 (정본: `apps/web/lib/satong-map-z.ts`)

```
지도 오버레이(≤500) < 본문 sticky(600) < 네비 플라이아웃(700) < 모달(800) < 앱 크롬(1000)
                                                            전체화면(9990)만 크롬 위
```

**층위를 건드릴 때 반드시 알 것**:
- 지도 래퍼는 **스태킹 컨텍스트를 만들지 않는다** → 오버레이가 루트에서 본문과 경쟁한다
- 지도 타일만 `.leaflet-container{isolation:isolate}` 로 격리돼 있어 **본체는 아래, 부속은 위**로
  가는 비대칭이 있다
- **z 를 올려도 소용없는 경우가 있다**(컨텍스트 안에 갇히면) — 컨텍스트 자체를 봐라
- 한 칸을 올리면 **위/아래 칸이 함께 검사**되도록 `__tests__/layer-ladder.contract.test.tsx` 가
  사다리 전체를 잠근다

## 4. 재생성 금지 — 이미 반증한 것

1. "지도 위에서만 경쟁한다 → 지도 컨트롤이 이기는 게 옳다" → **거짓**. 패자는 본문 정보였다
2. "근원 봉합은 풀스크린 회귀 위험" → **존재하지 않는 경로**(`mode:"css"` 라 네이티브 분기 도달 불가)
3. "래퍼에 `isolate`" → 오버레이는 갇히지만 **FAB(95)이 지도 컨트롤 위로** 올라와 서열이 뒤집힌다
4. "전역 모달 z 일괄 승격" → 실측 결과 실위험 조합이 적어 **회귀 위험 대비 이득이 낮다**
5. "앱 헤더가 지도 오버레이에 덮인다" → 앱 헤더는 z-1000 이라 **안전**(좌표 겹침을 z 우열로 오독한 것)
