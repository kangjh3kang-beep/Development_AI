### 결함 요약

**사용자가 웹훅을 등록하면 화면은 성공했다고 말하고 서버에는 아무 일도 일어나지 않는다.**
미배선보다 나쁘다 — **거짓말**이다. 그리고 목업이 지어낸 「마지막 전송 상태」는
**백엔드가 주지 않는 데이터**였다.

## 2. 변경

1. 목록/등록/토글/삭제를 **실 API** 로. 서버가 만든 행을 그대로 쓴다(화면이 id·시각을 안 지어낸다)
2. **낙관적 갱신 금지** — 서버가 거부하면 화면도 안 바뀐다
3. **지어낸 두 필드 삭제**. 대신 서버가 실제로 주는 `description`·`created_at` 을 적는다
4. 오류를 **삼키지 않는다**(상태코드/`detail` 을 사람 말로)

## 3. ★검증하지 못한 것

- **라이브에서 실제 등록/삭제를 안 해 봤다.** 웹훅은 외부 URL 로 발송하는 부작용이 있어
  라이브 쓰기 검증은 **의도적으로 하지 않았다**. 배포 후 확증은 **읽기(GET 목록)** 로만 한다.
- `/{id}/deliveries`·`/{id}/test` 는 **안 붙였다** — 목록 화면의 범위를 넘는다.
  「마지막 전송」을 다시 보이려면 그 경로가 필요하다(별건).
- ~~`SubscriptionPanel` 미조치~~ → **★이 PR 에서 함께 닫았다**(같은 결함 클래스·같은 디렉토리).
  ★그쪽이 **더 심각했다** — 과금 화면이 `프로젝트 2/3개 · API 호출 347/500회 · AI 분석 18/30회 ·
  스토리지 156/500MB` 를 보여 줬는데 **백엔드에 그런 건수 쿼터가 없다**(과금은 **예산(원) 기반**).
  사용자가 그 숫자로 판단하는 화면이다.
  · 지어낸 4행 **삭제** · 서버가 주는 `billed_krw`·`budget_krw` 로 교체 · 현재 등급은 **서버가 정한다**
  · **없는 값은 행을 만들지 않는다**(0 으로 지어내지 않는다)
  · ★**가짜 데이터와 정적 문구를 갈랐다** — 플랜 기능 목록의 *"API 호출 월 500회"* 는 서버가 주지
    않는 **마케팅 문구**이고 결함이 아니다. 락의 검사 범위를 `data-testid="billing-usage"` 로
    좁혔다(첫 실행에서 락이 그 정상 문구를 결함으로 신고했다)
- ★**「목업 2건」은 하한**이다 — 대문자 `MOCK_` 명명 축이라 소문자·인라인 리터럴은 안 잡힌다.
