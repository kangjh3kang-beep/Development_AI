## 2. 그래서 무엇을 만드는가 — ★요청의 재해석

요청을 그대로 읽으면 «입력 폼을 새로 만든다」이지만, 측정 결과 **폼은 이미 있고 흩어져 있다.**
그대로 하나 더 만들면 **다섯 번째 이름**이 생긴다.

| 요청 항목 | 지금 | 할 일 |
|---|---|---|
| 건축개요 입력 폼 | ◎ 있음(8종) | **재사용** — 새로 만들지 않는다 |
| 대지면적 | ◎ 있음 | 정본에 편입 |
| **지상/지하 연면적 구분** | ✘ **0건** | ★**신설** |
| 용적률·건폐율 자동 산입 | △ 역산 로직 일부 | 정본에서 **파생값으로** 계산 |
| 평형·상가·오피스 | ◎ 있음(분산) | 정본 스키마로 통합 |
| 팝업 새창 | ◎ 모달 프리미티브 있음 | **재사용** |
| 통합 필지 입력에서 열기 | ✘ 없음 | ★**신설**(진입점) |
| 보고서 글로벌 적용 | ✘ 이름 4종 분열 | ★**SSOT 신설 + 어댑터** |

### 설계 — 3층

    ① 정본 스키마   packages/schemas  BuildingOverview
       landAreaSqm · aboveGroundGfaSqm · basementGfaSqm · buildingAreaSqm
       uses[]  { useType: 주거|상가|오피스|근생|… , gfaSqm, unitCount?, avgExclusiveSqm? }
       ★파생값은 **저장하지 않는다**: farPct = 지상GFA/대지면적, bcrPct = 건축면적/대지면적
         (저장하면 원본과 갈린다 — 오늘 푸터에서 겪은 그 형태)

    ② 순수 계산    lib/building-overview.ts
       deriveFar() · deriveBcr() · sumGfaByUse() · validate()
       ★입력이 0/음수/미입력일 때 **「모름」을 유효값으로 표현하지 않는다**(null 로)

    ③ 소비 어댑터  lib/building-overview-adapters.ts
       toConstructionCostInput() · toEsgPanelInput() · toFeasibilityModuleInput()
       ★기존 4종 이름을 **어댑터가 흡수**한다 — 94곳을 한꺼번에 고치지 않는다

### 진입점

    통합 필지 입력(SatongMapShell) 하단에 「건축개요 입력」 버튼 → 모달
    ★필지가 0개면 **비활성**(대지면적이 필지 합계에서 오므로 — 공허한 입력 방지)
    ★대지면적 기본값 = 선택 필지 면적 합계(자동 산입) · 사용자가 덮어쓸 수 있고
      덮어썼음을 **표시**한다(자동값과 수동값을 구별하지 않으면 다음 사람이 못 믿는다)

## 3. ★검증하지 못한 것

- **94개 소비처 중 몇 곳이 어댑터로 실제 전환되는지** — 미측정. 이 계획은 **어댑터 3종**만 만든다.
  나머지는 각 소비처 소유자가 옮긴다(한 PR 로 94곳을 건드리는 것은 되돌리기가 불가능하다).
- **용도(useType) 목록의 정본** — 지금 5개 컴포넌트가 각자 갖고 있다. 그 합집합을 아직 안 셌다.
  ★스키마를 짜기 **전에** 세야 한다(손으로 고르면 목록이 곧 상한이 된다).
- **기존 `ModuleInputForm` 사용자 데이터의 마이그레이션** — 미측정.
  기존 입력을 새 스키마로 옮길지, 병행할지는 소유자 판단.
- **#992 와의 충돌** — 방금 그 폼을 2차 확장했다. 소유자(sid=d67f8fff)와 조율 필요.

### 착수 후 갱신 (2026-09-09 · 라벨을 승계하지 않고 다시 잰 것)

- **용도(useType) 정본** — ✅ 해소. 「합집합을 안 셌다」는 위 항목을 실측으로 갈음했다:
  17파일 · 7목록 · 축 안 4종을 전수로 뽑아 `lib/building-use.ts` 를 정본으로 세웠고,
  **3목록은 다른 축이라 뺐다**(경공매 물건종류 · 입찰가율 키 · 에너지원단위 영문 키).
  ★남은 **미측정**: 그 3목록 외의 나머지 소비처 이관(축 안 4종 중 1종만 이관했다).
- **모달 표면 계약** — ★착수 시점에 **모르던 축**이 하나 더 있었다. `modal-dismiss.contract.test.tsx`
  가 파생 수집으로 새 표면을 잡아, ESC·포커스·**트랩 범위** 세 축을 함께 요구했다.
  실측 결과 내 모달은 `role="dialog"` 와 트랩 `ref` 를 **한 요소에 겹쳐** 달아, 락이 보는
  「백드롭에 트랩이 달렸다」와 구별되지 않았다 — 형제 3표면은 전부 갈라 놓고 있었다(§29).
  → 배선하고 `FOCUS_WIRED`·`RUNTIME_CASES` 에 등재했다(**면제를 늘리지 않았다**).
- **DB 에 저장된 `building_type` 값 분포** — 여전히 **미측정**. 정본의 `CODE_TO_WIRE` 는
  전선 값을 **바꾸지 않으므로** 회귀가 아니지만, 「어떤 값이 실제로 쌓여 있는가」는 안 쟀다.
