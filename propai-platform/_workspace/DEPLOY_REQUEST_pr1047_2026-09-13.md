## 2. ★배포자가 **반드시 알아야 할 것** 셋

## 3. ★배포 후 검증 — **가용성이 아니라 기능**

정본이 적었다: *"25회 이상 「라이브 검증 완료」라고 보고한 것의 실체는 **가용성 검사**였고

### ★함정: 상태코드로는 가를 수 없다

새 엔드포인트는 **배포 후에도 404** 다(존재하지 않는 추첨 id 라 **핸들러가 404 를 낸다**).
***「404 → 404」를 보고 「배포 안 됐다」고 오진하게 된다.*** **본문**으로 가른다:

```bash
U=https://api.4t8t.net/api/v1/sales/draw/groups/00000000-0000-0000-0000-000000000000/verify
curl -s -m 15 "$U"

#  배포 **전**(2026-09-13 실측) : {"detail":"Not Found"}          ← 라우트 부재
#  배포 **후** 기대             : {"detail":"공약이 없습니다"}      ← ★핸들러가 응답했다
```

★**두 번째가 나오면** 라우트가 살아 있고 **서비스 계층까지 닿았다**는 뜻이다
(상태코드도 200 도 아니고 **본문만**이 그것을 말한다).

### 대조군(조회기 생존 증명 — 이것 없이 「0건」을 말하지 않는다)

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://api.4t8t.net/api/v1/auth/login   # 405(있는 경로)
curl -s -o /dev/null -w '%{http_code}\n' https://api.4t8t.net/zzz-없는경로         # 404(없는 경로)
curl -s https://api.4t8t.net/health                                               # healthy
```

### 배포 전 기준선 (실측 2026-09-13)

    /health                     200 · healthy · version 62.0.0 · postgres/redis/qdrant healthy
    …/draw/groups/<0>/verify    404 · {"detail":"Not Found"}
    …/subscription/<0>/verify   404 · {"detail":"Not Found"}
    /api/v1/auth/login          405   ← 대조군
