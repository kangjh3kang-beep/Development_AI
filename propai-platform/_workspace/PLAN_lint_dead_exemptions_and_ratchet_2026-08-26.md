## 2. 왜 전면 `--max-warnings 0` 이 아닌가

그러면 **다른 세션의 무관한 PR 이 즉시 빨개진다.** 이 저장소는 동시에 여러 세션이 개발하고,
지금 158건이 84파일에 흩어져 있다. 래칫은 *"늘지 않게"* 만 하므로 **기존 경고가 있는 파일을
건드리지 않는 PR 은 영향이 없다.**
★**전면 게이트화는 팀 결정 사안**으로 남긴다 — 나 혼자 정할 것이 아니다.

## 3. 왜 단일 카운트가 아니라 파일별인가

- 단일 카운트는 **어디서 늘었는지 말하지 않는다.**
- 파일별이면 **줄었을 때도 알려 준다** → 래칫을 낮추라는 신호가 되어 **정리를 유도**한다.
  ★단 줄었다고 **실패시키지는 않는다** — 곁가지로 하나 고친 PR 을 빨갛게 하면 정리를 벌주는 꼴이다.

## 5. ★검증하지 못한 것 (승계 금지)

1. **CI 에서 실제로 돌려 보지 않았다.** `pnpm lint --format json -o` 의 인자 전달은
   로컬에서 확인하지만, GitHub Actions 러너에서의 동작은 **이 PR 의 CI 가 첫 실측**이다.
2. **제거한 31개 면제가 정말 "죽은" 것인지는 eslint 판정을 신뢰한 것**이다.
   `--report-unused-disable-directives` 가 그렇게 말했고 나는 재검증하지 않았다.
   ★다만 `tsc` 는 통과했고 **에러는 0 그대로**다.
3. **런타임 테스트를 안 돌렸다**(vitest 전수). 주석 제거라 논리 변경이 없지만 **재지 않았다.**
4. **다른 세션이 지금 만들고 있는 PR 이 이 래칫에 걸릴 수 있다.** 그들의 브랜치는
   래칫 파일이 없는 상태에서 갈라져 나갔으므로, 머지 후 경고를 새로 만들면 빨개진다.
   ★보드에 공지했다. **불편이 예상되면 되돌리는 것이 옳다.**
5. **`react-hooks/*` 70건은 손대지 않았다** — 그건 진짜 코드 결함일 수 있고
   기계적 제거가 불가능하다. 래칫으로 **동결**만 한다.

## 6. 되돌리기

세 갈래 전부 독립적으로 되돌릴 수 있다:
① `ci.yml` 의 래칫 스텝 제거 → 게이트만 사라지고 코드는 그대로
② `lint-ratchet.json` 삭제 → 스텝이 exit 3 로 시끄럽게 죽는다(조용히 통과하지 않는다)
③ 면제 제거 커밋 revert → 원상복구

위 4축을 **실제 리포트를 변형한 입력**으로 확인했다(합성 픽스처가 아니다).
★그래도 **자동 회귀망은 아니다** — 스크립트가 조용히 망가지면 exit 3 로 죽어야 하는데
그 경로는 **사람이 손으로 태운 것**이지 CI 가 매번 태우는 것이 아니다. 알고 남긴다.
