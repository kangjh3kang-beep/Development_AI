## 2. 변경 내용과 **회귀가 아닌 근거**

1. **락 보강**(활성 결함): 음성 단언 하나 → **3축 + 대조군**
   ①양성(페이지 집계 3건이 그려진다) ②음성(서버값 아님) ③고지가 뜬다
   ④**대조군**: 서버가 집계를 주면 그 고지가 **뜨지 않는다**(상시 문구면 ③이 무의미)
   ★픽스처 warn 을 1→3 으로 둔 이유: 전역 픽스처의 `"1"` 은 화면 다른 곳과 충돌해 대조가 흐려진다.
2. **폴백 고지**(잠복 예방): `!countsFromServer` 일 때만 한 줄. **같은 파일의 절단 고지 관용을 복제**
   (새 UI 를 만들지 않는다 — 형제를 안 보고 새로 만드는 것이 이 저장소가 반복해 데인 자리다).

무회귀 근거: 정상 경로(서버가 집계를 줌)에서는 **DOM 이 종전과 같다**(고지는 조건부이고 그 조건이
현재 항상 거짓). 대조군 테스트가 그 사실을 단언한다. 계산 로직은 **한 줄도 안 건드렸다**
(`countsFromServer` 는 기존 `serverCounts` 의 Boolean 사본).

## 3. ★검증하지 못한 것

- **폴백 경로를 라이브에서 재현하지 않았다.** 재현하려면 API 를 롤백해야 하고, 그건 **검증 비용이
  보호 대상보다 크다**(§라이브 프로브 규율). 그래서 *"활성 결함을 고쳤다"* 고 쓰지 않는다.
- 고지 문구가 실제 롤백 상황에서 **레이아웃·다크모드**를 깨지 않는지 — 안 쟀다.
- 문구의 정확성: 폴백은 *"현재 목록"* 중에서도 `status==="open"` + 비조치 타입 제외로 **더 좁게** 센다.
  문구는 그 좁힘을 말하지 않는다 — **과소 설명**일 수 있다(리뷰에 판정을 맡긴다).
- `info: 2000` 을 **다른 축**(기간·프로젝트 필터)으로는 재지 않았다. severity 축에서만 정합을 봤다.
- ★**초판 P7 수치가 창 불일치였다**(위 표에 정정 이력을 남겼다). 잰 것이 *"화면이 실제로 보내는 쿼리"* 가
  아니라 내가 편한 쿼리였다 — 이 세션에서 같은 클래스를 여러 번 냈다.
  ★★그리고 **P7 만 고치고 P2·P5 에는 같은 불일치를 남겨 뒀다**(독립 리뷰 지적). 정정이 **한 항목만**
  닿으면 나머지가 정정된 문서 안에서 더 신뢰받는다 — 지금은 세 항목 모두 **창을 라벨링**했다.
- **`platform_insights.severity` 가 NULL 일 수 있는지** 재지 않았다(리뷰가 남긴 미측정).
  NULL 이면 백엔드가 `"None"` 키를 만들어 세 카드가 0 이 되는데 고지는 안 뜬다 — `{}` 와 같은 계열이다.
  이 PR 이 만든 것은 아니고 **라이브에서 NULL 을 관측하지 못했다.**
