## 2. 변경 내용과 **회귀가 아닌 근거**

1. **`available_subset` 이 정직 필드 5종을 중계**한다(하위 site 에서 그대로 옮김).
2. **패리티 락을 「키 존재」에서 「ctx별 값」으로.** 그리고 선별자를 **역할 기반**
   (`total_area_sqm` + `parcel_count` 를 함께 내는 dict)으로 바꿔 세 번째 표면을 모집단에 넣는다.
3. ★**두 종류를 구별한다** — **계산형**(자기가 만든다 → `requested_count`·`addrs` 를 읽어야)과
   **중계형**(하위 site 를 옮긴다 → 같은 이름 키를 실어야). 한 판정으로 뭉치면 둘 중 하나가 거짓이 된다.

회귀 아님: 백엔드는 **additive**(subset 에 키 5개 추가). 락은 강화만 한다.

## 3. ★검증하지 못한 것

1. **`available_subset` 의 부분합 경로를 실행 재현하지 못했다** — 코드상 도달 가능을 논증했을 뿐
   (일부 차단 + 나머지 중 미해석). 라이브 재현은 미측정.
2. **프론트가 그 필드를 아직 안 그린다** — 백엔드가 실어 보내지만 `DevelopmentScenarioCard` 의
   `available_subset` 타입에 정직 필드가 없다. **소비처 0** 상태다(이 PR 범위 밖 · 부채로 명시).
3. **site 표면이 셋뿐인지는 `simulate` 안만 봤다** — 다른 함수가 site 를 만들면 여전히 미감시.
   ★`#934` 계획서가 같은 문장을 적었고 **그때 틀렸다**. 이번에도 같은 한계다.
4. 라이브 확증은 배포 후에만.
