# 계획서 — `globals.css` 언레이어드 요소 기본값 이동 (2026-08-24)

## 1. 전제 (측정으로 확인한 것만)

| 전제 | 확인 방법 | 결과 |
|---|---|---|
| Tailwind v4 가 유틸리티를 레이어에 넣는다 | `globals.css` 첫 줄 | `@import "tailwindcss"` · `@layer base/components/utilities` 선언 **확인** |
| 언레이어드 규칙이 유틸리티를 이긴다 | **라이브 브라우저 `getComputedStyle`** | `<h1 font-medium>` → **700**(기대 500) · `<p leading-none>` → **27.2px**(기대 16px) · `<button text-xs>` → **16px**(기대 12px) |
| 유틸리티 자체는 정상이다 | **대조군** `<div font-medium>` | **500** ✔ — 언레이어드 규칙이 있는 요소 **한정** 문제 |
| 영향 규모 | 소스 전수 | 헤딩 **380** · `<p>` **417** · 버튼 **47** |
| 개발자가 우회했는가 | `!important` 사용 실측 | 해당 요소에 **0건**(저장소 전체 `!` 유틸리티 1건) → **아무도 몰랐다** |
| 형제가 남아 있는가 | `@layer` 밖 요소 규칙 파싱(중괄호 균형) | **10건** — 종전에 `a` **하나만** 옮기고 스윕 안 함(규율 §6) |

## 2. 변경

`@layer` 밖 요소 규칙 **10블록**을 `@layer base` 안으로 **이동**(삭제 아님).

## 3. 왜 이것이 회귀가 아닌가

우회(`!important`)가 **0건**이므로, 아무도 "유틸리티가 안 먹는 상태"에 맞춰 코드를 쓰지 않았다.
이동 후에는 **작성자가 쓴 유틸리티가 그대로 적용**된다 — 즉 **의도대로 렌더된다.**
유틸리티가 없는 요소는 base 규칙이 그대로 적용되므로 **무변경**이다.

## 4. ★검증한 것과 **하지 못한 것**(정직)

- **검증함**: 전제 6종(위 표) · 구조 불변식 테스트 3건 · 옮긴 규칙이 **사라지지 않았음**(대조군)
- **검증 못 함**: **시각적 결과**. 800곳 이상의 타이포그래피가 "작성 의도대로" 바뀌는데,
  그중 일부는 **부주의하게 붙은 유틸리티**일 수 있다(예: 디자인 의도가 600 인데 누가
  `font-normal` 을 무심코 붙였다면 이제 400 으로 보인다).
  → **배포 후 화면 확인이 필요하다.** 이 PR 은 그 확인을 대체하지 않는다.
