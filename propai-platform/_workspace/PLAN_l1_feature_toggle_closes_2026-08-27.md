## §2 변경 내용과 회귀가 아닌 근거

1. 후보 SQL 을 `SELECT id, metrics_json` 으로 — **닫을 대상을 조회한다.**
2. `feature_toggle` 후보가 `insight_id` 를 **들고 간다.**
3. 디스패치의 **단일 길목**(`if res.get("applied")`)에서 **한 번만** 닫는다.
   분기가 셋이라 각 분기에 손으로 붙이면 반드시 하나를 빠뜨린다(`#886` 의 판단을 따른다).
4. ★**공용 헬퍼를 재사용**한다(`healing_rules.mark_insight_acted`). 복제하면
   **한쪽만 고쳐지는 형제가 또** 생긴다 — 이 PR 이 존재하는 이유가 그것이다.
   L1 의 평평한 후보/`applied` 를 헬퍼 계약(`params.insight_id`/`executed`)으로 **번역**해 넘긴다.

**회귀가 아닌 근거**
- `insight_id` 가 없는 종류는 헬퍼가 **0 을 돌려주고 아무것도 안 한다** → 연속 보정 2종 무영향.
- 헬퍼는 **`status='open'` 만** 닫는다 → 사람이 이미 판단한 행은 안 건드린다.
- `best-effort`(예외 삼킴) → 닫기 실패가 L1 사이클을 죽이지 않는다.
- 라이브 `acted` 가 **0** 이라 줄어들 값이 없다.
- 형제 회귀 확인: `test_growth_dynamic_config` · `test_heal_closes_the_insight` **21 passed**.

## §3 ★검증하지 **못한** 것

1. **라이브 확증 없음.** 게이트(`down_pct >= 40`)가 미달이라 이 경로가 **현재 안 돈다**.
   도달성은 픽스처로 증명했고 **발생은 미관측**이다. → *"고쳤으니 곧 `acted` 가 생긴다"* 고
   말하지 않는다(그렇게 말하면 `#886` 문서의 교훈을 그대로 반복하는 것이다).
2. **`float(m.get("down_pct") or 0.0)` 가 보류(None)를 `0.0` 으로 붕괴시킨다**(별건).
   오늘 안전한 이유는 게이트가 **한 방향**(`>= 40.0`)이기 때문**뿐**이다 —
   대칭 규칙("낮으면 재활성")이 생기면 **미측정으로 발화**한다.
   ★이 PR 에서 **고치지 않았다**: 동작이 바뀌지 않는 무해한 정리라 범위를 넓히지 않았고,
   `#901`(보류 계약을 표면까지)이 착지한 뒤 그 어휘로 함께 다루는 것이 맞다.
3. 실 Postgres 통합 테스트 **0건** — 스텁이 SQL 을 실행하지 않으므로 `SELECT id …` 의
   문법은 **문자열로만** 방어된다.

## 【추가 2026-08-28】리뷰 요청은 **거절당했는데** 그 거절이 결함 둘을 냈다

질문 둘을 줬고, 재 보니 **둘 다 진짜였다.**

### ① *"락이 「호출했다」를 보는가, 「그래서 상태가 그렇게 됐다」를 보는가"*

스텁 `_Recorder` 가 `(action.get("params") or {}).get("insight_id")` 를 **다시 쓰고** 있었다.
그러면 진짜 `mark_insight_acted` 가 계약을 바꿔도 이 락은 초록이다:

    진짜 closer 의 추출 경로 변경 변이
      · 이 파일 단독      → **SURVIVED**
      · 성장루프 전체 락  → CAUGHT (형제가 잡았다)

**형제가 잡는다고 이 락이 잠근 것은 아니다.** → 스텁은 **원문 그대로** 보관하고,
판정은 `mark_insight_acted` **소스 파일을 `ast` 로 파싱**해 그 추출식을 평가한다.
★`inspect.getsource(healing_rules.mark_insight_acted)` 는 **못 쓴다** — 이 락이
`monkeypatch` 아래에서 돌아 **스텁을 본다**(실측 `TypeError: … got _Recorder`).
재검증: 그 변이가 **CAUGHT** 로 뒤집혔다.

### ② *"픽스처가 경계 근처를 태우는가 — 분쟁 대역이 비어 있지 않은가"*

픽스처가 `down_pct=90.0 · 표본 20+20` 이라 게이트(40.0 / 합 10)에서 **한참 위**였다:

    FEATURE_DISABLE_ERROR_PCT  40.0 → 0.0   → **SURVIVED**
    FEATURE_MIN_SAMPLES        10   → 0     → **SURVIVED**

**게이트가 잠겨 있지 않았다.** 경계 모집단 넷을 넣었다(경계값 · 품질 한 칸 아래 ·
표본합 경계 · 표본합 한 칸 아래).

★**그런데 파생만으로는 여전히 안 잡혔다** — 기대값을 상수에서 파생시키니 상수를 낮추면
픽스처와 기대값이 **같이 움직인다**(자기지시적 기대값). **파생과 못 박기는 다른 락**이라
`test_the_gate_constants_are_pinned` 로 리터럴을 못 박았다. 그제서야 3종 전부 CAUGHT.

★**내가 계약을 잘못 읽은 것도 이 과정에서 드러났다**: 게이트는 `(ftotal + vtotal) >= 10`
**합**인데 나는 각각으로 읽었다(9와 9 = 18 이라 발화). 픽스처 주석이 *"표본 >= 10"* 이라고만
적어 **합인지 각각인지 말하지 않았다** — 그 주석이 나를 틀리게 했다.

### ★③ 별건 — `_should_disable()` 은 **호출부 0건**이다 (이 PR 에서 안 고친다)

    _should_disable 호출부 전수  →  **0건**(독스트링 1 · __all__ 1 뿐)
    ★대조군 같은 방법으로 형제 헬퍼 → 2건 (조회기 생존)
