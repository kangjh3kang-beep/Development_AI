## 2. 변경 내용 — **절단일 때만** 2단 분할

    1차(무변경): 전체 스키마 1회 호출
    ★is_truncated 면 → 2단 재시도
        2a) **사실만**: ownership/owners/history/seizure/mortgage/other_rights/provisional
            (산문 필드 제거 → 출력이 짧아진다)
        2b) **판단**: baseline_right/acquired_extinguished/right_to_demand_sale/
            rights_analysis/risks/safety_grade/summary
        병합해 반환

★★**초안을 구현 중에 고쳤다 — 캡의 대상을 잘못 짚고 있었다.**
초안은 *"2b 의 입력은 **2a 의 구조화 사실**(짧다)"* 이었다. 그런데 `max_tokens` 가 캡하는 것은
**출력**이다(입력은 이미 등기부 전문이 들어가고 있었다). 사실 요약만 넘기면 말소기준권리
순위·대항력 판단이 **접수번호를 못 보고 근거가 얇아진다** — 얻는 것 없이 품질만 잃는다.
→ **2b 도 원문 등기부를 그대로 본다**(+ 2a 의 사실 JSON 을 함께). 락이
`"긴 등기부 원문" in seen[2]` 로 이것을 잠근다.

★**정상 경로는 손대지 않는다**(과금·지연 불변). 절단 경로는 지금 **전량 실패**이므로
호출이 늘어도 «실패 → 성공» 이다.

★**2b 가 실패해도 2a 의 사실은 살린다** — 산문 없이라도 소유·담보·압류는 화면에 뜬다.
그때 사유를 **정직하게** 남긴다(«판단 산문 생성 실패 — 사실은 유효»).

## 3. ★검증하지 못한 것

- **2b 의 입력이 정말 안 잘리는가** — 논리적으로는 짧지만 **긴 등기부 실물로 재보지 못했다**
  (유료 호출이고, 실패 재현에 실제 등기부가 필요하다). **미측정**.
- **절단이 유일한 실패 원인인가** — `#968` 에서 이어지는 미결. 라이브 `raw_head` 2건만 봤다.
- **분할이 품질을 낮추는가** — 2b 가 원문을 보게 고쳤으므로 **근거는 얇아지지 않는다.**
  다만 사실 추출과 판단이 **다른 호출**이라 일관성이 떨어질 여지는 남는다.
  ★이건 **정확도 축**이라 락으로 못 잡는다 — **미측정**.
- **비용** — 절단 시 호출이 1 → 3(1차 + 2a + 2b). 그 경로의 **빈도를 재지 못했다**.
  정상 경로는 **1회 불변**이고 락이 호출 횟수를 직접 센다.
- **로컬 회귀 기준선을 못 잡았다** — 이 워크트리의 Python 은 **3.10.19** 인데
  `integrations/base_client.py` 의 「3.10 호환성 백포트」가 `except ImportError` 안에서
  다시 `enum.StrEnum` 을 참조해 **270건이 수집 단계에서 죽는다**(선재 · 내 파일은 그
  체인에 **0건**). CI(3.11+)가 기준선이다. ★그 백포트 자체가 결함으로 보이지만 **범위 밖**이다.

## 4. 되돌리기
