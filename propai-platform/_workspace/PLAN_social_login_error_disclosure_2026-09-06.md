## 2. 변경 내용과 회귀가 아닌 근거

1. **콜백 3사가 `error`·`error_description` 을 읽어 전달**한다(`page.tsx` → 클라이언트).
2. 클라이언트가 그 값을 **사용자 언어로 번역해 고지**한다 — ★**사용자 취소**와 **설정 오류**를 가른다.
   · `access_denied` → 「로그인을 취소하셨습니다」(정상 흐름 · 재시도 안내)
   · 그 외(`redirect_uri_mismatch`·`invalid_client`·`unauthorized_client` 등) → 「연동 설정 문제 — 관리자 확인 필요」 + **원문 코드 노출**(진단 가능성)
3. **진단 스크립트 신규** `scripts/check_social_login.sh` — 3사 `login-url` + `authorize` 를 실제로 태워 **어디서 깨지는지** 판정한다.

**회귀가 아닌 근거**: 기존 성공 경로(`code` 존재)는 **분기 앞에서 그대로** 흐른다. `error` 가 없으면 동작이 **바이트 단위로 동일**하다. 세 파일에 **같은 형태**로 적용한다(§29 형제 누락 방지).

## 3. ★검증하지 못한 것

- ★**공급자 콘솔 등록은 내 권한 밖**이다(사유 = **권한 부족**). Google Cloud Console·네이버 개발자센터는 소유자 계정이 필요하다. **그래서 이 PR 은 「고쳐서 되게 하는」 것이 아니라 「왜 안 되는지 말하게 하는」 것**이다. 이 구분을 숨기지 않는다.
- **실제 OAuth 왕복 미검증** — 완주하려면 각 사 실계정 동의가 필요하고, 그건 사용자 몫이다(사유 = **권한 부족**). 대신 **`error` 파라미터를 붙인 콜백 URL 을 직접 열어** 고지 문구를 확인한다.
- **`disp_stat=207` 의 정확한 의미 미측정**(사유 = **장치 부재** — 네이버 공식 코드표를 조회할 수단이 없다). 「오류 페이지로 보낸다」까지만 관측이고 그 원인은 추론이다. **반증조건**: 콘솔에 Callback URL 을 등록한 뒤에도 같은 코드가 나오면 다른 원인이다.
- 로케일별 콜백(`/en/`·`/zh-CN/`) 등록 필요 여부 **미측정**.
