## 1. ★배치 잡 오염 — 보고값이 최대 **2.8배**

| 항목 | 내용 |
|---|---|
| **증상** | `batch_item_result` 에 같은 `(job_id, pnu)` 가 여러 행 → `counts.total`·`items` 둘 다 부풀었다 |
| **규모** | 잡 **9건 / 25건(36%)** · 최악 `cf5f8651` 2,800 → 실제 고유 **1,000** |
| **돈 축** | `batch_service.py:275` 가 `counts.confirmed` 를 단가에 곱한다 → **견적도 2.8배** |
| **청구 여부** | ★**표시 전용이다**(실측 · 아래 세 축) |
| **★쿼터 축** | 중복 행만큼 VWorld 호출이 중복됐다 — **요금은 아니고 쿼터** |
| **소유** | 동료 세션 `8f` — PR `#952`(읽는 이음매에서 접기 + `counts` 재계산) |
| ★**비가역** | 접힌 레코드가 저장되면 **DB 중복 행이 영구 삭제**된다(`save()` 가 job_id 행을 DELETE 후 재삽입). **코드 revert 로 못 되돌린다** |
| ★**백업** | 배포 전 스냅샷 — 아래 §7 |
| **남는 것** | ★**이미 화면에 틀린 금액이 보였다.** 청구는 아니지만 **의사결정 입력**이었을 수 있다 |

**재측정** (읽기 전용 · 컨테이너 안에서):

```python
# app.core.database 의 세션 팩토리 이름은 AsyncSessionLocal 이다(async_session_maker 아님)
SELECT j.id, j.state, (j.counts->>'total') AS ct,
       COUNT(i.id) AS rows, COUNT(DISTINCT i.pnu) AS uniq
FROM parcel_batch_job j JOIN batch_item_result i ON i.job_id=j.id
GROUP BY j.id, j.state, j.counts
HAVING COUNT(i.id) > COUNT(DISTINCT i.pnu)
-- ★대조군: SELECT COUNT(*) FROM parcel_batch_job   (0이면 조회기 사망)
```

### ★「청구되나」를 **세 축**으로 갈랐다 (한 축만으로는 부족했다)

처음엔 두 축만 봤다 — «billing 이 배치를 읽나» · «배치가 과금 함수를 부르나». 그런데
**진짜 질문은 「견적 필드가 청구되나」가 아니라 「배치가 확정 필지수만큼 차감하나」** 다.
견적 필드가 표시 전용이어도 **다른 이름으로** 차감하면 중복 행 = 실제 돈이다.

    ★대조군(조회기 생존)
      ① 서비스 전반의 차감 낱말        74
      ② 유료 등기 발급 낱말             10
      ③ ★음성 대조군                     0

    ★본 판정
      ④ 배치가 차감 함수를 부르는가     **0**
      ⑤ 배치가 유료 등기를 타는가       **0**
      ⑥ 배치의 실제 외부 호출(파생)      `vw.get_land_characteristics` ·
                                        `vw.get_land_use_districts` ·
                                        `vw.get_parcel_by_pnu` ·
                                        `vw.merge_parcels_gis_union`  = **무료 VWorld 4종**

★⑥은 **이름을 지어내지 않고 소스에서 파생**했다(`grep -ohE '\b(vw|self\._…)\.[a-z_]+\('`).
동료가 처음에 `await self._vworld\.` 로 찾았다가 **빈 출력**을 얻었는데, 실제 코드는 `vw.…` 였다 —
**대조군이 비어서 즉시 「패턴이 틀렸다」로 읽혔다.**

★**「돈이 안 나갔다」와 「틀린 수를 안 보여 줬다」는 다르다.** `cf5f8651` 을 연 사람은
**2.8배 견적**을 봤고 그건 **의사결정 입력**이었을 수 있다.

★**「막혔다」를 질문의 속성으로 착각하지 마라.** 이 항목은 처음에 *"미측정 — 프로덕션 권한 필요"*
로 라벨링됐는데 **소스로 답이 났다.** 권한이 막히면 **그 질문이 정말 그 권한을 필요로 하는지**
부터 다시 본다(동료 자기정정 · 같은 라벨을 붙인 §6 의 빈 PNU 항목은 **실제로** 권한이 필요하다).

★**「counts ≠ 행수」로 세면 안 된다** — 오염된 잡은 **counts 도 함께 부풀어 「일치」**한다.
9건 중 **8건이 그 조건에 안 걸렸다**. 옳은 축은 **중복 `(job_id, pnu)`** 다.

## 2. 큐 슬롯 예약 장치 부재 — **다주체 기아**

`strict` 보호 + auto-merge 에서 **각자 「한 번에 하나」를 지켜도** 서로의 CI 창이
상대의 머지로 무효화된다. 실측: 두 주체가 규율을 지켰는데 **3회 러닝머신**.

★**기아는 값과 무관하다** — 델타 18(`#908` 결제)도 델타 0(`#946` 도구)도 똑같이 굶었다.
★현재 유일한 조정 기제는 **「상대가 알아채고 말을 거는 것」**. 보드 `claim` 은
**영역**을 잡지 **큐 슬롯**을 안 잡는다.

**처방 후보(전부 미검증)**: 보드에 큐 슬롯 claim 추가 · 밀기 전 보드 조회 강제 · 배포 레인 단일화

### ★일반화 — 「되돌리기 경로」 칸은 revert 로 못 채운다

계획 게이트 §4 가 **되돌리기 경로**를 요구하는데, 비가역 데이터 변경에서는
*"revert 하면 이전 동작으로 복귀"* 가 **거짓**이다. **그 칸은 코드가 아니라 데이터로 채워야 한다.**

★그리고 **백업 매체가 세션보다 오래 살아야 한다** — 전역 지침의
*"공유는 세션보다 오래 사는 매체에 한다"* 가 **백업에도 적용**된다.
★**파일만 두는 것으로 부족하다** — 경로와 체크섬을 **문서에** 박아야 다음 사람이 찾는다.
