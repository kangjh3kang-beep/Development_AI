## 2. 변경 내용

`constr_block` 에 `direct_won` + `indirect{items, ratios, base_won}` 를 **additive** 로 싣고,
원장이 공사비를 **직접 1행 + 간접 4행**으로 분해한다. 각 간접 행은
`직접공사비 × 요율 = 금액` 을 **재현**한다.

### 회귀가 아닌 근거

- **합계 불변**(전제 ⓓ). 검산 `cost_total` 이 그것을 확인한다.
- 분해가 **안 오면 종전대로 한 행**(구버전 응답·강등) — 두 모집단 락으로 확인.
- `constr_block` 키 **추가만**. 기존 소비처는 `total_won`·`unit_per_sqm_won` 만 읽는다.
- ★**전제 ⓔ 의 결함이 이 변경으로 해소된다** — 분해 후 직접 행은 직접단가×연면적으로 **정확히 맞는다**.

## 3. ★검증하지 못한 것

1. **라이브 종단** — 배포 후 확인.
2. `general_expense`(일반관리비)가 09_LEGACY 의 「일반사업비」와 **같은 개념인지** 미확인 —
   이름만 비슷할 수 있다. 라벨은 **엔진 개념 그대로**(`일반관리비`) 두었다.
3. 간접비 4항목 외에 **엔진이 새 항목을 추가하면** 라벨표에 없어 **키 이름 그대로** 나간다
   (버리지는 않는다 — 락으로 확인).
4. 이 분해가 **09_LEGACY 의 간접공사비 6행**(설계·감리·인입·예술장식·철거·기타용역)과
   **1:1이 아니다** — 우리는 4행이고 인입·예술장식·철거는 **여전히 없다**.

## 4. 되돌리기 경로

`constr_block` 의 추가 키 2개 제거 + 원장 분기 제거. 2파일.

## 5. 잠금

| 축 | 검사 |
|---|---|
| 분해 | 직접 1 + 간접 4행 · **실무 양식 이름**으로(엔진 키가 화면에 나가지 않게) |
| **합계 불변** | 소계 == 엔진 총액 · 검산 `cost_total` = OK. ★**없으면 이중계상도 초록** |
| 재현 | 간접 각 행이 `직접공사비 × 요율 = 금액` |
| **두 모집단** | 분해 있음 5행 / 없음 1행 · **합계는 둘 다 같다** |
| 미지 항목 | 라벨표에 없는 키도 **버리지 않는다** |
