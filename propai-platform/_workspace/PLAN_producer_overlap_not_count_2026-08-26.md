## 2. 변경 내용과 그것이 회귀가 아닌 근거

- **판정을 셸에서 프로브(파이썬)로 옮긴다** — `is_stale_stack(spans)` 순수 함수.
  잔재의 정의는 *"옛 빌드가 새 빌드와 **동시에** 쓴다"* 이므로 **구간 겹침**으로 판정한다.
  (저장소 규율: *"수집은 파생형으로, 판정은 파서로"*)
- 프로브가 `min/max(created_at)` 을 함께 조회하고 `overlap=` 필드를 출력한다.
- 계기판은 `overlap` 만 읽는다. `NB` 는 **표시용**으로만 남긴다.
- **회귀가 아닌 근거**: 종전 판정이 참이 되는 유일한 경우(표식 2종 이상)는 새 판정에서
  *겹칠 때만* 참이 된다. 즉 **진짜 잔재는 여전히 잡히고**(변이 ②로 확인),
  순차 승계만 통과한다(실측 데이터로 확인).

## 3. ★검증하지 못한 것

- **실제 잔재 스택이 발생한 라이브 상황에서 겹침이 관측되는지는 미측정**이다.
  오늘 라이브에는 잔재가 없어서(교차 0건) **양성 사례를 실측할 수 없었다.**
  픽스처로만 확인했다 — `test_동시_기록은_잔재다`.
- `OVERLAP_WINDOW_SEC = 60` 이 **적정한지 미측정**. 블루-그린 전환이 초 단위라는
  관측(오늘 배포 로그)에 근거한 추정이며, 전환이 1분 넘게 걸리는 경우 위양성이 날 수 있다.
  → 상수로 노출하고 테스트가 경계 양쪽을 태운다(`test_경계_창이_상수로_노출된다`).
- 프로브가 컨테이너 안에서 **새 필드를 실제로 출력하는지는 배포 후에만** 확인 가능하다.
  그래서 필드가 없으면 `DEAD=1`(판정 불가)로 시끄럽게 실패시킨다 — 0 으로 읽지 않는다.

## 4. 되돌리기 경로

`git revert <이 PR 머지커밋>`. 계기판·프로브는 **읽기 전용 도구**이고 런타임 코드가
아니므로 되돌려도 서비스 영향 0. 되돌리면 상시 exit 2 상태로 복귀한다.
