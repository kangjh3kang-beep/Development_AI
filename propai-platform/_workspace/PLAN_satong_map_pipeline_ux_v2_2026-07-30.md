## 1. 근본 진단 — 필터 튜닝이 아니라 **조회 축의 부재**

코드 실측:
- `nearby_map_service.py` = **반경 기반(radius_m=1000) 주변 거래 수집기**. 거래를 모아 지오코딩하고 반경으로 자른다.
- `_MAX_GEOCODE_GROUPS_PER_CAT = 80` → 초과분 사전컷(93건)
- 지오코딩 실패분 제외(29건) · 반경 밖 제외(326건)
- **`PNU로 이 필지의 거래 이력을 직접 조회하는 경로가 없다`** (grep 확인)

즉 임야·대규모 필지처럼 "주변에 아파트 거래만 있는" 지역에서는 **구조적으로 0건**이 나온다. 필터를 완화해도 축이 없으면 이 필지의 4.81억 거래는 영원히 안 나온다.

`getRTMSDataSvcLandTrade`는 **이미 호출하고 있다** — 수집은 되는데 소비 축이 반경뿐이라 버려진다.

## 2. 파이프라인 재정립 — 3축 분리

현재는 "주변축" 하나가 모든 걸 떠맡는다. 축을 분리한다.

```
① 필지축 (PNU 직결·무손실)        ← 신설. 지금 비어 있는 축
   PNU → 거래이력 · 공시지가 시계열 · 추정가 · 규제 · 소유/권리
   지오코딩 불필요(필지 좌표를 이미 안다) → 사전컷·좌표미확보 손실 0

② 주변축 (반경·통계)               ← 기존. 역할을 좁힌다
   반경 내 비교사례 → 분포·중앙값·comparable 선별
   "이 필지 값"이 아니라 "이 필지를 평가할 근거"로만 쓴다

③ 레이어축 (WMS/타일)              ← 기존. 실패 격리
   지적·용도지역·규제·노후도·개발여력
   실패는 해당 레이어 배지에만 표기(지도 위 전역 오류 문구 금지)
```

**핵심 규칙**: ①이 답을 만들고 ②가 근거를 대고 ③이 배경을 그린다. 지금은 ②가 ①의 역할을 대신하려다 실패하고 있다.

### 데이터 가용성 실측(그린필드 아님)
| 필요 | 보유 |
|---|---|
| 토지 실거래 | ✅ `getRTMSDataSvcLandTrade` 이미 호출 |
| 추정가 | ✅ `desk_appraisal_service` · `land_price_estimator` |
| 공시지가 시점수정 | ✅ `land_price_index.time_adjust_factor` |
| 규제 | ✅ 50+ 파일 · WMS 5종 |
| 학교·교통 POI | ✅ `site_score` POI(이번 세션 dedup 봉합분) |
| 대지경계·건축선 도해 | ⚠️ 경계 폴리곤은 있음 · 건축선 도해는 미보유 |

## 3. 인터페이스 리팩토링 — 참고 화면의 좋은 점을 우리 구조에 이식

### 3-1. 좌측 = 필지 상세 패널(신설·최대 효과)
현재 좌측은 "통합 필지 입력"만. 필지를 고르면 그 자리에 **상세 패널**로 전환한다(입력은 접기).

```
[호미곶면 대보리 산1-1]           경북 포항시
보전관리 · 임야 · 44,491평 · 건물없음 · 개인

추정가 (토지)
  약 19.4억원          ← 큰 숫자 1개(경쟁사 패턴)
  평당 4.35만원
  [실거래가 · 개별공시지가 · 추정가 3계열 시계열 차트]
  ★방법론 배지 유지(우리 정직성 자산 — 경쟁사엔 없다)

최근 실거래                        ← ①필지축 산출
  토지  19.07.29  4.81억  44,500평
  토지  14.11.19  4.45억  44,500평
  [주변 유사 거래 보기 →]          ← ②주변축으로 연결

탭: 토지 | 규제 | 입지 | 개발
  규제 = 우리가 이미 강한 영역(중첩규제·군사·보호구역)
  개발 = 우리만의 축(실효FAR·개발여력·산출물)
```

### 3-2. 레이어 선택 = 썸네일 미리보기
현재 아이콘+2글자 → **작은 지도 썸네일 칩**으로. "무엇이 보일지"를 눌러보기 전에 안다.
- 이미 `SWATCH_TILE_BASE`/`SWATCH_TILE_ZYX`로 **베이스맵 스와치를 만들고 있다** → 같은 방식을 레이어에 확장(그린필드 아님)
- 12개 전부는 과하다 → 자주 쓰는 4~6개만 썸네일, 나머지는 현행 캡션 유지

### 3-3. 지도 위 = 값을 보여주는 마커
- 실거래 마커에 **가격 라벨**(현재는 점) + **총액/평당 토글**
- 개발여력 색상 범례는 유지(우리 강점)

### 3-4. 오류 표기 = 지도 밖으로
현재 "규제 오버레이 타일 조회 실패 — 지적 배지의 자가진단으로 원인 확인"이 지도 위에 상시.
→ 해당 **레이어 칩에 점 배지**로 축소, 상세는 클릭 시. (이번 세션 타일 판정 비율화와 같은 원칙: 부분 실패로 전역 경보 금지)

## 4. 워크플로우 — 사용자 여정 기준

```
검색/엑셀 → 필지 선택 → [필지축 즉시 채움: 추정가·거래이력·규제]
                          ↓
                    레이어로 맥락 확인(썸네일로 선택)
                          ↓
                    주변축으로 근거 확인(비교사례)
                          ↓
                    OUTPUT DOCK 산출물(우리만의 종착점)
```
현재는 2번째 칸이 비어 있어 "지도는 예쁜데 이 필지를 모르겠다"가 된다.

## 5. 단계 (각 단계 독립 배포 가능)

| 단계 | 내용 | 근거·위험 |
|---|---|---|
| **W1** | **필지축 신설** — PNU 거래이력 API + 상세 패널에 거래 테이블 | 데이터 보유·지오코딩 불필요. **최대 효과** |
| **W2** | 추정가 카드 + 3계열 차트(방법론 배지 유지) | `desk_appraisal`·`land_price_index` 재사용 |
| **W3** | 좌측 상세 패널 탭 구조(토지/규제/입지/개발) | 데이터 전부 보유 · UI 재배치 |
| **W4** | 레이어 썸네일(4~6개) | 베이스맵 스와치 패턴 확장 |
| **W5** | 마커 가격 라벨 + 총액/평당 토글 | 실거래 다중표시(#470) 위에 얹음 |
| **W6** | 오류 표기 레이어 배지로 격리 | 타일 비율판정(#499)과 동일 원칙 |

**권장 착수: W1** — 사용자가 본 "실거래 무자료"를 직접 해소하고, 이후 모든 단계의 데이터 기반이 된다.

## 6. 하지 않을 것 (정직 경계)

- **jootek 화면 복제 금지.** 우리 축(개발여력·실효FAR·다필지·산출물)이 상대에 없고, 그게 제품 정체성이다. 좋은 패턴만 이식한다.
- **방법론 배지 제거 금지.** 경쟁사는 추정가만 크게 보여주고 근거를 안 밝힌다. 우리 정직성 표기는 유지가 아니라 **차별점**이다.
- **건축선 도해**는 데이터 미보유 — 만들려면 별도 조사. 이번 범위 밖.

---

## 7. 미해결·확인 필요

- jootek의 "추정가 19.4억"과 우리 추정치의 **차이 원인**은 미확인. W2 착수 시 같은 필지로 대조해 우리 방법론의 편향을 실측할 것(경쟁사 값이 정답이라는 전제는 두지 않는다).
- 실거래 2건이 **이 필지 자체 거래인지 인접 필지 거래인지** 화면만으로는 단정 불가(44,500평 = 우리 44,491평과 근사 → 동일 필지 가능성 높음). W1에서 PNU 조회로 확증.
