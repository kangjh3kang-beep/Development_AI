## §1 전제 표 — **전부 실측**

| # | 전제 | 확인 방법 | 결과 |
|---|---|---|---|
| 1 | 백엔드가 층수·구조를 **받는가** | `construction_cost_engine.py` 원문 | ✔ `floor_count_above/below`·`structure_type`·`unit_cost_per_sqm`·`cost_index_factor` **전부 실재** |
| 2 | 프론트가 그것을 **보내는가** | `store/use-feasibility-v2-store.ts` 원문 | ✘ **`params: {}`** 로 초기화되고 `construction_cost_override_won` 외 **아무것도 안 채움** |
| 3 | 입력 인터페이스에 `floors` 가 있나 | 같은 파일 18~32행 | ✘ **없음** |
| 4 | 수지 입력폼이 공사비 축을 주나 | `ModuleInputForm.tsx` `NumberInput` 전수 | ✘ **14개 중 0개**(대지면적·연면적·세대수·평당분양가·평균전용·분양률·공시지가·시가배율·브릿지·본PF·중도금·사업기간·할인율·자기자본) |
| 5 | 그래서 프로덕션은 무엇을 쓰나 | 백엔드 독스트링 + 2·3·4 | **항상 폴백** `연면적 × ₩/㎡` |
| 6 | **효과 크기** | 순수 계산 실측(연면적 2만㎡·아파트·200세대) | 지하3층 **+7.4%** · SRC **+23.5%** · 철골 **+18.1%** |
| 7 | 지상 층수의 판별력 | 반증 시도(3조건 × 5값) | ★**조건부** — 지하 0층이면 **판별력 0**, 지하 있으면 유효하고 **고층일수록 감소**(연면적 고정 → 바닥면적↓ → 굴착↓). **물리적으로 타당 · 결함 아님** |
| 8 | 기본 단가 | `_resolve_direct_unit_cost("apartment")` | **2,400,000 원/㎡** = 평당 **7,933,920 원** |

★**7 은 제 첫 판정을 뒤집은 것**이다. 처음엔 «지상 층수 판별력 0 = 결함» 으로 봤는데,
반증 조건(지하층 고정)을 걸자 **5개 서로 다른 값**이 나왔다. **없는 결함을 신고할 뻔했다.**

## §2 변경 내용

**신설이 아니라 배선이다.** 산출식은 이미 있고 **호출되지 않을 뿐**이다(생산 0 = 소비처 0 의 거울상).

1. FE 입력 인터페이스에 `floors_above`·`floors_below`·`structure_type`·`unit_cost_per_pyeong` 추가
2. 스토어가 그것을 `params` 로 직렬화 — **평당 → ㎡ 변환은 한 곳에서**
3. `ModuleInputForm` 에 입력칸 4개(+ 총공사비 직접입력 1개)

### ★단위 위험 (이 PR 이 반드시 지켜야 할 것)

사용자 어휘는 **평당공사비**, 백엔드 계약은 **`unit_cost_per_sqm`**. 배수 **3.3058**.
평당값을 `sqm` 칸에 그대로 넣으면 **3.3배 과대**다.
★**`#980` 이 고친 것이 정확히 이 클래스**(단위 다른 두 수의 블렌딩)다 — 같은 캠페인 안에서 재발시키지 않는다.
→ 변환은 **한 함수**에서만 하고, **두 모집단**(평당 입력 ↔ 미입력 폴백)으로 잠근다.

## §3 ★검증하지 못한 것

- **회귀 방향**: params 를 채우면 기존 프로젝트 재계산 값이 **바뀐다**(지금은 폴백). 사용자에겐 «갑자기 숫자가 달라짐»으로 보인다 — **미측정**(장치 부재: 기존 프로젝트 재계산 이력을 볼 계기가 없다)
- 구조유형 표기 집합(`RC`/`SRC`/`철골` 외 무엇을 받는지) — **미측정**
- 라이브에서 실제로 몇 %의 프로젝트가 지하층을 갖는지 — **미측정**

## §4 되돌리기

입력을 비우면 `params` 가 비고 **종전 폴백 그대로**(백엔드가 이미 그렇게 설계됨). 무회귀 경로 실재.

## §5 잠금

1. **호출부 파생형 계수** — §0 이 기록한 «3곳 중 2곳» 누수의 재발 방지
2. **단위 변환이 한 곳뿐** — 평당↔㎡ 변환 리터럴이 여러 모듈에 있으면 실패
3. **두 모집단** — 평당 입력 시 값이 바뀌고, 미입력 시 폴백과 **바이트 동일**
4. **배선 락** — 스토어가 `params` 에 실제로 싣는지(이름이 아니라 **값**)
5. **지상층수 조건부 유효성** — 지하 0층에서 판별력 0인 것이 **의도**임을 명시(변이로 «항상 무효»와 구별)
