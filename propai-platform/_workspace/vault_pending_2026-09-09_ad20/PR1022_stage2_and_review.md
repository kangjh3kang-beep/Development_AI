# Stage 2 — 현장 발견 → 신청 → 승인 (PR #1022)

사용자 요구: *"모든 회원은 … 등록된 모든 분양현장을 확인하고 등록신청을 하고
관리자 및 상위레벨이 승인할경우 … 접속가능하도록"*. 이 PR 은 **발견·신청·승인**까지다.

## 1. 측정이 설계를 두 번 바꿨다

| 처음 생각 | 실측 | 바뀐 것 |
|---|---|---|
| «모든 현장을 보는 경로가 없다» | `site_auth.my_sites` 분기 (c) 가 **superadmin 에게 전체를 준다**. 라이브 `/sales/sites` **13** · `/sales/my-sites` **14** ⇒ 총 현장 14, 타 테넌트 1 | 없는 것은 «전체 현장» 이 아니라 **«일반 회원에게 축소 필드로 주는 발견 경로»** |
| «등록신청 경로가 없다» | 어휘 6종 grep 6건 → **원문 확인 전부 위양성**(코루틴 «합류» · WS 룸 «합류»). 대조군 `job_applications` 로 조회기 생존 확인 | 진짜 공백은 **«공고를 대상으로만 신청할 수 있다»**(`apply_post(post_id)`) |

★**목적으로 찾지 않았으면 있는 것을 새로 만들 뻔했다.**
★빈 상태 문구가 막다른 길이었다 — *"관리자가 조직도에 추가하면 표시됩니다"*.

## 3. 처방 — 좌표가 아니라 축

- **A-1** 스텁이 **쿼리를 컴파일해 기록**(`literal_binds=True`) + 조회 종류별 **라우팅**.
  한 스텁이 모든 조회에 같은 답을 주면 «두 모집단» 이 아니라 **한 모집단**이다
  (실측: AGENCY 루트 분기를 태우는 테스트가 **0건**이었는데 아무도 몰랐다).
- **B-1** 축은 문 하나가 아니라 **전이 3건 중 원자적 1건**. 공용 `claim_status_transition`(CAS)로
  뽑아 **두 문 다**. «pending 고정» 이 아니라 **읽은 값 그대로**를 조건에 싣는다 —
  `market` 의 «거절→수락» 재결정을 죽이지 않기 위해. **정답 패턴이 같은 파일 80줄 위에 있었다.**
- **B-3** SSOT 를 **의존 없는 최하위 모듈**(`org/roles.py`)로 내리고 `deps_sales` 는 재수출.
  ★그냥 `deps_sales` 를 임포트했더니 FastAPI 체인이 딸려 와 **테스트가 임포트 단계에서 죽었다**
  — PR #1021 의 `_ORG_RANK` 와 **같은 처방**이 필요했다.
- **B-4** `JoinRequestsPanel`(승인 UI)을 만들어 `org` 탭에. `membership_reason` 을
  **형제 문과 같은 공용 모듈**로 사람 말로 옮긴다.

## 4. ★이번에 새로 배운 것

1. **스텁이 버리는 입력 = 원리적 무잠금 영역.** 변이를 고르기 전에 «내 스텁이 무엇을 버리나» 를
   적어라. 안 적으면 변이는 영원히 **잠긴 층 안에서만** 골라진다.
2. **「고쳤다」 ≠ 「고친 것을 잠갔다」.** B-1 을 고친 직후 변이가 `UNDECIDED` —
   참조한 테스트 파일이 **없었다**(락을 안 만들었다).
3. **판정 불가의 원인이 코드가 아니라 「내 명령」일 수 있다.** 두 번째 `UNDECIDED` 는
   테스트 명령을 **인용부호로 묶어** 한 실행파일 이름이 된 것(rc=127).
   앞선 실행들은 인용 없이 넘겨 통했다 — **같은 세션 안에서 명령 형태가 갈렸다.**
4. **락을 걸면서 바로 옆에서 같은 결함을 만들 수 있다.** 같은 커밋에서 «사유 어휘를 복사하지
   마라» 는 락을 넣고 **역할 SSOT 를 손으로 복사**해 토큰 2개를 떨어뜨렸다.
   락의 축이 «그 상수 하나» 였지 «이 모듈이 SSOT 를 복사하지 않는다» 가 아니었다.
5. **삭제 가드의 범위와 PR 의 base 가 다를 수 있다.** 스택 PR 이라 가드가 `origin/main` 기준
   393줄을 셌는데, 실제 base 기준은 **−17줄**이었다. 전수로 확인하고 사유를 붙여 통과시켰다.

## 6. 미측정 (정직하게)

- **동시성 실증 부재** — B-1 의 경쟁을 **실제 Postgres 로 재현하지 않았다.** SQL 의미론과
  코드 좌표에서 도출했고, 락은 «CAS 조건이 실린다» 까지만 본다.
- **DB 통합 테스트 부재** — 부분 유니크 인덱스·`ON CONFLICT` 의 실제 동작 미측정.
- **`platform_admin`·`총괄관리자` 계정 실재 미확인** — B-3 은 **소스 수준 불일치**로만 확정.
- **라이브 도달성** — 새 라우트를 라이브에 안 태웠다.
- **기계 변이 분모 오염** — 스택 PR 이라 base 가 #1021 변경까지 포함. 머지 후 재실행 필요.
