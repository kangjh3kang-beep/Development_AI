## 2. 변경 내용 — **형태에서 층으로**

    ✘ 종전:  인자열 **전체**에서 문자 `|` 하나  → 두 층(셸 스크립트 / 리터럴 argv)을 섞어 판정
    ◎ 현재:  ① 셸 래퍼가 아니면 → **신뢰**(execvp 직접 실행이라 rc 는 그 명령의 것)
             ② 래퍼면 **`-c` 뒤 스크립트**를 본다
                · 접두 `set -… pipefail;` 를 **걷어내고**
                · 나머지에 `;`·`&&`·`||` → **판정 불가**
                · 나머지에 `|` 이고 pipefail 이 **없으면** → 판정 불가
             ③ 탈출구 `MUTATE_ALLOW_SHELL="사유"`(옛 `MUTATE_ALLOW_PIPE` 도 계속 받는다)

★**같은 `;` 를 위치로 가른다**: `set -o pipefail; cmd | tail` 은 **안전**(설정 분리),
  `cmd; tail` 은 **위험**. 문자 하나로 못 하던 것을 **구조**로 한다.

**회귀가 아닌 근거**: 두 락 루트 **19 passed**(기존 15 + 신규 4). 기존 호출부 위양성 0(P7).

## 3. ★검증하지 못한 것

1. **`eval`·백틱·`$(...)` 안의 명령 연결**은 안 본다. 스크립트 문자열을 **파싱하지 않고 부분문자열**로 보므로, 따옴표 안의 `;`(예: `pytest -k 'a;b'`)는 **위양성**이 될 수 있다 — 실사용 0건이라 그대로 뒀다.
2. **`-c` 를 다른 위치·형태로 주는 호출**(`bash -lc`, `--command=`)은 못 찾는다.
3. **`RC_WHY` 문구가 판정 줄에 실리는지**는 락이 안 본다(사유 없는 판정 금지를 잠그지 않았다).
4. **다른 셸**(`fish`·`pwsh`)은 목록에 없다.
5. 동료의 `#944` 등 **다른 세션의 과거 변이 판정**이 이 결함으로 오염됐는지 **재감사하지 않았다**.

## 7. ★`&&` — 리뷰 지적을 **받되 사유는 반대로 바로잡는다**

리뷰: *"`a && b` 의 rc 는 마지막 실행 명령의 것이라 **실패를 가리지 못한다** → `cd X && pytest` 를
막는 것은 위양성"*.

**앞부분은 맞고 결론은 아니다.** `a && b` 는 어느 쪽이 실패해도 rc≠0 이므로 **거짓 SURVIVED 를
만들지 못한다** — 그러나 **반대 방향**이 열린다:

    cd 없는디렉토리 && pytest   →  rc=1  →  "CAUGHT"   ★테스트는 돌지도 않았다

**거짓 CAUGHT 는 변이 점수를 부풀린다** — 있지도 않은 락이 있다고 믿게 만드는, 위 dash 결함과
**같은 클래스**다. 그래서 **차단을 유지**하고(탈출구 `MUTATE_ALLOW_SHELL` 있음), 대신 종전 주석의
**틀린 근거**(*"rc 는 마지막 명령의 것"*)를 코드에서 바로잡았다.

## 8. ★검증하지 못한 것 — **§3 을 좁히고 넓힌다**(리뷰 지적 반영)

### 8-1. §3-1 서술이 **실제보다 넓었다** (재측정으로 정정)

§3-1 은 *"`eval`·백틱·`$(...)` 안의 명령 연결은 안 본다"* 고 적었으나 **틀렸다** — 실측:

    bash -c 'eval "cmd; true"'    → 12  (잡힌다)
    bash -c 'echo $(cmd; true)'   → 12  (잡힌다)

스크립트 문자열 **안에** `;` 가 있으므로 그대로 잡힌다. 실제로 새는 것은 아래 8-2 **하나**다.

### 8-2. 잔존 구멍 **2건** — 실측 rc=0(거짓 SURVIVED) · `xfail(strict=True)` 로 잠갔다

| 형태 | 실측 | 왜 지금 안 닫나 |
|---|---|---|
| `env T='cmd; true' bash -c 'eval "$T"'` | **0** | 명령이 **환경변수에 실려** 스크립트엔 `eval "$T"` 뿐. 따라가려면 셸 의미론 구현 = **「문자열은 불투명」 설계 선언과 충돌** |
| `./mywrap` (임의 실행파일) | **0** | argv[0] 이 임의 실행파일이면 내부를 볼 수 없다. 닫으려면 접두 래퍼 **손 목록**을 넓혀야 하는데 **목록이 곧 상한**이 된다 |

★둘 다 `xfail(strict=True)` 이라 **누가 닫으면 XPASS 로 빨개진다**(래칫). 커밋 메시지에만
적으면 안 드러나므로 **초록 안에** 뒀다.

### 8-3. 여전히 미측정

- `zsh`/`ksh` 에서의 실제 동작(이 호스트에 없다). **`bash`/`sh` 만 실행으로 확인**했다.
- `MUTATE_ALLOW_SHELL` 사유 **문구**는 잠그지 않았다(산문 락 금지 — §G-30). 사유가 **출력에
  남는지**만 잠갔다.

| 리뷰 지적분 | 11 | 전부 `0` → **`12`** |
| 종전 형태(회귀 방지) | 8 | **`12` 유지** |
| ★정당한 형태(위양성 축) | 8 | **`1 CAUGHT` 유지** |
| 잔존(부채) | 1 | `./mywrap` 임의 실행파일 — `xfail(strict=True)` |

### ★변이 P2 가 **SURVIVED** 했고, 그것이 설계를 고쳤다

「롱옵션이면 판정 불가」를 지웠는데 **아무 락도 안 빨개졌다.** 설명 가능한 생존이 아니라
**내 설계가 과잉**이었다 — `--norc` 자체는 rc 를 바꾸지 않으므로 막으면 **위양성**이다.
C1 을 실제로 고친 것은 **`--*` 를 `-*c*` 앞에서 보는 순서**였다.
→ 차단을 걷어내고 **양방향으로** 잠갔다(`--norc -c 'cmd|cat'` → 12 · `--norc -c '단일'` → CAUGHT).
순서를 뒤집는 변이 P2b 는 **CAUGHT**.

### ★내가 적은 「닫을 수 없다」가 틀렸다

`xfail#1`(환경변수에 실린 명령)의 사유를 *"닫으려면 설계를 바꿔야 한다"* 라고 적었다.
**설계를 바꾸니 닫혔다.** `eval "$T"` 에 `$` 가 남으므로 화이트리스트가 그냥 막는다.
**「닫을 수 없다」도 측정 대상이다**(CLAUDE.md §D-14 「미룸의 근거를 실측하라」의 형제).

`xfail#2` 는 유지하되 **모집단을 바로잡았다** — `./mywrap` 뿐 아니라
`sudo`·`xargs`·`make`·`npx`·`poetry run`·`uv run`·`python -m` 이 전부 그 구멍에 있고 훨씬 흔하다.

### 함께 닫은 리뷰 항목

- **M2** `timeout` 은 셸을 끼워도 신뢰하지 않는다(시간초과 rc 124 = **거짓 CAUGHT**).
  `&&` 를 막은 것과 **같은 자**인데 종전엔 한쪽에만 댔다.
- **M1** 접두 `set …` 스트립이 **주석·명령치환이 든 절은 걷지 않는다**(걷으면 위음성).
- **M4** 셸 목록을 **호스트에 실재하는 셸에서 파생** — zsh/ksh 가 설치되면 그날부터 감시망에.
  (종전엔 `bash` 외 3개가 무잠금이었다.)
- **M5** `exit 12`(판정 불가)를 **CLAUDE.md 에 선언**하고 계약 테스트가 그것을 요구한다.
  비영 종료라 **"CAUGHT" 로 오독되기 가장 쉬운 코드**인데 문서에 없었다.
- **L1** 빈 스크립트 · **L2** §6 표 한 칸(1 → 2) · **L3** `-o pipefail` 명령줄 형태.

### 아직 안 고친 것 (실측 후 남긴 것)

- **M3 `2>&1` 위양성.** 화이트리스트가 `>` 와 `&` 를 막으므로 리다이렉션도 걸린다.
  **의도한 값**이다(따옴표·리다이렉션을 파싱하지 않겠다는 선언). 다만 리뷰 지적대로
  **탈출구가 전부 아니면 전무**라, `2>&1` 때문에 켠 플래그가 진짜 결함도 통과시킨다.
  **축별 탈출구**(예: `MUTATE_ALLOW_SHELL=redirect`)는 **미구현 — 부채**.
- **`zsh`/`ksh` 실동작 미측정** — 호스트에 없다. 파생형 락이 설치되면 자동으로 태운다.

## 12. ★3차 적대 리뷰 — **기저율이 유지됐다(3/3)** · 역전을 **한 층에만** 걸었다

### 무엇을 놓쳤나

화이트리스트 역전을 **`-c` 스크립트 문자열 층에만** 걸었다. **그 위 argv 층은 여전히
열거형이고 기본값이 「신뢰」** 였다. 리뷰가 찾은 6형태 중 **4개는 화이트리스트에 도달조차
하지 않았다.**

> §10 에 쓴 *"새 형태가 나와도 표에 없어도 자동으로 막힌다"* 는 **화이트리스트에 대해서만
> 참**이고 **도구에 대해서는 거짓**이었다. 「목록이 곧 상한」이 사라진 게 아니라
> **한 층 위로 옮겨갔을 뿐**이다.

★자문: ***"내가 역전을 적용한 범위가, 결함이 사는 범위와 같은가?"***(CLAUDE.md §D-20)

### 실측 (전부 `0` → **`12`**)

| 형태 | 왜 샜나 |
|---|---|
| `bash -- runner.sh` | `--` 를 **`-c` 표지로** 받아 **파일명**을 스크립트 문자열로 검사했다. 파일명엔 메타문자가 없어 통과 |
| `rbash -c 'a; true'` | 셸 목록이 **손 목록** — `rbash`(→bash 심링크)가 셸로 인식 안 돼 **직접 명령으로 신뢰** |
| `script -qc … /dev/null` | `script` 는 `-e` 없이 **자식 rc 를 버리고 0** 을 낸다. `timeout` 만 보고 있었다 |
| `flock <lock> bash -c …` | 경합 시 1 — 같은 자리 |
| `bash +o pipefail -c '\|'` | **`+o` 는 끄는 것**인데 켜는 것으로 셌다(부호를 안 봄) |
| `set -e pipefailZZ; …` | **부분문자열** 매칭. 주석 110행이 *"단어 경계 없음"* 을 **해소된 과거형**으로 적어 뒀는데 살아 있었다 |
| `set -e \| grep …; true` | **스트립 가드(4종)가 화이트리스트(12종)보다 약해** 위험이 스트립으로 사라졌다 |
| `bash -c $'\t'` | 빈 스크립트 검사가 **리터럴 하나만** 잠갔다 |

### ★내가 문서를 고치면서 만든 결함

`CLAUDE.md` 에 *"`exit 12` 를 실패로 읽지 마라"* 를 쓴 순간, **테스트가 진짜로 rc=12 를 내면**
stdout 은 `CAUGHT` 인데 종료코드가 「판정 불가」와 같아졌다 — 종료코드만 읽는 호출자가
**진짜 CAUGHT 를 판정 불가로 오독**한다. **충돌하는 값만** 1 로 옮겼다.

### 처방 — argv 층도 **열거를 줄였다**

- **셸 판정을 파생**시킨다: 이름 · **심링크를 따라간 실체** · 시스템 자신의 목록 `/etc/shells`
- rc 파괴 래퍼를 **측정된 만큼** 확장(`timeout` `script` `flock` `xargs` `retry`)
- `--` 는 `-c` 를 본 적 없으면 **스크립트 파일**
- `-o`/`+o` 는 **부호**를, `pipefail` 은 **낱말**로 판정
- 스트립 가드를 **화이트리스트와 같은 집합**으로

### ★그래도 argv 층은 **완전히 닫히지 않는다** — 그렇게 적었다

임의 실행파일(`./mywrap`·`sudo`·`npx`·`poetry run`)의 rc 의미론은 알 수 없다.
그 층은 **「모르면 신뢰」가 기본**이고, 그것을 `CLAUDE.md` 와 `xfail(strict=True)` 에
**명시**했다. ★리뷰가 정확히 지적했듯 **처방 방향이 반대였다** — 상한이 되는 것은
**블랙리스트**이고, 여기 필요한 것은 화이트리스트다. 다만 argv 층의 화이트리스트는
「알려진 안전한 프로그램 목록」이 되어 **정상 사용(pytest·grep)을 전부 막으므로** 채택하지
않았다. **그 선택과 대가를 적어 둔다.**

### 함께 닫은 것 — 리뷰가 준 **파생 축 교정**

`_설치된_비bash_셸` 이 `("sh","dash","zsh","ksh")` **튜플과 교집합**이라 **`rbash` 를 영원히
못 태웠다**. 파생의 축이 한 단계 위에 있었다 — 후보를 넓히고 **실재하는 것만** 태운다.

### 수치를 손으로 세지 않는다

§10 의 *"28개 축"* 이 파일과 갈렸다(실제 27). 이제 **판정 대상 36개**이고,
`test_판정_대상_수는_손으로_세지_않는다` 가 **파일에서 파생시켜 이 문서와 대조**한다 —
목록이 늘면 이 문서도 같이 빨개진다.
