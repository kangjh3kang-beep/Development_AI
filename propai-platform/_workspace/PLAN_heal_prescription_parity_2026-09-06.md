## 2. 변경 내용과 그것이 회귀가 아닌 근거

**핵심: 동작을 바꾸지 않는다. 「하지 않기로 한 것」을 선언하고 기계로 잠근다.**

1. `healing_rules.py` 에 **면제 표**를 신설:
   ```python
   HEAL_UNHANDLED_REASONS: dict[str, str] = {
       "latency_regression": "★부채 — 자동 임계조정은 프로덕션 HTTP 타임아웃을 곱한다(…)…",
   }
   ```
   ★**사유를 적는다**(§36). 부채는 `★부채` 로 표시해 초록 안에서 보이게 둔다.
2. **AST 파생 락** 신설 — 분석기가 `recommended_action='heal'` 로 발행하는 타입을 코드에서 **파생**해,
   각각이 `HANDLED_INSIGHT_TYPES` **또는** `HEAL_UNHANDLED_REASONS` 에 있어야 함을 단언.
   **죽은 면제**(더 이상 heal 을 안 내는 타입이 면제표에 남아 있음)도 **실패**시킨다.
3. **공허 진리 가드**: 파생한 타입 수가 하한 미만이면 **판정 불가로 실패**(파서가 모집단을 자르면
   «위반 0» 이 조용히 참이 된다 — 오늘 두 세션이 이 클래스로 데였다).

**회귀가 아닌 근거**: 런타임 분기·임계·쿼리를 **한 줄도 바꾸지 않는다.** 추가되는 것은
모듈 상수 하나와 테스트 파일 하나다. 라이브 응답 불변(큐 우선순위 2군).

## 3. ★검증하지 못한 것

- **`latency_regression` 에 실제 치유를 붙이는 것이 옳은지** — 미측정. 이 계획은 **판정만** 만들고
  처방은 만들지 않는다. 임계 자동조정은 볼트 기록상 **기각된 길**이다.
- **#996 의 `executed` 가 라이브에서 옳게 실리는지** — ★**측정 불가(사건 미발생)**.
  `payload ? 'executed'` 행 **0/524**이고, #996 배포(132주기 01:37Z) 이후 `heal_action` 이 **0건**이다.
  ⇒ **배포됐지만 한 번도 실행되지 않았다.** 「null 비율 감소」로 확증하려는 계획은 **분모가 안 늘어서
  원리적으로 불가** — 다음 `fallback_rate` 발화를 기다려야 한다.
- **`llm_usage_log` 가 08-25 이후 0행**인데 `llm_call` 이벤트는 09-05까지 있었다 — 두 계측이
  **12일 갈렸다**. 어느 쪽이 정본인지 **미측정**(별건).
- **`api_call` 이 30만 행 넘게 쌓이는데 `service` 열이 전부 NULL** — `route` 는 정상. 별건, 미측정.
