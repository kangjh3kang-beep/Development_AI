## 3. 설계 — 쿼터가 구조를 정한다

**필지 397개를 필지마다 조회하면 쿼터가 죽는다.** 그래서:

1. **PNU 에서 `lawd_cd = pnu[:5]` 를 파생**하고 **(lawd_cd, 월) 단위로 접는다.**
   77필지 프로젝트라도 시군구가 1개면 **월당 1회**다.
2. 응답 행을 **지번으로 필지에 되매핑**한다 — PNU 는 `법정동(10)+대장(1)+본번(4)+부번(4)` 이므로
   **지번을 정확히 계산**할 수 있다(순수 함수).
3. 조회 실패(429/403/빈응답)를 **"거래 0건"으로 저장하지 않는다** — `#832` **보류값 계약**으로
   `transactions=None` + `transactions_absent` 코드를 싣는다(무언 보류 금지).

## 5. ★검증하지 못한 것 (정직)

- **`landSchedule` 는 프론트 블롭이다.** 백엔드가 그것을 읽는 통로가 있는지 **미측정** —
  없으면 **프론트가 PNU 목록을 보내는** 형태여야 한다(S1 설계에서 확정한다).
- **토지 실거래(`prop_type="land"`) 의 `jibun` 표기 형식을 라이브로 확인하지 않았다.**
  아파트와 다를 수 있다 — S1 에서 **실호출로 확인**하고, 다르면 매칭 규칙을 고친다.
- **397필지의 시군구 분포 미측정** — 쿼터 예산의 분모다. S1 에서 센다.
- `MolitClient.get_transactions` 의 `validate_transactions` 가 **이상행을 드롭**한다
  (`molit_client.py:496-509`). 즉 **원천에 있었는데 우리가 버린 행**은 보고서에 안 나온다.
  이 사실을 보고서에 **명시**해야 한다(미반영 시 "신고내역 전수"라는 거짓 주장이 된다).
- **다른 테넌트의 필지 분포 미측정** — 표본은 admin 테넌트 하나다.
