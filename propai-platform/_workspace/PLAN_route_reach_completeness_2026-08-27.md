## 2. 변경 — 구조 하나

**「의도적 비노출」 4번째 분류를 사유와 함께** 도입하고 완성도를 재정의한다:

    완성도 = (확정 소비 + 의도적 비노출) / 전체
    100%  ⇔  **미분류(설명되지 않은 고아) = 0**

★목표가 *"고아 0"* 이 아니라 **"설명되지 않은 라우트 0"** 이 된다 —
모든 라우트가 **소비되거나, 왜 소비되지 않는지 적혀 있거나** 둘 중 하나.

**측정 결과**: `75.64% = (414 + 2) / 550 · 미분류 130 · 판정불가 4`

★**면제 3 → 2 로 줄였다.** `/webhooks/{webhook_id}/test` 를 넣었다가 **뺐다** —
PR #895(웹훅 패널 실 API 배선)가 그 경로를 **확정 소비로 전환**시키므로, 면제로 남기면
`test_no_dead_exemption` 이 **#895 착지 순간 빨개진다.** 두 PR 이 순서에 따라 서로를 깨는
상태였고 **착지 전에 재현해서 잡았다**(#895 의 프론트 파일을 이 워크트리에 얹어 재현 → 실패 확인 → 제거 후 양쪽 순서 모두 통과).
★교훈: **면제는 「지금 고아」가 아니라 「영원히 고아여야 한다」에만 넣는다.**
진행 중인 배선이 걷어갈 수 있는 것은 고아로 남겨 래칫이 줄이게 한다.

★**지표가 개선을 실제로 포착한다**(피드백 루프 실증): #895 를 얹으면
`75.64% → 76.36%`(소비 414→418 · 미분류 130→126). 목업을 실 API 로 바꾼 것이 **숫자로 보인다.**

★**기존 도구·기준선·래칫은 한 줄도 안 건드린다.** 이 축은 그 위에 얹히는 **추가 관측**이다.
