# 토스 결제 — 키 계열 게이트 + 결제 퍼널 피드백루프 (2026-09-06)

> **배경**: 토스 연동 자체는 `PLAN_toss_payments_integration_2026-08-27.md` 로 이미 구현·머지됐다.

## 2. 변경 내용과 그것이 회귀가 아닌 근거

### 2-1. 키 계열 게이트 (Q4~Q7 대응)

| 변경 | 회귀가 아닌 근거 |
|---|---|
| `toss_payments`: 키를 `(환경, 계열)` 로 **파싱**하는 SSOT 추가 | 순수 추가. 기존 `is_test_mode()`·`secret_key()`·`client_key()` 시그니처 불변 |
| `key_pairing_ok()` 가 **환경 + 계열 + 우리 SDK 요구계열** 세 축을 본다 | 정상 조합(`test_gck`+`test_gsk`, `live_gck`+`live_gsk`)은 **종전과 같이 True**. 값이 바뀌는 것은 **원래 동작하지 않았을 조합**뿐 |
| `resolve_payment_mode()` 가 **짝이 맞을 때만** `"toss"` | 키 미설정 시 종전과 동일(`simulated`/`manual_only`). 짝이 맞으면 종전과 동일(`toss`). **바뀌는 것은 「짝이 틀린 채 toss 로 켜지던」 경로뿐이고, 그 경로는 결제창에서 `INVALID_API_KEY` 로 죽던 경로다** |
| 진단이 **사유를 말한다** — 무엇이 왜 틀렸는지 | 현재 `key_pairing_ok:false` 만으로는 관리자가 고칠 수 없다(진단 불가는 그 자체로 장애) |

★**방향 두 개를 다 건다**(§B-19): 「틀린 짝을 켠다」와 「맞는 짝을 안 켠다」 **둘 다** 결함이다.
두 모집단을 같은 실행에서 단언한다.

### 2-2. ★환수액을 **금액에서 파생**한다 (독립 렌즈 2종이 같은 자리를 지목)

| 변경 | 회귀가 아닌 근거 |
|---|---|
| `reconcile_order` SELECT 가 `refunded_krw` 를 읽는다 | 순수 추가. 종전엔 **한 번도 안 읽었다** |
| `PARTIAL_CANCELED` 를 `_REVOKED_STATUSES` 에서 **분리** | 전면 철회 4종의 동작은 **불변**(테스트 모집단 ①이 그것을 잠근다) |
| 환수액 = `(amount − refunded) − 벤더 balanceAmount` | `refunded=0` · 전면취소면 `벤더잔액=0` → **종전과 같은 전액**. 값이 바뀌는 것은 **부분환불이 있었던 주문뿐**이고, 그 경우 종전 값이 틀린 값이었다 |
| 벤더 잔액 미상 → `clawback_undetermined` | 종전엔 미상을 **0으로 뭉개** 전액을 뺐다. 「모름」을 유효값으로 표현하지 않는다 |
| 원장에 **실제로 빠진 액**을 적는다(CTE `prev`) | 종전엔 차감이 `GREATEST(0,…)` 로 잘리는데 원장엔 전액을 적어 합이 갈렸다 |
| ★환수가 `paid_at` 을 **안 지운다** | 형제 `coin_orders_service.py:317-319` 가 *"진짜 잠금은 `paid_at IS NULL`"* 이라 **선언**한다. 종전 이 줄이 그 전제를 지워 전상법 시행령 §6①(청약철회 기록 **5년 보존**) 대상을 파기 대상으로 재분류했다 |

### 2-3. 금액 대조를 **형제와 통일**한다

`totalAmount` 대조가 `reconcile_order` 에만 있고 `confirm_toss_payment` 경로에는 **0회**였다
(AST 로 실측: 파일 전체 판정 비교문 1곳 → 이제도 1곳이지만 **두 경로가 그것을 공유**한다).
특히 `_try_resolve()` 는 **사용자가 보낸 `paymentKey`** 로 조회한 Payment 를 금액 확인 없이
지급으로 흘렸다. 승인 요청은 서버 금액을 실어 보내 벤더가 대신 걸러 주지만, **재조회에는
그 방어가 없다**.

★**양방향으로 건다**: 금액이 틀리면 지급 0, 금액이 맞으면 **복구가 실제로 일어난다**.
한쪽만 걸면 "재조회 결과를 전부 거절"하는 구현이 만점을 받고 복구 경로가 죽는다.

## 3. ★검증하지 못한 것 (비워 두지 않는다)

1. **라이브 결제 왕복 — 여전히 미측정.** 스크린샷의 **시크릿 키는 마스킹**(`test_gsk_****`)돼
   나에게 없다. 등록은 소유자가 관리자 화면에서 해야 한다(§6 절차).
   → 등록 **후** 실행할 검증 스크립트를 §5 에 무료(테스트키) 로 준비한다.
2. **컨테이너 다중성 미측정**(Q9). `--workers` 는 없지만 컨테이너가 여러 대면
   `set_secret` 의 `os.environ` 반영이 **한 대에만** 걸린다. → 등록 직후
   `/admin/payments/health` 를 **연속 폴링**해 응답이 흔들리는지로 **무료로** 판정한다(§5-3).
3. **프로덕션 결제 퍼널 볼륨 미측정** — Q15 의 인용값(0행)은 2026-08-12 기준이라 **승계하지 않는다.**
   전수 계측의 볼륨 영향은 등록 후 성장루프 이벤트 수로 실측한다.
4. **웹훅 실수신 미측정** — 토스 콘솔에 URL 등록은 소유자 작업(선행 계획서 §3-2 와 동일). 라벨을 승계하지 않고 **재확인 대상**으로 남긴다.
5. **분석기가 `funnel_step` 을 어떤 축으로 판정하는지 미측정** — 이벤트가 저장되는 것과
   **인사이트로 판정되는 것은 다른 명제**다. 렌즈 조사 결과를 받아 §7 에 반영한다.

| K5 | **결제 퍼널이 전수 수집된다** | `funnel_step` 기본 15% ↔ 결제 호출 100% **두 모집단**을 같은 실행에서 |
| K6 | **화이트리스트 parity 불변** | 기존 parity 테스트가 계속 초록(타입 추가 0) |

★K2·K5 는 **한쪽만 단언하면 무의미**하다(§「한쪽만 거는 단언」 하루 3회 실측).
