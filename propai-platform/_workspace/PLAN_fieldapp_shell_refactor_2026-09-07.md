## 2. 변경 내용과 **회귀가 아닌 근거**

### C1. 데스크톱 내비를 `MENU_GROUPS` 소비로 전환 (P3·P4 해소)

- **무엇**: `SiteWorkspaceClient` 의 데스크톱(sm+) 가로 탭바를 **그룹 레일**로 교체.
  `MENU_GROUPS`(P2 의 SSOT)를 `visibleTabs` 와 교집합해 그룹별로 접어 렌더.
- **회귀가 아닌 근거**: **IA 를 새로 만들지 않는다.** 모바일 시트가 이미 소비 중인 **같은 SSOT** 를
  데스크톱이 소비할 뿐이다 ⇒ 두 모집단이 **같은 IA** 로 수렴한다(현재는 갈라져 있다).
  라벨·아이콘·게이팅은 `roleConfig` 소비 그대로(재정의 0).
- ★**부수 관측(이번에 고치지 않음)**: `MENU_GROUPS` 의 그룹 제목이 **영문**(Sales/Money/Operations/My)
  인데 탭 라벨은 전부 한글이다. 표기 일관성 문제로 보이나 **이번 변경의 원인이 아니므로 범위 밖**에
  둔다(고치려면 별도 근거가 필요하다).

### C2. 「앱으로 열기」 정직화 (P5·P6·P7 해소)

- **무엇**: ①이미 앱 안이면 **숨긴다** — `standalone`(PWA 실행) **또는** 팝업 내부
  (`window.name === "propai-field-app"` / `window.opener !== null`) ②남는 경우 **라벨을 실제 동작에
  맞춘다**(「앱으로 열기」→「별도 창으로 열기」) ③설치 가능하면 **설치를 우선 제시**.
- **회귀가 아닌 근거**: 형제 `InstallGuide` 가 **이미 `standalone` 가드를 갖고 있다**(P6).
  같은 셸 안에서 한쪽만 가드가 없던 **불일치를 없애는 것**이지 새 정책이 아니다.
  ★그리고 P7 이 주석의 동작 주장을 반증했으므로, **라벨이 사실과 어긋나는 상태를 유지하는 것이
  회귀**다(§30 — 주석·라벨의 동작 주장은 검증 대상).

### C3. `DESIGN.md` 에 Part C「현장앱 셸」신설 (P9 해소)

- **무엇**: 현장앱 셸의 규정을 명문화 — 데스크톱 레일/모바일 하단탭의 **모집단별 규칙**,
  탭 상한, 그룹 축, 앱 어포던스의 위치(설치 유도 ≠ 창 모드 전환).
- **회귀가 아닌 근거**: **없던 절을 추가**할 뿐 기존 Part A/B 를 건드리지 않는다.

★**하지 않는 것(범위 밖 · 명시)**: 커맨드팔레트 · `MENU_GROUPS` 한글화 · 볼트가 남긴 SSOT
불일치 2건(세대 상태모델·직급 라벨) · 오프라인 outbox. 각각 별도 근거가 필요하다.

## 3. ★검증하지 못한 것 (2026-09-07 적대 리뷰 반영해 **다시 씀**)

★초판은 5건을 적었고 전부 진짜였으나 **최소 4건이 빠져 있었다.** 아래는 보강본이다.

### 잰 것 — 초판이 「미측정」이라 적었다가 **측정으로 바뀐 것**

- **팝업에서 `window.name` 이 유지되는가** → **측정됨**(Chromium 1228 · Playwright 1.58.2):
  `named="propai-field-app"` · 대조군 `_blank` 는 `""` · 팝업 안 라우팅 후에도 유지.
  재현: `e2e/field-app-window-name.spec.ts`.
  ★초판은 이것을 *"기기가 없어 불가"* 로 분류했는데 **틀렸다** — 저장소에 playwright 와
    크로미움이 이미 설치돼 있었다. **잴 수 있는데 안 잰 것**이었다.

### 여전히 미측정 — 이유를 함께 적는다

| 미측정 | 이유(셋을 구분한다) |
|---|---|
| WebKit·Firefox 의 `window.name` | **장치 부재** — 이 환경에 그 엔진이 없다. 잰 것은 크로미움뿐이다 |
| 실기기 iOS Safari 의 `standalone`·설치 단계 | **장치 부재** — 진짜 불가 |
| **셸(`SiteWorkspaceClient`) 렌더 커버리지 = 0** | **미착수** — 패널 40여 개 임포트라 비용이 크다. `FieldShell.wiring.test.ts` 는 **소스 문자열 검사**이고, 계획서 §5 가 스스로 선언한 *"렌더 결과를 태운다(소스 grep 금지)"* 를 **이 PR 이 어겼다.** 그 사실을 그 파일 머리에 적었다 |
| **셸의 변이 커버리지 = 0** | `SiteWorkspaceClient.tsx` 변경분이 import·주석·JSX 2줄이라 기계 변이가 **0건 생성**됐다 |
| `InstallGuide` 동작 변경 | 그 파일 전용 테스트가 **0건**이다. 이 PR 이 가드를 `standalone` → `inAppShell` 로 넓혔다가 되돌렸는데, 그 왕복을 태우는 락이 없다 |
| e2e 레인이 **PR 을 막지 않는다** | ★한때 여기에 *"CI 가 playwright 를 돌지 않는다"* 고 적었다 — **거짓**이었다(`ci.yml` 한 파일만 보고 「CI」로 일반화 · §G-26). `.github/workflows/e2e-nightly.yml` 이 **경로 필터 없이** `playwright test` 를 cron `0 18 * * *`(03:00 KST)+수동으로 돌리고 `testDir: "./e2e"` 라 **새 스펙도 수집된다.** 정확히는 **PR 게이트가 아니지만 깨지면 야간 레인이 빨개진다** |
| 레일 전환의 실제 인지부하 감소 | **사건 미발생** — 이 제품 사용자로 측정한 값이 없다. 성장루프로 사후 관측할 자리 |
| 국내 경쟁 제품 IA | 공개 자료 **0건**(제품은 실재) |
| 벤치마크 5종의 URL·접근일 | 조사 산출물에 URL 이 있으나 **이 계획서에는 옮기지 않았다** — 재검증하려면 조사 보고를 봐야 한다 |
| 기존 데스크톱 탭바 사용자의 근육기억 손실 | 미측정 |

### ★판별자가 **하나뿐**이라는 사실 (초판이 「둘 다 걸었다」고 잘못 적었다)

초판 §2 C2① 은 *「`standalone` 또는 팝업 내부(`window.name` / `window.opener !== null`)」* 라고
적었고, 구현에는 `window.opener` 가 **없다**. 그리고 `standalone` 과 `window.name` 은
**이중화가 아니라 배타적 커버**다(설치본 축 / 별도 창 축).

⇒ 사용자가 신고한 **별도 창 모집단의 판별자는 `window.name` 하나**다.
   `window.opener` 를 쓰지 않는 이유는 **위양성**이다 — 우리 목록 화면에서 `target=_blank`
   로 연 평범한 탭도 `opener` 를 갖는다. 위음성 하나를 줄이려다 정상 화면에서 어포던스를
   지우게 된다. **그래서 판별자는 하나이고, 그 사실을 숨기지 않는다.**
   잔여 위험은 위 표의 「WebKit·Firefox 미측정」 줄에 있다.
