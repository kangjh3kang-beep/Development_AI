## 2. 설계 — **판정률의 정의를 바꾼다**(하한은 그대로)

현재 `judged/total` 은 *"임계로 분류할 수 있었던 표본의 비율"* 이다. 표본이 작으면 영원히 100% 가 안 된다 —
**트래픽이 적은 것은 결함이 아니다.**

> **100% 의 올바른 정의: 「모든 축이 *무언가를* 말한다」 — 판정이든, 왜 판정 못 하는지든.**

### 세 상태로 가른다(지금은 둘)

| 상태 | 뜻 | 지금 |
|---|---|---|
| `judged` | 임계로 분류함 | 있음 |
| `withheld` | **표본 부족 — 지금은 알 수 없다** | 있으나 **화면에 안 나감** |
| **`inconclusive_reported`** | **표본 부족을 *인사이트로* 말한다** | **없음 ← 이걸 만든다** |

**`withheld` 가 0 이 아니어도 100% 가 될 수 있다** — 보류를 *보고하면* 그 축은 자기 몫을 다한 것이다.

```
coverage_pct = (judged + withheld_reported) / total
```

### 구현 축 — ★이 PR 의 실제 범위는 **둘**이다

**이 PR 에 있는 것**

1. **`judged_pct`** — 임계로 분류한 비율. `total==0` 이면 **`None`**(0.0 으로 두면
   *"판정률 0%"* 가 되어 **축 정지를 결함으로 오독**시킨다).
2. **`state`** — `axis_idle`(축이 안 돎) / `partial`(표본 부족) / `judged`(전부 판정).
   `quality_drop` 은 라이브에서 `total=0` 인데 종전엔 표본 부족과 **뭉개졌다**.

**이 PR 에 없는 것 — 별건으로 남긴다**

3. ~~보류를 인사이트로 승격~~ — 기존 `note_coverage` 독스트링이 *"행을 새로 만들지 않는다"* 로
   **이미 기각**했고(키별 802건 우려), 내 축별 1건(축 3개)은 다른 제안이지만 **누적 영향이 미측정**이다.
4. ~~`coverage_pct`~~ — **독립 적대 리뷰(2026-08-27)가 반증했다.** `100.0 if total else None` 은
   `total>0` 인 모든 입력에서 **상수**이고, 유일한 비상수 거동은 `state=="axis_idle"` 와 **완전 중복**이다.
   계획서 식 `(judged + withheld_reported)/total` 의 `withheld_reported` 가 **3번(미구현)에 걸려 있으므로**
   그 식은 아직 성립하지 않는다. **소비처 0인 상수를 싣지 않는다** → 필드 제거.

★**따라서 「100%」는 이 PR 로 달성되지 않는다.** 이 PR 이 하는 것은 **왜 100% 가 아닌지를
정직하게 말하게 하는 것**이다(`state` 로 축 정지와 표본 부족을 가르고, `judged_pct` 로 비율을 싣는다).
100% 는 3번이 들어가야 정의상 가능해진다.

## 3. ★검증하지 못한 것

- **★기존 코드가 이 접근을 이미 기각했다 — 그런데 다른 제안이었다.**
  `note_coverage` 독스트링: *"행을 새로 만들지 않는다. **802개를 보류 행으로 발행하면 소음이 늘 뿐**"*.
  그 기각은 **키별 발행**(latency 키 825개 중 802개 보류)을 우려한 것이다.
  **내 설계는 축별 1건**이고 축은 **3개**(`fallback_rate` · `quality_drop` · `latency_regression`
  — `note_coverage` 호출부 파생: analyzer.py:640·770·831)이므로 **창당 최대 3건**이다.
  ★계획서 초판에 *"축이 6개"* 라고 적었는데 **틀렸다**(세어 보지 않고 썼다). 실측 3개.
- **누적은 여전히 미측정.** 창이 여러 개면 3건이 반복 발행될 수 있다 → **중복 억제를 축 단위로**
  걸고, `#880` 의 retention 이 정리하는지는 **오늘 03:12 UTC 이후 확인**해야 한다.
- **`quality_drop` 이 `total=0` 인 이유 미측정.** 축이 안 도는지, 데이터가 없는지 안 갈렸다.
  `axis_idle` 은 그 구분을 **표기**할 뿐 원인을 밝히지 않는다.
- **100% 가 되면 운영자가 무엇을 하는지 미측정.** 지표가 100% 여도 `withheld` 가 다수면
  *"판정 못 한 것이 많다"* 는 사실은 남는다. **`coverage_pct` 와 `judged_pct` 를 둘 다** 실어
  한 수로 뭉개지 않는다.
