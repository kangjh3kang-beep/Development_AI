## 2. 변경 내용과 **회귀가 아닌 근거**

1. **키 3종 제거** — `openaiApiKey` · `anthropicApiKey` · `getActiveApiKey` · `hasValidKey`.
   *회귀 아님*: 전제 3·4·5·6 으로 **소비처가 없다**(백엔드 수신 경로도 없다).
2. **입력칸 제거** — 사용자가 넣어도 아무 효과가 없는데 `sk-...` 를 요구하는 칸.
3. **"Connected" 를 사실로 교체** — 서버 공통 키를 쓴다는 사실을 그대로 표기.
   근거: `useAIReady()` 독스트링이 이미 *"서버 공통 키를 사용하므로 항상 준비됨"* 이라 적는다.
4. **이미 저장된 키 폐기** — `persist` 의 `version`+`migrate` 로 기존 localStorage 에서
   키 필드를 **떨어낸다**. 전제 9 — 로그아웃 전에는 안 지워지므로 제거만으로는 남는다.
5. **래칫 하향** — 전제 10. 같은 커밋에서 낮춘다(안 낮추면 "죽은 면제" 로 빨개진다).

★**하지 않는 것**: `llmProvider`/`llmModel` 제거(전제 8 — 살아 있다) · 백엔드 변경 ·
`projectSync` 목록 변경(그 항목은 여전히 유효 — 다른 필드가 남는다).

## 3. ★검증하지 못한 것

- **이미 배포된 브라우저에 저장된 키가 실제로 몇 건인지** 알 수 없다(클라이언트 저장소).
  마이그레이션이 도는 것은 **그 사용자가 다음에 앱을 열 때**다.
- **제품/디자인 의사결정자의 의도** — 볼트·계획서에 BYOK 요구가 0건이라는 것이 근거이지,
  누군가의 미문서화 의도가 없다는 증명은 아니다.
- 마이그레이션이 **다른 필드를 건드리지 않는지**는 테스트로 잠그지만, 실제 사용자
  localStorage 형태의 다양성(옛 버전·손상된 JSON)은 표본이 없다.
- 라이브 확인은 **배포 후에만** 가능.
