### 결함 요약

**관리자가 LLM 키를 「테스트」하면 초록 「연결 성공」이 뜨는데, 그건 「값이 있다」는 뜻이다.**
키가 401(무효)이든 402/429(크레딧 소진)든 **화면은 성공이라고 말한다.**
그리고 그것을 진단할 도구가 **이미 있는데 아무도 안 쓴다.**

★**같은 파일이 원칙을 적어 두고 등기 키에만 적용했다** — *"처방을 적용한 범위 =
결함이 사는 범위인지 확인하라"*(회귀망 규율 §D-20)의 교과서적 사례다.

★그리고 오늘 성장루프에서 본 `site_analysis 폴백률 76~91%`(critical, 08-24)의
**원인을 이 도구로 알 수 있었다** — 독스트링이 정확히 *"인터프리터가 실패를 삼켜
'지연'으로만 보이던 문제"* 라고 적고 있다.

## 2. 변경

`/{name}/test` 가 LLM/이미지 키에 대해 **`llm_health`/`image_health` 를 태운다.**
★**프론트는 한 줄도 안 바꾼다** — 기존 「테스트」 버튼이 그대로 진짜가 된다.
실패는 `error_type` 과 원본 응답(`detail`)을 함께 싣는다(사유를 버리지 않는다).

## 3. ★검증하지 못한 것

- ★**라우트 도달률은 안 움직인다.** 실측 확인: 고아 **132 → 132**.
  내가 **백엔드 내부 함수**로 호출했지 프론트가 HTTP 로 부르는 게 아니기 때문이다.
  `orphan_routes` 는 **프론트 리터럴**을 보므로 `llm-health`·`image-health` 는 여전히 고아다.
  → **기능 결함은 고쳤고 라우트 축은 별개다.** 그 둘을 「간접 소비」로 면제할지는
    `#892` 착지 후 **별건**으로 다룬다(PR 간 결합을 또 만들지 않는다).
- **라이브에서 실패 케이스를 못 재 봤다.** 키가 유효한 환경에서는 `ok:True` 만 나온다.
  401/402 응답 형태는 **백엔드 독스트링을 신뢰**한 것이고 직접 관측하지 않았다.
- `image_health` 의 프로바이더 매핑은 **`openai` 하나**만 넣었다(`IMAGE_PROVIDERS` 전수는 미확인).
- 등기 키 4종의 기존 경로는 **무변경**이다.
