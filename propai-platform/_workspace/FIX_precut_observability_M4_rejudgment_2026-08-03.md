## 2. ③ M-4 재판정 — **조건부 기각**(캡 구속 regime 한정)

독립 3렌즈(반사실·판정가능성·병목) 전원이 **"예산 분할 착수 반대, 계측 먼저"**로 수렴했다.

> ★리뷰 F-7 정정 — 최초 보고는 "철회"라고 썼으나 **이 PR 자신의 테스트가 반례**다.
> 아래 반증 1(정렬키 상쇄)은 **캡(28)이 구속력을 가질 때만** 성립한다. 그런데
> `test_precut_makes_dong_prior_saturation_observable` 은 정확히 **캡 비구속** regime을
> 구성하고, 거기선 프라이어가 반경 **안**의 이웃 리를 실제로 굶겨 `count_in_radius == 0`이
> 된다 — 그 regime에서 쿼터의 순효과는 **양수**다. 하필 이 캠페인의 발단인 **호미곶이 그 계열**
> (거래는 멀고 많으며 가까운 물건은 이웃 리)이다.
> → 판정: **캡 구속 regime = 기각 / 캡 비구속 regime = 보류.**
> 재검토 트리거: `groups_cut > 0 && 반경통과 그룹수 < _MAX_GROUPS_PER_CAT`.
> **이 PR의 계측이 그 조건을 프로덕션에서 처음으로 관측 가능하게 만든다.**

### 반증 1 — 사전컷 정렬키와 캡 정렬키가 다르다

| 게이트 | 정렬키 | 동·거리 항 |
|---|---|---|
| 사전컷(80) | `(동일치, -건수)` | 동 ○ |
| 캡(28) | `(정밀도, -건수)` | **없음** |

프라이어가 밀어낸 그룹은 정의상 "구 top-80 중 건수 최하위권"인데, 캡이 다시 `-건수`로 자른다.
→ 프라이어의 **손해(밀어냄)와 이득(끌어올림)이 캡에서 상쇄**된다.

### 반증 2 — 비대상동 후보의 반경내 적중률이 0%였다

역삼동 1km 실측: 반경 내 `apt_trade` **24건 전량이 역삼동**.
이 regime에서 쿼터 Q를 예약하면 적중률 0%인 후보에 예산 Q를 쓰고, 적중률 100%인 대상동 그룹을
직접 밀어낸다 → **순효과 엄격히 음수**.

★"굶김"으로 보였던 신호는 **통제실험으로 반증**됐다. 사전컷은 반경과 무관하므로 반경만 3km로
넓히자 같은 카테고리에서 6개 동(도곡·삼성·대치·개포·논현)이 나타났다 — 타 동 그룹은 사전컷에
굶은 것이 아니라 **1km 밖이었을 뿐**이다.

### 반증 3 — M-4 근거 수치의 분모가 틀렸다

"사전컷 = 그룹 손실의 73.8%"는 **지오코딩 이전 모집단** 기준이다. 사용자 가시 수율의 분수가 아니다.
반경 통과 그룹이 28 이상인 카테고리에서는

```
∂(가시 출력)/∂(사전컷 상한) = 0        ∂(가시 출력)/∂(캡) = 1
```

즉 사전컷을 아무리 넓혀도 **출력이 변하지 않는다**. 실측(3km): 반경 내 456그룹인데 출력은
카테고리당 28 — **최소 176그룹이 캡에서 버려졌고, 그건 이미 사전컷을 통과한 모집단**이다.

### 그래서 남은 진짜 문제 = **판정 재료가 없다**

`geocode_precut_count`는 10개 카테고리 **합산 스칼라 하나**다. 응답에서
(a) 어느 카테고리가 컷됐는지 (b) 대상동 그룹이 예산을 넘었는지를 **원리적으로 역산할 수 없다**
(미지수 10개에 방정식 1개, 게다가 `== 80`은 "잘려서 80"과 "원래 80"을 구분 못 한다).

## 3. 변경 내용 (백엔드 전용 · 응답 additive · 숫자 무변경)

### D-1 — `_dong_from_address` 무음 오발화 봉합 (실결함)

```
"서울특별시 강남구 역삼동 736 101동 502호"  →  종전 "101동"  /  수정 "역삼동"
```

주소 전체에서 **마지막** 동/리/가 토큰을 채택해, 지번 **뒤**의 동/호 표기가 법정동을 덮어썼다.
`101동`은 MOLIT `umdNm`과 **영영 매칭되지 않으므로** 사전컷 프라이어의 1순위 항이 전 그룹에서
상수로 붕괴 → 순수 건수 정렬(= W2 이전 동작)로 **무음 회귀**한다. 오좌표를 만들지는 않지만
기출하 최적화가 조용히 꺼지고, 응답에 그 사실이 **0비트도 없었다**.

봉합: 법정동은 지번보다 앞에 오므로 **지번 토큰(숫자 시작 또는 "산"+숫자)에서 멈춘다.**
도로명 주소가 빈 값이 되는 기존 계약은 그대로 유지.

### 카테고리별 사전컷 계측 (`categories[*].precut`)

| 필드 | 의미 |
|---|---|
| `budget` | 사전컷 상한(80) |
| `groups_before` | **분모** — 컷 전 그룹 수 |
| `groups_cut` | 잘린 그룹 수(미발동이면 0) |
| `dong_prior_active` | 프라이어가 켜지긴 했는가 |
| `dong_matched_group_count_before` | 대상동 일치 그룹 수(컷 전) |
| `dong_matched_group_count_kept` | 같은 값(컷 후) |

- **분모를 미발동 카테고리에도 싣는다** — 없으면 `groups_cut == 0`이 "80 이하라 안 잘림"인지
  "그 카테고리 거래 0건"인지 구분되지 않는다(0과 미확보를 같은 기호로 쓰지 않는다).
- 단위는 전부 그룹 수 — **이름에 `_group_count`로 박고**, 거래 건수 전용 계약인 `sample_basis`에는
  넣지 않는다(H-4 단위 혼입 재발 방지).
- 실패 시 **0이 아니라 `None`** — 세는 데 실패한 것을 0으로 적으면 관측된 적 없는 사실을
  만들어 낸다(N-4와 동일 판단).
- 추가 외부 호출 **0**.

### 최상위 관측 (`sigungu_hint`/`sigungu_source`와 대칭)

- `target_dong_hint` — 이름에 `_hint`를 박는다. PNU/bcode에서 온 **권위값이 아니라** 입력 문자열
  휴리스틱이다. 소비처가 "대상 법정동"으로 렌더하면 주소 오타가 사실로 승격된다.
- `target_dong_source` — `address` / `unresolved_road_name`(설계상 정상) / `unresolved`(조사 대상).
  꺼진 **이유**를 구분하지 않으면 "프라이어 미발화 30%"가 정상인지 버그인지 판정할 수 없다.
- `precut_accounting_mismatch` — 카테고리별 합과 기존 스칼라의 **무성 발산을 스스로 고발**한다.
  런타임 assert는 계측이 본로직을 죽이므로 쓰지 않는다(관측 장치 제1원칙).

★종전엔 **힌트 축만** 노출돼, `sigungu_source == "hint"`(정상)인데 동 프라이어만 꺼진 조합이
"전부 정상"으로 보였다. 두 힌트는 **독립적으로 실패**하고 실패 모드가 다르다.

### ★내 "5건 전부 CAUGHT"는 과장이었다 — 리뷰어가 미선택 변이 4건의 생존을 실증했다

`M1~M5`는 **내가 고른** 변이일 뿐이고, 잠금의 **판별 범위**는 따로 물어야 한다는 교훈
(H-1에서 이미 배운 것)을 또 어겼다. 리뷰어가 찾은 생존 변이:

- **F-1** `precut_accounting_mismatch` 를 리터럴 `False` 로 → 통과. **고장난(항상 False) 탐지기가
  단언을 통과**한다 — 탐지기가 잡을 회귀를 스스로 false-healthy로 가리는 #497의 그 형태.
- **F-2** `kept = before` → 통과. 내가 "둘의 차가 포화도"라고 **직접 규정한 판별량**이 한 번도
  실행되지 않았다(골든이 `before == kept == 80`이라 축이 죽어 있었다).
- **F-3** 빈 target 시 `0 → None` → 통과. 내가 명시한 원칙("0과 미확보를 같은 기호로 쓰지
  않는다")을 인코딩한 분기가 안 잠겼다.
- **F-4** break의 `산` 절 제거 → 통과. `"산1-1"`은 애초에 동/리/가로 끝나지 않아 덮어쓴 적이
  없으므로, 내 단언은 **주석이 주장하는 이유와 다른 이유로** 통과하고 있었다(H-1 클래스 공허 단언).
- **F-5** 도로명 판정 `("로","길")` → `("로",)` → 통과(길 픽스처 부재).

### ★★F-1은 한 번 더 뚫렸다 — 헬퍼는 잠갔는데 **호출부**를 안 잠갔다

F-1 봉합으로 순수 헬퍼를 빼고 True 분기 단위테스트를 넣었는데, **리터럴 `False` 변이가 여전히
생존**했다. 헬퍼는 멀쩡한데 **아무도 부르지 않는 상태**를 잠그지 않은 것이다.
→ 헬퍼를 `True`로 monkeypatch 했을 때 응답이 따라오는지 보는 **배선 락**을 추가한 뒤 CAUGHT.
**배선 미변이로 뚫린 여섯 번째 사례**다.

★M4도 처음엔 생존 위험이 있었다 — 단일 토큰 동만 쓰면 `_dong_tail`이 **항등함수**가 된다
(R-2에서 실제로 뚫린 그 함정). 골든을 읍·면 두 토큰(`"호미곶면 대보리"`)으로 바꿔 판별력을

## 6. 교훈

1. **"굶김 신호"를 보면 통제변수를 먼저 세라.** 반경 1km에서 전량 대상동이라 굶김으로 보였지만,
   반경만 바꾼 대조에서 반증됐다. 직전 세션이 정확히 같은 실수(재시도 오진)를 했고, 이번엔
   실험 설계 단계에서 잡았다.
2. **처방의 근거 수치는 분모를 확인하라.** "사전컷 73.8%"는 참이지만 **가시 수율의 분수가 아니다.**
   한계수율(∂출력/∂상한)로 다시 물어야 병목이 드러난다.
3. **관측 계약도 대칭이어야 한다.** 힌트 축만 노출하면, 다른 축이 죽은 상태가 "전부 정상"으로 보인다.
4. **계측은 관측 대상과 같은 규약으로 세야 한다.** 다른 규약으로 세면 계측이 대상을 대변하지 못한다
   (W2-c 가짜 골든과 같은 계열). 그리고 그 사실을 **판별할 수 있는 골든**이어야 한다 — 단일 토큰
   픽스처로는 `_dong_tail` 변이가 생존한다.
5. **티켓의 처방과 티켓의 의도를 분리하라.** M-4의 처방(예산 분할)은 캡 구속 regime에서 틀렸지만
   의도(순효과 미측정)는 옳았다. 처방을 정정하면서 의도를 버리지 않는 것이 이 PR이다.
6. **★기각에는 범위를 붙여라.** "틀렸다"가 아니라 "이 regime에서 틀렸다"여야 한다. 내 결론은
   캡 구속 regime에서만 참인데 무조건으로 썼고, **내가 쓴 테스트가 그 반례를 이미 담고 있었다.**
   리뷰어가 내 코드가 아니라 **내 결론의 범위**를 잡아냈다.
7. **★"내가 고른 변이가 전부 잡혔다"는 잠금의 증명이 아니다.** 리뷰어가 미선택 변이 4건의
   생존을 실증했고, 그중 둘은 내가 **직접 정의한 판별량**(포화도)과 **직접 선언한 원칙**(0≠None)을
   잠그지 않았다. H-1에서 같은 교훈을 적어놓고 또 반복했다 — 변이는 **적대적 제3자**가 고를 때만
   판별 범위를 말해준다.
8. **★헬퍼로 추출하는 것은 봉합의 절반이다.** F-1을 순수 함수로 빼고 True 분기를 단위테스트로
   잠갔는데도 호출부 상수화 변이가 살아남았다. **로직과 배선은 따로 잠근다** — 이 저장소가
   배선 미변이로 뚫린 여섯 번째 사례다.
