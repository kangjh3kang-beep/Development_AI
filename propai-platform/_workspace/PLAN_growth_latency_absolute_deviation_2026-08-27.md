## 2. 변경 내용과 **회귀가 아닌 근거**

- `LATENCY_ABSOLUTE_DEVIATION_MS = 5000` · `LATENCY_TYPICAL_MIN_WINDOWS = 3`
- `typical_p95()` — 이력 p95 의 **중앙값**(평균이면 장애가 평소값을 밀어 다음 장애를 놓친다)
- `classify_latency_absolute()` — 두 표본을 비교하지 않으므로 **표본 잡음이 원리적으로 없다**
- 배선: `sev = ratio_sev or abs_sev` · `metrics_json` 에 `triggers`·`typical_p95`·`typical_windows`

**회귀가 아닌 근거**: 비율 축 **무변경**(P8 의 `ai/status` 가 여전히 비율로 잡힘을 락으로 확인) ·
키 형식 무변경(→ **baseline 고아 0 · `#880` IDENTITY 무영향**) · 형제 스위트 **44 passed** 유지.

## 2-5. ★내가 죽인 처방 둘 (다음 사람이 다시 안 밟게)

- **백분위 낮추기** → P2 로 사망. 23.0%→14.7% 로 줄 뿐이고 분산이 큰 route 는 안 듣는다.
- **tenant 를 key 에 추가** → 별도 측정으로 사망: 구성 탓 위양성이 **발화 25건 중 1건(4%)** 뿐인데
  비용은 **baseline 96개 전부 고아 + 옛 키 행 영구 open**. **기전은 진짜이고 발생률이 낮다.**

★그리고 **확정순서 2번을 정정한다**: 「7일 트레일링 + **1.5배 비율**」은 0% 개선(내가 잰 그대로)이지만
「7일 트레일링 + **절대편차**」는 작동한다. **재료는 옳았고 연산자가 틀렸다.**

## 3. ★검증하지 못한 것

1. **배포 후 실제 발화 미관측** — 배치로 도는 기능이라 **배치 1회 실행 후**에만 확인된다.
2. **임계 5,000ms 가 제품적으로 옳은지** 모른다. **SLO 결정**이고 나는 *"실장애 5/5 를 잡고
   하루 2.1건"* 까지만 잰다. 다른 트래픽 국면에서는 재보정이 필요하다.
3. **평소값이 「장애가 상시화된 route」에서 밀린다** — 장애가 7일 내내면 그것이 평소값이 된다.
   중앙값이라 소수 극단엔 강하지만 **과반이 장애면 진다**. 미봉합.
4. **`typical` 은 `p95_ms` 이력에서 온다** — 그 이력은 판정된 창만 남으므로 **저트래픽 시간대가
   과소대표**된다. 편향 방향·크기 **미측정**.
5. baseline 자기참조 · tenant 혼입 · 백엔드 4xx 무주지 — **셋 다 안 고친다**.

## 4. 되돌리기 경로

`sev = ratio_sev or abs_sev` 를 `sev = ratio_sev` 로 되돌리면 종전 동작.
`metrics_json` 추가 필드는 **가산적**이라 소비처가 없어도 무해하다.
