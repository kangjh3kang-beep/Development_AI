## §2 순차 계획

### A. 머지 게이트 (3축 · 못 재면 거부)
  A1 필수 목록을 **branch protection 에서 파생**(손 목록 금지 · 매칭 수 ≠ 필수 수 → UNDECIDED)
  A2 `BEHIND` → `update-branch` **한 번에 하나만** → CI 재실행(≈18분)
  A3 재판정: 상태 + **run.head_sha == PR head**(STALE 방지) + `BEHIND` 아님

### B. 머지
  B1 squash merge
  B2 ★산출물 확인 — **브랜치 sha 로 재지 않는다**(스쿼시라 조상이 아니다). `mergeCommit.oid` 로
     `git merge-base --is-ancestor` 판정 + 파일 내용 대조

### C. 배포요청 (보드 = 세션보다 오래 사는 매체)
  C1 대상 **168 백엔드만** · 근거(런타임 델타 web 0)
  C2 ★**DB 마이그레이션 경고**: 이 PR 은 `_ensure` 가 `ALTER TABLE … ADD COLUMN IF NOT EXISTS`
     **6개**를 돌린다. ***실제 Postgres 로 태운 적이 없다*** — 최대 미측정 위험
  C3 ★**새 의존성** `eth-account` — 이미지 빌드에 포함돼야 한다
  C4 ★**앵커 env 3개**(`POLYGON_RPC_URL`·`DRAW_REGISTRY_ADDRESS`·`DRAW_ANCHOR_PRIVATE_KEY`)를
     안 넣으면 앵커링은 `skipped`. **넣을지는 운영 판단**(키를 서버에 두는 문제)
  C5 롤백 자산: `~/rollback.sh`(168 · API+arq 동반)

### D. 검증 — ★**가용성이 아니라 기능**
  D1 배포 **전** 기준선(실측 완료 · 2026-09-13):

        /health                        200 · healthy · version 62.0.0 · postgres/redis/qdrant healthy
        …/draw/groups/<0>/verify       404 · 본문 `{"detail":"Not Found"}`
        …/subscription/<0>/verify      404 · 본문 `{"detail":"Not Found"}`
        대조군 /api/v1/auth/login      405   ← 조회기 생존(있는 경로와 없는 경로를 가른다)
        대조군 /zzz-없는경로            404

  D2 ★★**상태코드로는 가를 수 없다** — 이 함정을 계획 중에 발견했다.
     배포 **후에도** 그 경로는 **404** 다: 존재하지 않는 추첨 id 라 **내 핸들러가 404 를 낸다.**
     ***즉 「404 → 404」 를 보고 「배포 안 됐다」고 오진할 뻔했다.***
     ⇒ **본문으로 가른다**:

        배포 전 : {"detail":"Not Found"}          ← FastAPI 의 라우트 부재
        배포 후 : {"detail":"공약이 없습니다"}      ← **내 핸들러가 응답했다**

     ***이것이 「가용성」과 「기능」의 차이다*** — 정본이 *"25회 이상 「라이브 검증 완료」라고
     보고한 것의 실체는 가용성 검사였다"* 고 적은 바로 그 자리.
  D3 ★기능: 존재하지 않는 추첨 id 로 호출해 **「공약이 없습니다」**가 오는가
     (= 라우트가 살아 있고 **서비스 계층까지 닿았다**는 증거 · 200 만으로는 알 수 없다)
  D4 DB 마이그레이션 실측: 새 컬럼이 실제로 생겼는가
  D5 회귀 대조군: 기존 엔드포인트가 그대로인가

## §3 ★검증하지 못한 것

1. **DB 마이그레이션을 실제 Postgres 로 태운 적 없다** — 배포가 그 첫 실행이다.
   ★**다만 위험이 좁혀졌다**(형제 스윕 실측): 런타임 DDL 은 이 저장소의 **확립된 패턴**이다 —
   `CREATE TABLE IF NOT EXISTS` **38파일** · `ALTER TABLE` **19파일**이 이미 배포돼 있다.
   ⇒ **DB 권한 문제가 아니다.** 남는 위험은 **내 6개 구문 자체**뿐이고 전부 표준 형태다.
   ★그리고 `sales_draw_commitments` 는 **이 배포가 처음 만드는 테이블**이라(추첨 스택 전체가
   미배포) `ALTER` 6개는 방금 만든 빈 테이블에 붙는다 — 기존 데이터 위험 없음.
2. **`eth-account` 설치가 프로덕션 이미지 빌드에서 도는지 미측정**(로컬 venv 에서만 확인)
3. **앵커링은 프로덕션에서 `skipped`** 로 시작한다 — 켜려면 키를 서버에 둬야 하고 그건 별도 판단
4. 통합자 세션이 없어 **요청이 언제 처리될지 미정**
