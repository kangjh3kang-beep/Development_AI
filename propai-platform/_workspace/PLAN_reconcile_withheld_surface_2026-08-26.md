## 2. 처방 — 값·판정 **불변**, 표면만 추가

1. `RollupConsolidated` 에 `reconcile_withheld_count?` · `Reconciliation` 에 `balanced_basis?`·`balanced_absent?`
2. 롤업 배너 — `> 0` 일 때 *"독립 대사 확인 불가 · 현장 N곳"*. **정보색**(경고색 아님)
3. 드릴다운 — 보류 갈래가 **백엔드 사유 문구**를 그린다(화면 상수는 구버전 응답 폴백으로만)

★**경고색을 쓰지 않는 이유**: 보류는 결함이 아니라 **미확인**이다. 13곳 중 11곳이 보류인
정상 운영 상태를 경고로 칠하면 **위양성**이고, 위양성 배너는 곧 무시된다(§A-6).

## 3. 회귀가 아닌 근거

- 기존 키·값·판정 로직 **불변**(추가만). `reconcile_failed_count` 갈래는 손대지 않았고
  **D4 가 그 축의 생존을 따로 단언**한다.
- 프론트 전체 vitest 스위트로 대조(개수가 아니라 **실패 집합**으로 비교).
- 백엔드 무변경 → 파이썬 스위트는 이 변경의 회귀망이 아니다(그래도 로컬을 CI 모집단에 맞춰 뒀다).

## 4. ★검증하지 못한 것 (정직)

- **라이브 화면 확증 불가 — 지금은 원리적으로 못 한다.** 라이브 API 응답에
  `reconcile_withheld_count` **키 자체가 없다**(P3). `#838` 배포 후 캐시를 비우고 재확인해야 한다.
  → **이 PR 을 "라이브 검증 완료"로 읽지 마라.**
- `balanced=false` 갈래는 **라이브 표본 13곳에 한 건도 없다** — D4 는 픽스처로만 확인.
- 표본은 **admin 테넌트 하나**. 다른 테넌트의 보류 비율은 **미측정**.
- 배너 **문구·색이 실제 화면에서 읽히는지**(대비·줄바꿈)는 미측정 — 렌더 테스트는 DOM 만 본다.
