# 계획 — 206필지 **기본 ON 화면의 가독성** (2026-09-04)

★`#954` 는 «끌 수 있게» 를 줬다. 이 계획은 **끄기 전 화면** 자체를 다룬다 —
사용자가 말한 *문제* 는 가독성이었고 토글은 *제안한 해법* 이었다.

## 0. 옵시디언 조회 결과 (§계획게이트 0)

조회기 생존 확인: 사통맵 관련 문서 **82건** · 음성 대조군 **0**.

| 찾을 것 | 결과 |
|---|---|
| 이미 기각된 접근 | **없음** — 개수 기준 롤업을 기각한 기록 0건 |
| 같은 클래스의 앞선 결함 | ★**있다** — `_workspace/PLAN_satong_map_ux_overhaul_2026-07-17.md` **D2**: *"선택 필지 주소 라벨 파일업 — 12필지 주소 텍스트가 지도 중앙에 겹쳐 다른 정보를 가림"* = **같은 결함의 12필지 판**. 그때 처방이 **줌 롤업**이었다 |
| 미결·부채 | 그 계획의 P0 이 «줌 롤업+칩» 이었고 구현됐다(`#351`). **개수 축은 안 했다** |
| 이전 판단의 근거 | `#361` 이 버짓을 48/16 → 96/64/24 로 **상향**했다(«정보 상시화»). 그 주석: *"겹침 방지는 여전히 **버짓 상한**+**선택 라벨 줌 롤업**이 담당한다"* |

★**그 문장이 이 결함의 좌표다.** 설계는 겹침 방지를 **두 기전**으로 선언했는데,
선택 라벨 트랙은 그중 **버짓을 면제**받고 있다.

## 2. 변경 내용과 **회귀가 아닌 근거**

선택 라벨 롤업 조건에 **개수 축**을 더한다 — **새 임계를 지어내지 않고** 기존 버짓을 쓴다:

    롤업 = (줌 롤업 && 다필지)  또는  points.length > satongLabelBudget(zoom)

- **회귀 아님**: 종전에 롤업되던 경우는 그대로 롤업된다(조건을 **더하기만** 한다).
  버짓 이하 선택(대다수)은 **동작 무변화**다.
- 기존 집계 칩 UI 를 **그대로** 쓴다(새 UI 없음).
- P3 의 의도(«레이어 안 켜도 식별») 보존: 칩이 **선택 N필지**를 계속 알린다.

★**왜 뷰포트가 아닌가**: P6·P7. 설계가 명시적으로 배제한 축이고, 그것을 뒤집으려면
이 PR 범위 밖의 성능 판단이 필요하다.

## 3. ★검증하지 못한 것 / 하지 않기로 한 것

- **브라우저 눈 확인** — 라이브 배포 후에만 가능(`#954` 도 아직 미배포).
- ★★**206필지는 어느 줌에서도 개별 라벨이 안 나온다**(206 > 96). 식별은 **필지 클릭**
  (기존 통합 패널)으로 남는다. **이것은 절충이고, 숨기지 않고 여기 적는다.**
  중간 규모(예: 30필지)는 z16→롤업 · z17→개별 이라 **줌이 의미를 갖는다.**
- **뷰포트 기반 필터링**은 하지 않는다(P6).
- **버짓 값 자체를 바꾸지 않는다** — 다른 트랙에 전역 영향이 간다.
