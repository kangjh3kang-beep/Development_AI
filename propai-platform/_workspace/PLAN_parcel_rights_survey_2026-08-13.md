# 토지필지 종합분석 보고서 — 상세 구현계획 (2026-08-13)

디벨로퍼의 **토지작업(land assembly)** 실무를 대행하는 보고서. 다필지를 등록하면 등기·대장을
모아 필지별 권리분석을 하고, **매입 전략(협의매수/매도청구/제척)**으로 필지를 분류한다.

## 1. ★★법적 전제 — 사용자 요구를 한 곳 정정한다

사용자 요구: *"매도청구가 불가능한 보유기간이 1순위 핵심관리필지"*.
방향은 맞지만 **보유기간 단독 조건이 아니다.** `MAGDO_RULES` 실측:

```
주택법 제22조 계열(역세권 장기전세·지구단위계획 연계·역세권 활성화):
    사용권원 95% 이상  → 잔여 **전부** 매도청구 가능 (보유기간 무관)
    사용권원 80~95%    → **10년 미만 보유** 토지에만 매도청구 가능
                        ⇒ 10년 이상 보유 = 매도청구 **불가**

정비사업(도정법 §64) · 소규모정비(특례법 §35) · 도시개발법 §22:
    **동의율** 기준(75~80%). 보유기간 조건 **없음**.
```

### 귀결 — 설계에 직접 반영해야 하는 세 가지

1. **사업방식을 먼저 정해야 1순위 판정이 가능하다.** 방식 미정이면 분류 자체가 성립하지 않는다.
   → 입력에 `scheme`(사업방식)을 **필수**로 둔다. 기본값을 몰래 넣지 않는다.
2. **1순위는 정적 목록이 아니라 확보율의 함수다.** 지금 82%면 10년 이상 보유 필지가 1순위지만,
   95%를 넘기는 순간 **그 지위가 해제**된다.
   → 분류는 스냅샷이 아니라 **현재 확보율 기준 시뮬레이션**이어야 한다.
3. **"매도청구가 가능한 방안"의 정답이 여기서 나온다** — 사용자가 요청한 그 항목이다.
   1순위 필지를 매도청구 대상으로 만드는 유일한 합법 경로는 **확보율 95% 돌파**다.
   → **95% 도달 최소조합 탐색**이 이 보고서의 알고리즘 핵심이다(§2-C).

★이 문단의 수치는 저장소 `MAGDO_RULES` 에서 가져왔다. **하드코딩하지 않고 그 테이블을 참조**한다 —
  법령이 바뀌면 한 곳만 고치면 전역이 따라온다.

### ★★법령 원문 대조 완료 (2026-08-13, 법제처 DRF · 주택법 MST=283191)

정책표의 95%/10년은 **맞다**. 그러나 원문에는 **정책표에 없는 결정적 조건 셋**이 더 있다.
이 셋을 모르고 구현하면 **분류가 틀린다.**

```
제22조(매도청구 등) ①  … 사용할 수 있는 권원을 확보하지 못한 대지(건축물을 포함한다)의
  소유자에게 그 대지를 시가로 매도할 것을 청구할 수 있다.
  이 경우 매도청구 대상이 되는 대지의 소유자와 **매도청구를 하기 전에 3개월 이상 협의**를 하여야 한다.
    1. 주택건설대지면적의 **95퍼센트 이상**의 사용권원을 확보한 경우:
       사용권원을 확보하지 못한 대지의 **모든** 소유자에게 매도청구 가능
    2. 제1호 외의 경우: … 소유자 중 **지구단위계획구역 결정고시일 10년 이전**에 해당 대지의
       소유권을 취득하여 **계속 보유**하고 있는 자(**상속**의 경우 피상속인 소유기간을 **합산**)를
       **제외한** 소유자에게 매도청구 가능
```

**① 10년의 기준일은 "오늘"이 아니라 「지구단위계획구역 결정고시일」이다.**
   정책표 note("10년 미만 보유 토지")는 기준일을 안 적었다. `오늘 − 10년` 으로 계산하면
   **결정고시가 오래된 구역일수록 오분류가 커진다.** → 입력에 `district_plan_notice_date` 필수.

**② 상속 취득은 피상속인 보유기간을 합산한다.**
   최근 상속받은 소유자를 "보유 3년"으로 보면 **매도청구 가능으로 오판**하는데, 실제로는
   피상속인 기간을 더해 10년을 넘으면 **매도청구 불가(=1순위 핵심관리필지)**다.
   → 등기 갑구의 **소유권 이전 원인이 '상속'인지** 판별하고, 전 소유자 보유기간을 합산해야 한다.
   ★이것이 §5-③(소유권 변동 이력)이 **선택이 아니라 필수**인 이유다.

**③ 매도청구 전 「3개월 이상 협의」가 법정 선행요건이다.**
   사용자가 말한 *"1순위 필지는 협의매수가 가장 우선"* 은 전략이 아니라 **법정 절차**다.
   → 보고서는 협의를 권고가 아니라 **필수 선행 단계**로 표기하고, 협의 개시일 기록을 유도한다.

★"매도청구 불가"는 소유자 속성이지 필지 속성이 아니다 — 공유필지는 **공유자별로** 판정이 갈린다.
  → 판정 단위를 필지가 아니라 **(필지 × 소유자)** 로 둔다.

## 2. 분류 체계 (사용자 지시 반영)

### A. 1순위 — 핵심관리필지 (매도청구 불가)
조건: `scheme` 이 주택법 계열 **AND** 현재 확보율 < 95% **AND** 보유기간 ≥ 10년
- **법규상 협의매수가 최우선**(강제수단 없음)
- 산출: 소유자 정보·보유기간·매입금액·근저당(협의 시 말소 조건)·연락 가능성 신호
- **해제 경로 제시**: §2-C 의 95% 도달 조합에 이 필지가 포함되지 않는 대안 경로

### B. 2순위 — 위치 기반 제척 가능/불가
- **외곽(제척 가능)**: 사업구역 경계에 접하고, 빼도 나머지가 **연결성을 유지**하는 필지
- **내부(제척 불가)**: 빼면 구역이 분단되거나 맹지가 생기는 필지 → **반드시 협의**
- 판정: 인접 그래프에서 **절단점(articulation point)** 과 **경계 필지**를 계산
  · 절단점 = 제거 시 그래프가 분리 → 제척 불가
  · 경계 필지 = 외부와 접함 → 제척 후보

★★**이 알고리즘은 이미 구현돼 있다** — `app/services/zoning/parcel_graph.py`(W2-5):
  `_articulation_points`(제거-재탐색 O(V·(V+E))) · `_components`(BFS) · `is_parcel_adjacent`
  (shapely 폴리곤, 톨러런스 SSOT ~6m) · N-1 시나리오 · `_contact_length`.
  모듈 docstring 이 스스로 목적을 이렇게 적는다 — *"어떤 필지가 인접에 핵심적인지(제거 시
  끊기는지)"*. **제척 불가 판정과 같은 문제다.**
  → P2 는 **알고리즘 신규 개발이 아니라 재해석**이다: articulation point = 제척 불가,
    비-articulation + 경계 = 제척 가능. 새로 만들면 같은 판정이 두 곳에 생겨 갈라진다.
★geometry 미확보 필지는 `parcel_graph` 가 이미 **'geometry 미확보'로 명세**한다 —
  그 표기를 그대로 승계해 "판정 불가"와 "제척 가능"을 섞지 않는다.

### C. 매도청구 가능화 경로 (95% 돌파 탐색)
- 목표: 면적 기준 사용권원 95% 도달
- 탐색: 미확보 필지 중 **최소 비용·최소 건수 조합**으로 95%를 넘기는 집합
- 산출: "이 3필지를 먼저 확보하면 나머지 전부에 매도청구 가능" 형태의 실행 지시

### D. 최종 판정표 (필지별 1행)
```
필지 | 소유자 | 보유기간 | 매입금액 | 근저당/가등기 | 건물유무
     | 매도청구 가부 | 분류(1순위/제척가능/제척불가) | 권고 액션
```

★**액션은 셋 중 하나로 수렴한다**: 협의매수 / 매도청구 / 제척.
  "협의매수 불가 + 제척 가능" → **제척 대상지**(사용자 지시 그대로).
  "협의매수 불가 + 제척 불가" → **최고 리스크**로 별도 경고(사업 성립 자체가 걸린다).

## 3. 단계 계획

| 단계 | 내용 | 이유 |
|---|---|---|
| **P0** | 다필지 등록 → **견적·선별** 화면. 등기 없이 되는 정보(공부·대장·실거래·인접성) 먼저 | 비용 사고 방지 |
| **P1** | 선택 필지 **병렬 발급·권리분석** + 필지별 카드 | 기존 엔진 조립 |
| **P2** | **매입전략 분류**(§2 A·B·C) | 신규 알고리즘 |
| **P3** | 건물 있는 필지: 건물 등기·대장 결합 | 토지·건물 별개 발급 |
| **P4** | 종합 보고서 문서화 + 매입 실행 요약 | 기존 렌더러 재사용 |

### ★P0 를 먼저 하는 이유 (비용)
필지당 **3,200원**(발급 1,200 + 분석 2,000), 건물 있으면 ×2.
**20필지 = 64,000원 · 건물 포함 최대 128,000원.**
견적 게이트 없이 P1 을 먼저 만들면 **첫날에 사고가 난다.** 사용자 승인도 (b) 안이었다.

## 4. 성장루프 결속

이 보고서는 **사용 결과가 다음 판단을 개선**해야 한다(성장루프 취지).
- 분류 결과와 **실제 매입 성사 여부**를 `capture_service` 로 적재
- `analyzer` 가 "1순위로 분류했는데 협의 성사" / "제척 권고했는데 매입 성공" 같은
  **판정 대비 실제** 신호를 집계
- 즉 이 기능은 **읽기 전용 보고서가 아니라 학습 표면**이다

★단, 적재는 **best-effort**로 붙인다 — 성장루프 실패가 보고서를 막으면 안 된다.

     → `scheme` 만으로 갈리지 않는다. **시행자 유형·관리지역 여부**가 분류를 뒤집는다.

   · **도시개발법 §22** — 민간시행자는 **면적 2/3 + 소유자 총수 1/2 동의**(정책표 일치). 다만
     이것은 **매도청구가 아니라 수용**이고 「토지보상법」을 준용한다(협의→재결→보상).
     정책표 note 의 *"매도청구에 준함"* 은 **절차가 다르므로 부정확**하다.
     ★공공(제11조 1~4호)이 **50% 초과 출자**면 동의요건 자체가 면제된다.

     같은 번호로 딸려 오고 `조문제목=None`). **첫 매치를 쓰면 틀린다** — 전건을 훑어
     `조문제목`이 있는 것을 골라야 한다. 실제로 이 실수로 "조문 없음"이라 오판할 뻔했다.
2. **법적 성격** — 말소기준권리·인수/소멸 판정은 **면허 업무(법무사·감정평가사) 영역**에 인접한다.
