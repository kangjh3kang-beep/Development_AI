## §2-0 ★내 전제가 틀렸다 — 「분양가」와 「실거래가」를 섞어 썼다

초판에서 나는 사용자의 **6.13억**을 «시장 관측»으로 인용하고 *"괴리 1.0%"* 라고 적었다.
**그 6.13억은 MOLIT 신고 7건 중 최저가**였고, 사용자가 말한 시장가는 **8억+** 다.
사용자 지적으로 갈렸다: ***분양가와 실거래가는 다르다.***

### 라이브 원문 — 중앙값을 만든 7건 전부

    202602  빌리브센트하이  전용 84.98㎡  6.46억   전용평당 2,513만원
    202602  빌리브센트하이  전용 98.84㎡  6.87억   전용평당 2,297만원
    202603  빌리브센트하이  전용 84.98㎡  6.96억   전용평당 2,709만원
    202606  빌리브센트하이  전용 98.84㎡  7.28억   전용평당 2,436만원  ← 중앙값
    202607  빌리브센트하이  전용 98.84㎡  7.03억   전용평당 2,351만원
    202607  빌리브센트하이  전용 84.86㎡  6.39억   전용평당 2,491만원
    202608  빌리브센트하이  전용 84.98㎡  6.13억   전용평당 2,387만원

★**MOLIT 신고 최고가가 7.28억**이다. 사용자 현장관측 8억+ 와 **갈린다.**

### 괴리는 **두 축이고, 곱해진다**

| 축 | 현재 | 교정 시 | 배수 |
|---|---|---|---|
| **데이터** — MOLIT 신고 vs 현장 | 84㎡ 중앙값 **6.43억**(전용평당 2,500) | **8.00억**(전용평당 3,112) | **+24%** |
| **전용률** — M07 vs M06 | ×0.60 → 1,462만원/평 | ×0.75 → 1,827만원/평 | **+25%** |
| **합성** | **1,462만원/평** | **2,334만원/평** | **+61%** |

★사용자 기대치 역산(8억 ÷ 공급 34평) = **2,353만원/평**. 두 축 교정값 2,334 와 **0.8% 오차**.
**두 축을 다 고쳐야 사용자 관측에 닿는다** — 하나만 고치면 여전히 25% 남는다.

### ★데이터 축의 괴리 원인은 **미측정**이다(가설 셋, 죽이지 못했다)

1. **호가 vs 실거래** — 사용자가 본 8억이 네이버 매물 **호가**일 수 있다
2. **신고금액의 성격** — 분양권 전매 신고액이 프리미엄 미포함/다운계약일 수 있다.
   파서는 `dealAmount` **하나만** 읽는다(다른 금액 필드를 원천이 주는지 **미확인**)
3. **신고 지연 30일** — 최신 월이 항상 불완전. 상승장이면 중앙값이 **뒤처진다**

★셋 중 무엇이든 **처방은 같다**: 시스템이 «신고 기준·후행 지표»임을 **근거에 밝히고**,
현장 관측을 **사용자가 넣을 수 있게** 한다. 계수를 지어내지 않는다.

## §2 근본원인 — 두 개다(하나가 아니다)

### R1. 유형 자동선정이 사용자에게 잠겨 있다 (배선 · **즉시 처방 가능**)

개발유형 Top1 = **주상복합(M07)** → 전용률 0.60. 사용자가 아파트(M06)로 볼 근거가 있어도
바꿀 수 없다. **백엔드는 이미 `dev_type` 을 받는데 프론트가 안 보낸다.**
`_exclusive_ratio_for` 독스트링이 *"파이프라인은 아직 못 갖는다"* 고 **부채로 적어 둔 그것**이다.

### R2. 전용률 차이를 **전액** 가격에 반영한다 (모델링 · **판단 필요**)

비교사례는 **아파트 분양권**(전용 기준), 대상은 **주상복합**. 대상 전용률만 곱하는 것은
*"매수자는 오직 전용평당가로 값을 매긴다"* 는 가정이고, 이는 **최대 할인**(−19%)을 만든다.

★반대 극단은 *"매수자는 공급평당가로 값을 매긴다"*(할인 0). 실제 시장은 그 사이다.
도보 역세권 주상복합이 인근 신축 아파트보다 **공급평당 19% 싸게** 팔린다는 근거는
이 측정에 없다. **N=1 이므로 계수를 지어내지 않는다** — 대신 **사용자가 고르게 한다**.

## §3 변경 내용

### W1 — 입력요약을 **편집 가능**하게 (요구 ②의 본체)

`RoughScenarioPanel` 입력요약 8칸 중 **산정에 실제로 쓰이는 축**만 편집 대상으로 연다.

| 칸 | 편집 | 배선 |
|---|---|---|
| **개발유형(Top1)** | **select**(M01~M15 정본표) | `buildBody` 에 `dev_type` 추가 — **백엔드 무변경** |
| **전용률** *(신규 칸)* | number | `overrides.exclusive_ratio` — 백엔드 신규 |
| 연면적(GFA) | number | `overrides.gfa_sqm` — 백엔드 신규 |
| 분양가능면적 | number | `overrides.saleable_area_pyeong` — 백엔드 신규 |
| 사업기간 | 기존 override 존재 | 표시칸에서도 바로 편집 |
| 통합면적·용도지역·실효용적률·필지수 | **읽기 전용 유지** | 필지 선택의 산출물 — 여기서 고치면 지도와 갈린다 |

★**「전부 열기」를 하지 않는다.** 상류(필지·용도지역)에서 파생되는 값을 하류에서 덮으면
지도·법규 판정과 **조용히 갈린다**. 파생값은 상류에서 고친다.

### W2 — 기존 8개 override 를 **보이게** (요구 ②의 절반)

`분양단가(원/평)` 직접입력은 **이미 있다**. 사용자가 못 찾았다 = 발견성 결함.
→ ①입력요약 칸에서 해당 override 로 **직접 점프**(앵커) ②override 가 적용 중이면
입력요약 칸에 **「직접입력」 배지**를 띄운다(현재 `overrides_applied` 가 응답에 이미 있다).

### W3 — 전용률 반영 강도를 **노출**(R2)

`overrides.exclusive_ratio_pass_through`(0.0~1.0, 기본 **1.0 = 현행**) 신설.

    공급평당가 = 전용평당가 × (1 − p·(1 − 전용률))       p=1 → 현행(0.60 적용)
                                                        p=0 → 공급기준 동등(할인 없음)

★**기본값을 바꾸지 않는다**(무회귀). 사용자가 근거를 갖고 조정한다.
★근거 문자열에 `p` 와 그 뜻을 **반드시** 싣는다(원장에 영속되므로).

### W4 — 세대수 축 비정합(§1-11) *— 별도 PR*

`세대수 = GFA / 표준전용` 은 **전용률을 안 쓴다**(GFA 100%를 전용으로 취급).
정합식은 `GFA × 공급비 × 전용률 / 표준전용` = 249 → **105세대**.
★인입공사비(전기 6,225만·가스 4,482만·통신 1,992만)가 세대수 기반이라 **함께 움직인다**.
범위가 다르고 회귀 위험이 크므로 **이 PR 에 넣지 않는다** — `it.todo`/`xfail` 로 초록 안에 남긴다.

## §4 ★검증하지 못한 것

- **R2 의 「옳은 p」는 측정하지 못했다.** 마석 지역 주상복합↔아파트 공급평당가 대조 표본이
  없다(분양권 전매 표본 7건은 전부 아파트). **그래서 계수를 지어내지 않고 노출만 한다.**
- **화면 렌더 확인 미측정** — 이 계획의 변경 후 실제 화면은 아직 안 봤다(구현 후 필수).
- **M07 전용률 0.60 의 시장 타당성** 자체는 재지 않았다. 정본표를 **바꾸지 않는다**
  (바꾸면 15유형 전 경로가 움직인다 — 범위 밖).
- 화면의 「**× 0 비율**」 표기(설계비 24.4억인데 산출내역 `× 0 비율`)는 **이 계획 범위 밖**.
  값은 맞고 비율 표기만 0 이다 — 별도 관측으로 기록.

## §6 되돌리기 경로

- W1·W2 는 **프론트 단독**(백엔드 무변경) → 해당 커밋 revert 로 완전 복구.
- W3 은 백엔드 신규 파라미터이나 **기본값이 현행과 동일**하므로, 미전달 시 산출물 무변화.
  파라미터를 제거해도 기존 호출부는 영향 없음.
- 정본표(`unit_standards`)와 `_GFA_TO_SALEABLE_RATIO` 는 **건드리지 않는다** — 전 경로 파급.
