## 3. 이 저장소의 층위 계약 (정본: `apps/web/lib/satong-map-z.ts`)

```
지도 오버레이(≤500) < 본문 sticky(600) < 네비 플라이아웃(700) < 모달(800) < 앱 크롬(1000)
                                                            전체화면(9990)만 크롬 위
```

**층위를 건드릴 때 반드시 알 것**:
- 지도 래퍼는 **스태킹 컨텍스트를 만들지 않는다** → 오버레이가 루트에서 본문과 경쟁한다
- **z 를 올려도 소용없는 경우가 있다**(컨텍스트에 갇히면) — 컨텍스트 자체를 봐라
- 감시망(`__tests__/layer-ladder.contract.test.tsx`)은 **`fixed inset-0` 백드롭**만,
  **리터럴 className** 만, **시드 임포트 파일의 아래 폐포**만 본다. 못 보는 것은 `it.todo` 4건에
  전부 적혀 있다 — **읽고 시작하라. 안전해 보이게 쓰여 있지 않다.**

## 4. 재생성 금지 — 이미 반증한 것

1. "비리터럴 className 파서를 만들자" → **3라운드 연속 위양성**을 생산했고, 지키는 대상은 전
   저장소 1건(그마저 준수)이었다. **대상 축을 고친 뒤** 실사례를 다시 세고 나서 재론할 것
2. "블록 주석을 정규식으로 지우자" → **수백 파일 실코드를 삼켰다**. #584 의 **TS 파서**를 써라
3. "폐포 크기 하한으로 배선 회귀를 잡자" → 80→130→150→100 으로 **네 번 뒤집혔다**.
   회귀는 `mustInclude`(경로 형태별)가 진다. 하한은 "폐포 붕괴"만 본다
4. "감시망을 한 번 더 봉합하면 된다" → 봉합 5회 중 4회가 **새 결함**을 낳았다.
   지키는 대상 수와 만든 결함 수를 세고 **범위를 줄이는 쪽**을 먼저 검토하라
5. "InputResolveModal 이 z-600 ContextHeader 에 덮였다" → **거짓**. 그 모달의 두 화면 어디에도
   `showContextHeader` 가 켜져 있지 않다(진짜 상대는 지도 오버레이 380~500)

## 5. 작업 방식

실측 → `/insight-loop` 으로 **독립 렌즈를 병렬로 돌려 문제를 생성**시킨다(자기 리뷰는 같은 축
안에서만 돈다 — 이번에 대상 축의 구멍은 렌즈를 나눠서야 나왔다) → 구현 →
**커밋 먼저 → 변이(본체 도구) → 원복** → 게이트 → 독립 적대검증(자기승인 금지) → 봉합 →
머지 → sw 범프(보드 claim 확인 — 통합자가 선점했을 수 있다) → 배포 → **라이브 검증** → 옵시디언 기록.
한국어 보고, 무목업·완결게이트 준수.

★**가드가 있다"와 "경쟁 상대가 있는 상태에서 이겼다"는 다르다** — 라이브 검증에서 조건부 요소는
그 상태를 만들어서 재라(이번에 레일을 안 연 채 재서 공허한 통과가 나왔다).
★**수치를 옮겨 적지 마라.** 이 캠페인에서 재실측 없이 옮긴 수치가 **세 번** 틀렸고, 그중 하나는
틀린 근거로 고른 하한이 회귀를 통과시켰다. **기각할 때도 실측이 필요하다.**
