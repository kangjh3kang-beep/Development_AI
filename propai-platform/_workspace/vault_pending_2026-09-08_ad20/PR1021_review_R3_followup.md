## 1. 무엇이 문제였고 어떻게 고쳤나

### M1 — 위계 판정이 라우터에 **두 벌**이었다

앞 판은 «루트는 AGENCY 만» 규칙만 `create_node` 로 내리고 **위계 규칙은 라우터에 남겼다**.
이 PR 의 논지가 *«두 생산자가 정반대 규칙을 갖는다»* 인데 **절반만 실행한** 셈이다.
파생형 전수(`_ORG_RANK` 소비처)로 재니 판정이 `actions.py` 안에 두 벌이었다 —
`add_node`(생성) · `move_node`(이동). 라우터를 안 거치는 생산자는 어느 쪽도 안 봤다.

처방: `_ORG_RANK` · `assert_hierarchy()` 를 `app/services/sales/org/service.py` 로 이관(SSOT).
★**서비스 층에 두면 라우터가 임포트하는 방향**이 되어 순환이 없다(반대는 순환이다).
`create_node` 가 위계를 직접 강제하고, 라우터 두 벌은 그 함수 호출로 대체.

### M2 — «연결 안 됨» 한 값이 여섯 상황을 덮었다

`_link_membership_on_accept` 는 `bool` 을 돌려줬고 **적용대상 아님 · 권한 없음 ·
조직도 미시드 · 조직 테이블 미존재 · 멱등 무변경**이 전부 같은 `false` 였다.
조치가 전부 다르고, 특히 `ORG_NOT_SEEDED` 는 **해결 가능한 보류**(조직도를 시드하고 다시 승인)인데
라이브 현장 대부분이 조직도 미시드라 **그게 기본 경로**였다.

★★그리고 **화면은 그 `false` 마저 읽지 않고 버렸다**(`.then(() => loadApps())`) — 소비처 0.
승인자는 «승인은 됐는데 조직도엔 아무도 없다» 를 **원인 없이** 마주쳤다.
*«진단 불가는 그 자체로 장애다»* 를 정확히 밟은 것.

처방: 사유 8종으로 분리(`_MEMBERSHIP_REASONS` = SSOT) · `membership_linked` 는 사유에서 **파생** ·
프론트가 사유를 사람 말로 옮기고 **실제로 렌더**(모르는 사유도 말을 한다).

### B2 — 계획서가 선언한 락 4개 중 **3개가 존재하지 않았다**

§5 를 **파일::함수** 로 다시 쓰고, 이름을 댈 수 없는 줄은 **부채 표**로 내렸다.
선언만 있던 두 축(raw INSERT 재등장 · 소프트삭제 누락)은 실제 락으로 만들었다.

## 2. ★★핵심 교훈 — 락을 정교화하지 말고 구조를 바꿔라

기계 변이가 라우터 검증 블록에서 계속 살아남았다:

```
if mnode:              → `if False:` ::VERDICT=SURVIVED   ← 검증이 통째로 꺼진다
mnode = mnode_uuid     → 줄삭제      ::VERDICT=SURVIVED   ← 검증은 돌지만 결과가 버려진다
```

**두 번째가 더 나쁘다.** 「검증했다」와 「검증한 것을 썼다」는 **다른 명제**인데
라우터에서는 두 줄이라 갈렸다 — 검증은 정상으로 돌고, 그 결과 대신 **원문 문자열**이
계약으로 흘러간다.

★★**내가 넣은 AST 배선 락도 못 잡았다.** «호출이 존재하는가» 를 잠갔는데
**`if False:` 안에서도 호출 노드는 AST 에 남는다.**
«존재를 잠그면 행위는 안 잠긴다» 가 AST 층에서 재현된 것이다.

⇒ 세 번째에 **락 대신 구조**를 바꿨다. 셋(빈 값 분기·UUID 파싱·검증 호출)을
`resolve_member_node(db, site_id, raw) -> UUID | None` **한 값 흐름**으로 묶었다.
어느 조각을 꺼도 **반환값이 달라져** 호출부에서 즉시 드러난다.
재측정: 등가 약화 변이 3종 전부 CAUGHT(결과 버리기 · 검증 건너뛰기 · 예외 삼키기).

## 3. 내가 이번 라운드에 틀린 것

1. **손 변이 9/9 CAUGHT 였고 거짓말하는 필드를 못 봤다.** 기계 변이 60건이 찾았다 —
   거절 경로가 `NOT_APPLICABLE`(«현장 비연계 공고라 멤버십이 생길 일이 없다»)을 실었다.
   내가 M2 를 고치며 **만든** 결함이다. ⇒ `DECLINED` 신설.
   ***«변이의 분모를 누가 정했나 — 도구인가 나인가»*** 를 CAUGHT 보고 **전에** 물어야 한다.
2. **브랜치 HEAD 가 `ruff` 8건 빨강이었다** — 필수 **차단** 게이트인데, 리뷰 대응을
   세 라운드 하는 동안 몰랐다. CI 와 같은 명령·같은 버전(0.16.3)으로 한 번 돌리면 즉시 나왔다.
   ⇒ **차단 게이트의 현재 상태를 착수 전에 재라.**
3. **소스 스캔 락이 주석에 위양성**을 냈을 뻔했다. 파일 전체를 소문자로 훑으면
   *"raw INSERT 를 쓰지 마라"* 라고 **경고하는 주석**이 위반이 된다. AST 문자열 리터럴로 좁혔다
   (독스트링도 뺐다 — 이 PR 의 `create_node` 독스트링이 사고 경위를 SQL 로 적고 있어
   **정본 파일이 자기 락에 걸릴** 뻔했다).

## 5. 미측정 · 부채 (정직하게 남긴다)

- **승인 경로 DB 통합 테스트 부재** — 조직 트리는 postgres+ltree 가 필요한데 로컬에 없다.

  **락을 더 써도 못 잡는다**(대역은 SQL 을 해석하지 않는다).
- **`test_contract_create_actually_validates_the_member_node` 는 로컬에서 한 번도 실행되지 않았다.**

  `datetime.UTC` 셰임으로 우회를 시도했으나 SyntaxError 라 원리적으로 불가 ⇒ **CI(3.12)에서 처음 실행**.
  ★같은 축을 임포트 없이 보는 AST 락과 서비스 층 행위 락이 로컬에서 돌아 이 부채를 덮는다.
