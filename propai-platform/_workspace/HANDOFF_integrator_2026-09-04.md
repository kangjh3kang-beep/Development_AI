## 3. ★작업 방식 — 그대로 쓰면 되는 것 다섯

1. **배포와 확증을 다른 세션이 나눈다.** 같은 세션이 둘 다 하면 **대조군이 없다.**
   실행=`development-ai-62`(사용자 위임 · ssh 보유) · 확증=통합자.
   **118·119·120·121 네 주기 연속 갈린 축 0.**
2. **확증은 3축 + 음성 대조군**:
   ①캐시명/빌드id(★앵커) ②배포 前에 찍은 불변값 ③**머지커밋이 main 의 조상인가** + 잔여 0.
   ★**「호스트 HEAD == main HEAD」를 축으로 쓰지 마라** — 큐가 도는 동안엔 **정상에서도 어긋난다.**
3. **침묵을 동의로 읽지 않는다.** 남의 PR 은 **보드 claim + 소유자의 명시적 「진행해도 좋다」**.
   무응답은 **대기**다. ★소유자 판정에 **`author`(전 PR 동일 계정) · 세션 이름 · 워크트리 존재 ·
   기억**을 쓰지 마라 — **넷 다 구별력이 없다**(내가 이 축에서 세 번 데였다).
   ✔ 쓸 수 있는 것: **보드 claim** · **계획서 절대형 서명**(`작성: development-ai-XX · 날짜`).
4. **CI 초록 ≠ 편집 완료.** 소유자가 «끝났다» 하기 전엔 밀지 않는다.
   실제로 `#960`·`#962` 는 4/4 초록 뒤에도 소유자가 새 커밋을 밀었다.
5. **한 번에 하나만 `update-branch`.** `strict=True` · `enforce_admins=True`(**재서 확인함**) —
   BEHIND 는 실제로 머지를 막고 **관리자도 우회 못 한다.** 무엇이든 머지하면 main 이 움직여
   다른 갱신분이 버려진다. ★**아직 배포 안 된 web PR 이 있으면 다음 web PR 과 묶어라**(배포 1회 절약).

### ★도구 함정 — 이 저장소에서 **실제로 걸린 것**

    gh pr edit --base   → **rc=0 인데 안 바뀐다**(Projects GraphQL). ★`gh api -X PATCH` 를 써라.
    grep -c … || echo 0 → 0건일 때 exit 1 이라 **둘 다 실행돼 "0\n0"**. `wc -l` 을 써라.
    cmd | tail          → 파이프 끝의 rc 를 준다. **파일로 받고 `$?`** 를 읽어라.
    변이 판정어         → **줄 시작 앵커**로 읽어라(`^(CAUGHT|SURVIVED)`). `head -1` 은 **도구 설명문**을 집는다.
    변이 판정 불가 코드 → **12·13·14·15·16** 은 **CAUGHT 로 세지 마라**(`#957` 이 도입).
    ★모든 외부 변경 명령은 **산출물을 다시 읽어** 확인한다. 종료코드는 근거가 아니다.
