## 2. ★내 앞선 보고 정정

보드 NOTE 와 사용자 보고에 *"C07 과 농지보전부담금 **둘 다** 미조회를 미지정으로 단정한다"* 고
적었다. **농지 쪽은 거짓**이다(전제 ⓔ). **실제 결함은 C07 하나.**
→ *"둘 다 ~하다"* 는 **두 번 확인해야 쓸 수 있는 문장**이다. 하나를 보고 나머지를 유추하면
그 유추가 보고서에 **관측처럼** 실린다.

## 3. 변경 내용 — **값이 아니라 주장을 고친다**

세 상태로 가른다. **금액은 셋 다 그대로**(안전측 0 유지 — 값 변경과 배선 수정을 한 커밋에
섞지 않는다). 바뀌는 것은 **우리가 무엇을 아는지에 대한 주장**이다.

    True   지정 확인            → 부과
    False  **조회했고** 해당 없음 → 미부과(확정)
    None   **미조회**            → 미부과(잠정) · confidence="unavailable"

전 경로에 전파(전제 ⓕ). `parse_tristate_flag` 를 `parse_bool_flag` **옆에 새로** 둔다 —
그 함수의 **다른 소비처가 같은 의미를 원하는지 모르므로** 계약을 바꾸지 않는다.

### 회귀가 아닌 근거

- **금액 무변화**: 세 상태 모두 기존과 같은 `amount_won`. 기존 테스트 `test_c07_in_zone_*` ·
  `test_sale_stage_default_excludes_infra_charge` 전부 통과(실측: 부담금 계열 **491 passed**).
- `parse_bool_flag` **무변경** — 다른 게이트 소비처 무영향.
- 추가되는 키는 `detail.surveyed` 와 (미조회일 때만) `confidence` — **additive**.

## 4. ★검증하지 못한 것

1. **누가 이 값을 넣을 것인가** — 지역지구 designation → 게이트 다리는 **이 PR 밖**이다.
   즉 배포 후에도 **여전히 전 사업이 `None`(미조회)** 이다. 달라지는 것은 **그렇다고 말한다**는 것뿐.
2. `""`(빈 문자열)을 `None` 으로 본 판단 — **입력했다 지운 것**과 **미입력**을 구별할 수단이 없다.
   안전한 쪽(모른다)을 택했으나 **사용자 의도는 미측정**이다.
3. 화면이 `confidence="unavailable"` 을 **어떻게 그리는지** — 프론트 소비 미확인.
4. `detail.surveyed` 를 읽는 하류가 생길지 — 지금은 **테스트만** 읽는다.
5. 라이브 종단 미실측.
