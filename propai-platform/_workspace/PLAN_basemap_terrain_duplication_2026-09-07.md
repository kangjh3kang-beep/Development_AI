## 1. 전제 표 — 확인 방법과 **실측값**

| # | 전제 | 확인 방법 | **실측값** |
|---|---|---|---|
| P1 | 두 UI 의 항목이 겹치나 | 두 정의 원문 | 베이스맵 `일반·위성·하이브리드·회색`(4) / terrain `기본지도·위성·항공뷰·표고·회색지도`(5) |
| P2 | ★**컨트롤 id 까지 같나** | `BASEMAP_SWITCHES` ↔ `terrain.controls` | ★**4/5 가 동일 id**: `base`·`satellite`·`hybrid`·`gray`. 「하이브리드」와 「항공뷰」는 **같은 `hybrid` 에 붙은 다른 라벨** |
| P3 | ★**같은 코드를 부르나** | 스위처 onClick 원문 | ★**그렇다** — `handleLayerControlClick("terrain", { id: opt.id, … })`. 문자 그대로 같은 핸들러·같은 저장 위치(`controlsByLayer.terrain`) |
| P4 | 배경 결정이 한 곳인가 | `resolveVWorldBaseLayer()` | **하나**다. 두 UI 가 같은 상태를 써서 같은 함수가 읽는다 |
| P5 | 고유한 것이 있나 | `terrain.controls` 차집합 | **`elevation`(표고) 하나뿐**이고 `mapEffect: false` = **미구현**. 자기 설명이 *"표고/경사도 격자 원천 연결 후 활성화"* |
| P6 | terrain 레이어를 사용자가 끌 수 있나 | `LAYERS_WITHOUT_POPOVER_TOGGLE` | **아니다** — `["terrain"]`. 주석: *"끄면 배경지도가 조용히 롤백·라벨도 거짓"*. 락도 있다(`basemapSwitcher.test.tsx:282`) |
| P7 | 스위처가 레이어 정의를 참조하나 | 스위처 onClick | ★**아니다** — 컨트롤 객체를 **인라인으로 만든다.** 그래서 `terrain.controls` 에서 항목을 빼도 **스위처는 영향받지 않는다** |
| P8 | 배타 전환 목록의 형태 | `setLayerControls` | ★**손 목록**이다: `["base","satellite","hybrid","aerial","gray"]`. **`aerial` 은 현재 컨트롤에 없는 레거시 id**(`resolveVWorldBaseLayer` 는 아직 받는다) |
| P9 | `status` 를 무엇이 소비하나 | 소비처 파생 | 배지 문구(`활성`/`준비`/`연동 필요`)와 안내 한 줄뿐. **어휘 전수**: `active` 10 · `idle` 3 · `needs-source` 1 · `ready` 1 · `running` 1 |

### ★P2·P3 이 이 PR 의 근거다

사용자가 *"같은 기능 아닌가"* 라고 물었고, **같은 기능이 아니라 문자 그대로 같은 컨트롤**이다.
같은 id 를 같은 핸들러로 같은 저장 위치에 쓰고 같은 함수가 읽는다. 라벨만 둘이다.

### ★P5 — 「지형도·항공뷰」라는 이름이 이미 거짓이다

레이어 설명은 *"경사, 고저차, 항공사진을 사업 리스크와 설계 제약에 반영합니다"* 인데,
**경사·고저차를 주는 컨트롤(`elevation`)은 미구현**이고 나머지는 전부 베이스맵 전환이다.
즉 이 레이어는 **자기 주제를 하나도 수행하지 않으면서** 다른 UI 의 복제본을 들고 있다.

## 2. 변경 내용과 **회귀가 아닌 근거**

### 2-a. `terrain.controls` 에서 **중복 4종을 걷어낸다** (`elevation` 만 남긴다)

회귀가 아닌 근거 — **P7**: 스위처는 컨트롤 객체를 인라인으로 만들므로 레이어 정의를 참조하지 않는다.
따라서 **베이스맵 전환 기능은 그대로 살아 있고**, 사라지는 것은 «같은 것을 두 번째로 보여 주던 화면»뿐이다.

### 2-b. 레이어의 **이름·설명·상태를 사실과 맞춘다**

| 항목 | 현재 | 바꿈 | 사유 |
|---|---|---|---|
| `label` | 지형도·항공뷰 | **표고·경사** | 항공뷰를 더 이상 소유하지 않는다(§P5 — 이미 거짓이었다) |
| `shortLabel` | 지형 | 표고 | 같음 |
| `description` | 경사, 고저차, **항공사진**을 … | 항공사진 문구 제거 | 같음 |
| `source` | VWorld WMTS 프록시 연동(기본·위성·**항공뷰**) | 표고/경사도 격자 **미연동** | 같음 |
| `status` | `ready`(배지 «준비») | **`needs-source`**(배지 «연동 필요») | 유일한 컨트롤이 미구현이다. `ready` 는 거짓 |

★`needs-source` 는 **이 파일에 이미 있는 어휘**다(`roadview`). 새 어휘를 만들지 않는다.

### 2-c. 배타 전환 목록을 **파생형으로** 바꾼다 (P8)

`["base","satellite","hybrid","aerial","gray"]` 손 목록 → `BASEMAP_SWITCHES` 에서 파생 + 레거시 `aerial`.
★그리고 **베이스맵 id 일 때만** 배타 처리한다 — 지금은 terrain 의 **아무 컨트롤**이나 누르면 배타 분기를
타므로, `elevation` 이 나중에 구현되면(`mapEffect: true`) 그 클릭이 **사용자의 베이스맵 선택을 지운다.**
지금은 `mapEffect:false` 라 도달 불가이므로 **오늘의 결함은 아니고**, 걷어내는 김에 구조로 막는다.

### 2-d. ★**하지 않는 것**

- **`resolveVWorldBaseLayer` 를 건드리지 않는다.** 저장 위치(`controlsByLayer.terrain`)도 그대로다
  → **persist 마이그레이션 불필요**(기존 사용자의 베이스맵 선택이 그대로 산다).
- **베이스맵 팝오버를 건드리지 않는다** — 사용자가 요청한 표면이다(§0).
- **`terrain` 레이어의 on/off 노출을 열지 않는다**(P6) — 끄면 배경지도가 조용히 롤백된다.
  ★그 롤백은 **오늘 도달 불가**이고(토글 미노출 + 스위처가 `ensureLayerEnabled` 를 부른다), 이 PR 은 그 상태를 유지한다.

## 3. ★검증하지 못한 것

1. **화면(브라우저) 실측 없음** — 락은 렌더 테스트로 건다. 라이브 확인은 배포 후.
   ★그리고 `SatongMapShell` 은 렌더 테스트가 있지만 **`SatongMultiMap` 의 effect 본체는 무잠금**이다
   (#1012 실측: Leaflet 목이 없어 `false` 변이가 64파일 468건을 전부 통과). 이 PR 은 셸 쪽이라
   렌더 락이 유효하지만, **배경지도가 실제로 바뀌는지**는 브라우저가 있어야 안다.
2. **`elevation` 을 언제 구현할지 미정** — 이 PR 범위 밖. `status: needs-source` 로 **초록 안에 보이게** 남긴다.
3. **`aerial` 레거시 id 를 쓰는 저장분이 실재하는지 미측정** — `resolveVWorldBaseLayer` 가 아직 받으므로
   **제거하지 않고 그대로 둔다**(가를 수 없으면 가르지 않는다).
4. **성장루프 관측(인접)**: `/api/v1/tiles/vworld/wmts/Satellite/…` 가 `latency_regression` **warn**
   (p95 561ms · 평소 299ms · 표본 47). 이 PR 과 **인과 관계 없음**(런타임 타일 경로를 안 바꾼다) —
   별건 관측으로만 적는다. **미측정**: 원인.

## 5. 잠금

| 잠그는 명제 | 형태 |
|---|---|
| ★**중복이 사라졌다** | `terrain.controls` 의 id 집합 ∩ `BASEMAP_SWITCHES` 의 id 집합 = **∅** |
| ★**두 모집단** | 그런데 **베이스맵 스위처는 여전히 4종을 그리고 동작한다**(사라진 것과 남은 것을 같은 실행에서) |
| **기능이 안 죽었다** | 스위처 클릭 → `resolveVWorldBaseLayer` 가 실제로 그 값을 돌려준다(라벨이 아니라 **값**) |
| **이름이 사실이다** | label·description·source 에 「항공뷰/항공사진」 **0건**, `status === "needs-source"` |
| ★**배타는 베이스맵 id 에만** | 베이스맵 id 는 서로를 지우고, **비-베이스맵 id 는 베이스맵 선택을 지우지 않는다** |
| **파생형** | 배타 목록이 `BASEMAP_SWITCHES` 에서 파생 — 스위처에 항목이 늘면 자동으로 따라온다 |
| **레거시 보존** | `aerial` 이 여전히 배타 집합에 있다(§3-3 — 가를 수 없으므로 남긴다) |

★**변이로 CAUGHT 를 확인한다.** ★**닫지 못하는 것**: 브라우저 실측(§3-1) · `elevation` 구현(§3-2).
