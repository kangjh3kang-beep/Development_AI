## 1. 전제 표 — 확인 방법과 **실측값**

| # | 전제 | 확인 방법 | **실측값** |
|---|---|---|---|
| P1 | 두 UI 의 항목이 겹치나 | 두 정의 원문 | 베이스맵 `일반·위성·하이브리드·회색`(4) / terrain `기본지도·위성·항공뷰·표고·회색지도`(5) |
| P2 | ★**컨트롤 id 까지 같나** | `BASEMAP_SWITCHES` ↔ `terrain.controls` | ★**4/5 가 동일 id**: `base`·`satellite`·`hybrid`·`gray`. 「하이브리드」와 「항공뷰」는 **같은 `hybrid` 에 붙은 다른 라벨** |

### ★P2·P3 이 이 PR 의 근거다

사용자가 *"같은 기능 아닌가"* 라고 물었고, **같은 기능이 아니라 문자 그대로 같은 컨트롤**이다.
같은 id 를 같은 핸들러로 같은 저장 위치에 쓰고 같은 함수가 읽는다. 라벨만 둘이다.

### ★P5 — 「지형도·항공뷰」라는 이름이 이미 거짓이다

레이어 설명은 *"경사, 고저차, 항공사진을 사업 리스크와 설계 제약에 반영합니다"* 인데,
**경사·고저차를 주는 컨트롤(`elevation`)은 미구현**이고 나머지는 전부 베이스맵 전환이다.
즉 이 레이어는 **자기 주제를 하나도 수행하지 않으면서** 다른 UI 의 복제본을 들고 있다.

## 2. 변경 내용과 **회귀가 아닌 근거**

### 2-a. ★**`terrain` 레일 항목을 통째로 없앤다** (초판 설계는 틀렸고, 기존 락이 잡았다)

★**초판은 «컨트롤 4종만 걷어내고 레이어는 남긴다»였다. 실제로 만들었고, 락이 반려했다.**

남기면 그 레이어에 `mapEffect` 컨트롤이 **0개**라 팝오버가 아무것도 안 한다. 그렇다고
`status: "needs-source"`(«연동 필요»)로 적으면 **거짓**이다 — `resolveVWorldBaseLayer()` 는
여전히 `controlsByLayer.terrain` 을 읽으므로 **그 레이어의 상태가 실제 배경지도를 좌우한다.**
`SatongMapShell.status.test.ts` 가 정확히 그 위장을 잡았다:

    AssertionError: terrain: expected false to be true
    // "실데이터가 렌더링되는 레이어를 '연동 필요'로 표기하면 반대 방향 위장이다"

⇒ **라벨을 고치는 게 아니라 라벨을 없앤다.** 레일 항목을 제거하면 붙일 이름이 없어지고,
따라서 거짓 이름도 없다. 베이스맵 스위처가 **단일 소유자**가 된다.

회귀가 아닌 근거 — **P7**: 스위처는 컨트롤 객체를 인라인으로 만드므로 레이어 정의를 참조하지 않는다.
따라서 **베이스맵 전환 기능은 그대로 살아 있고**, 사라지는 것은 «같은 것을 두 번째로 보여 주던 화면»뿐이다.

### 2-b. **죽은 면제를 삭제한다** — `LAYERS_WITHOUT_POPOVER_TOGGLE`

원소가 둘 다 사라졌다(`cadastre` 는 신고①/#1012 · `terrain` 은 이 PR).
★**빈 Set 을 남기지 않는다** — 죽은 면제는 「고쳤는데 안 잠긴」 상태를 **초록으로 보이게** 한다(§36).
반대 방향을 계약으로 세운다: **레일의 모든 렌더러블 레이어는 on/off 토글을 노출한다.**

### 2-b-2. 「표고·경사」(`elevation`)는 **함께 사라진다**

미구현(`mapEffect:false`)이라 오늘 사용자에게 주는 것이 없다. 구현 시 **자기 레이어로 되살린다** —
부채를 `it.todo` 로 초록 안에 남긴다(커밋 메시지에만 적으면 드러나지 않는다).

### 2-c. 배타 전환 목록을 **파생형으로** 바꾼다 (P8)

`["base","satellite","hybrid","aerial","gray"]` 손 목록 → `BASEMAP_SWITCHES` 에서 파생 + 레거시 `aerial`.
★그리고 **베이스맵 id 일 때만** 배타 처리한다 — 지금은 terrain 의 **아무 컨트롤**이나 누르면 배타 분기를
타므로, `elevation` 이 나중에 구현되면(`mapEffect: true`) 그 클릭이 **사용자의 베이스맵 선택을 지운다.**
지금은 `mapEffect:false` 라 도달 불가이므로 **오늘의 결함은 아니고**, 걷어내는 김에 구조로 막는다.

### 2-d. ★**하지 않는 것**

- **`resolveVWorldBaseLayer` 를 건드리지 않는다.** 저장 위치(`controlsByLayer.terrain`)도 그대로다
  → **persist 마이그레이션 불필요**(기존 사용자의 베이스맵 선택이 그대로 산다).
- **베이스맵 팝오버를 건드리지 않는다** — 사용자가 요청한 표면이다(§0).
- **`terrain` 레이어의 on/off 노출을 열지 않는다**(P6) — 끄면 배경지도가 조용히 롤백된다.
  ★그 롤백은 **오늘 도달 불가**이고(토글 미노출 + 스위처가 `ensureLayerEnabled` 를 부른다), 이 PR 은 그 상태를 유지한다.

## 3. ★검증하지 못한 것

1. **화면(브라우저) 실측 없음** — 락은 렌더 테스트로 건다. 라이브 확인은 배포 후.
   ★그리고 `SatongMapShell` 은 렌더 테스트가 있지만 **`SatongMultiMap` 의 effect 본체는 무잠금**이다
   (#1012 실측: Leaflet 목이 없어 `false` 변이가 64파일 468건을 전부 통과). 이 PR 은 셸 쪽이라
   렌더 락이 유효하지만, **배경지도가 실제로 바뀌는지**는 브라우저가 있어야 안다.
2. **`elevation` 을 언제 구현할지 미정** — 이 PR 범위 밖. `status: needs-source` 로 **초록 안에 보이게** 남긴다.
3. **`aerial` 레거시 id 를 쓰는 저장분이 실재하는지 미측정** — `resolveVWorldBaseLayer` 가 아직 받으므로
   **제거하지 않고 그대로 둔다**(가를 수 없으면 가르지 않는다).
4. **성장루프 관측(인접)**: `/api/v1/tiles/vworld/wmts/Satellite/…` 가 `latency_regression` **warn**
   (p95 561ms · 평소 299ms · 표본 47). 이 PR 과 **인과 관계 없음**(런타임 타일 경로를 안 바꾼다) —
   별건 관측으로만 적는다. **미측정**: 원인.
