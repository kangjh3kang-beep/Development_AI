## 2. 변경 내용

### 2-1. ★변이 **후** 판별 층을 신설한다 (`exit 16`)

**원인이 변이 자신**인 두 형태를 판정에서 제외한다:

    (a) 변이가 **대상 파일의 구문을 깼다**  → 그 변이는 **무효**다
    (b) 변이 후 테스트가 **0건 수집**됐다   → 잡힌 것이 아니라 못 돈 것

(a)는 **확장자에서 파생**한다: `.py`→`py_compile` · `.js/.mjs/.cjs`→`node --check` ·
`.sh/.bash`→`sh -n`. ★**모르는 확장자는 검사하지 않는다** — 그리고 그 사실을 **출력에 적는다**
(조용히 건너뛰면 «검사했는데 통과» 로 오독된다).

### 2-2. ★판정 토큰을 **본문에 안 쓰이는 형태**로 **추가**한다

    ::VERDICT=CAUGHT / ::VERDICT=SURVIVED / ::VERDICT=UNDECIDED

★**기존 줄은 그대로 둔다.** 88 의 스크레이퍼(`^(CAUGHT|SURVIVED)`)가 이미 돌고 있고,
바꾸면 **빈 값**을 낸다. 더하는 것은 안전하고 지우는 것은 아니다.

★**왜 새 토큰이 필요한가**: 88 과 내가 **각각** 자기 설명문을 자기 검사기가 집는 사고를 냈다.
앵커(`^`)는 **증상**을 막고, 토큰 분리는 **원인**을 막는다 — 안내문에 `CAUGHT` 라고 써도
`::VERDICT=` 는 안 쓴다.

### 2-3. ★토큰과 rc 를 **짝으로** 둔다 (88 지적)

    ::VERDICT=UNDECIDED  ↔  exit ∈ {12, 13, 14, 15, 16}

**둘 중 하나만 바꾸면 한쪽 소비자가 조용히 틀린다.** 기존 판정 불가 경로(13·14·15)에도
같은 토큰을 붙인다.

## 3. ★검증하지 못한 것

- ★**구문 검사기 자체의 위양성/위음성** — §3 에 이 항목이 **없었고**, 적대 리뷰가 정확히

  **검사기가 「전에도 후에도 통과」시키는 의미 파손**(구문은 맞고 뜻만 깨짐)은 여전히 못 가른다 —
  그건 «변이가 무효» 가 아니라 **진짜 CAUGHT 일 수 있어** 구별을 시도하지 않는다.
- **88 외의 스크레이퍼** — ★착수 시 셌다: 저장소 안 **프로그램 소비자 0건**

### ★설계 중 내가 낸 오류 셋 (전부 조용했다)

1. **`$SNAP` 으로 구문 기준선을 재려 했다** — 스냅샷은 `mktemp` 산물이라 **확장자가 없어**
   «모르는 확장자» 로 빠지고 **기준선이 항상 통과**한다. **임시 사본은 원본의 속성을 안 갖는다.**
2. **`set -e` 아래 함수 반환 1 이 판정 대신 스크립트를 죽였다** — 볼트가 `#924` 에 적어 둔
   그 함정. **에러 메시지 없이** 기준선 직후 멈추는 것으로만 드러났다.
3. **타임아웃이 변이 원복을 끊어 변이가 작업 트리에 남았다** — 도구 자신은 `trap` 으로 막는데
   **내 임시 하네스에는 없었다.** 이후 실행에 `trap … EXIT INT TERM` 을 넣었다.

## 7. ★이 레인의 **구조적 위험** — 도구는 `scripts/`, 락은 `propai-platform/tests/`

동료 `development-ai-3a` 가 자기 PR 의 2차 적대 리뷰에서 찾아 공유했고, **내가 직접 재서 확증**했다.

### 실측 (`origin/main` 의 `ci.yml:43`)

    if grep -qE '^(propai-platform/|\.github/workflows/ci\.yml$)' <<<"$FILES"; then
      platform=true
    else
      platform=false     # ← Backend (pytest) 잡이 **skip**

    scripts/mutate_manual.sh 단독 → **platform=false**
    #957 전체            → platform=true (우연히 `propai-platform/tests/` 를 건드림)

★**GitHub 은 skip 된 필수 잡을 「충족」으로 계수한다.** 즉 **도구만 고치는 PR 은
락이 한 번도 안 돌고 초록으로 머지된다** — 이 저장소 표현으로
*"면제를 남기면 락은 skip 이라 무잠금"* 의 **CI 판**이다.

### 이 PR 은 안전하다 — 그런데 **다음 PR 이 위험하다**

`#957` 은 `propai-platform/` 을 건드려 통과한다. 위험한 것은 **rc 판별 한 줄만 고치는**
후속 커밋이다. **이 도구의 락은 전부 `propai-platform/tests/` 에 있고 도구는 `scripts/` 에 있다** —
정확히 그 이음매다.

### 처방은 `3a` 의 `#958` 에 있다 (중복 구현하지 않는다)

    필터를 `^(propai-platform/|scripts/|\.github/workflows/ci\.yml$)` 로 확장
    + 파생형 락(루트 스위트 테스트에서 `scripts/…` 참조를 **긁어** 필터와 대조)
    + 음성 축(`README.md`·`docs/` 는 매치되면 안 됨 — 전부 매치하면 검사가 무의미)

★**`#958` 착지 전까지는 도구만 고치는 커밋을 내지 않는다.** 내야 하면
`propai-platform/` 아래 파일을 한 줄이라도 함께 건드려 `platform=true` 를 만든다.

### ★일반화

> **락과 대상이 다른 경로에 있으면, 「그 경로가 CI 감시 안에 있는가」를 따로 물어야 한다.**
> 락이 있다는 것과 **락이 도는 것**은 다르다. 이 저장소는 pytest 의
> `testpaths`(로컬 986 vs CI 10,344)와 ruff 의 `working-directory` 로 **같은 형태를 두 번** 겪었다 —
> 이번이 **세 번째**이고 매체만 달랐다(경로 필터).
