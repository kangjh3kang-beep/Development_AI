## §6 작업 규율 (이 캠페인이 비싸게 배운 것)

- **실측 → 구현 → 3층 변이(로직·배선·표면) → 게이트 → 독립 적대검증 → 봉합 → 머지 → 배포요청.**
- **자기승인 금지.** 승인 패스는 반드시 작성 컨텍스트와 **분리된** 서브에이전트.
- 계획·설계·분석을 제시하기 **전에** `/insight-loop` — 반사적 적대통찰 생성 후 증거로 검증(propose → dispose).
- **새 분기를 만들면 그 분기를 태우는 테스트를 같은 커밋에 넣는다.**
- **"생존" 보고 전에 주입이 실제로 됐는지 확인**(부분 치환·이스케이프 위양성).
- 게이트는 **마지막 변경 뒤** 재실행.
- sw 범프가 필요하면 PR 생성 **전에** 보드 claim.
- **"반례를 못 찾았다"를 "반례가 없다"로 승격하지 말 것** — 표본이 아니라 **코드 경로**로 논증한다.
- 리뷰 에이전트에게 같은 워크트리를 주면 **내 미커밋 편집을 덮는다.** 커밋 후 넘기거나 별도 워크트리를 쓰게 한다.

### ★이 세션에서 새로 얻은 것

**선대의 기록이 후대의 설계를 직접 교정했다.**

배선 락을 추가하고 나서 자체 적발했다 — 그 락이 판정 **조합을 재현**할 뿐 `desk_appraisal_service` 를
태우지 않는 **공허 배선 단언**이었다. 통과하는 테스트를 써 놓고 "잠갔다"고 말할 뻔했다.

그래서 저장소의 기존 배선 검증 방식을 찾아봤더니 `tests/test_comparable_sample_wiring.py` 헤더에
**선대의 같은 자체 적발**이 적혀 있었다 — *"처음엔 이름 존재 검사였는데 변이가 통과했다. 응답 dict 의
키 이름이 그대로 남아 정규식에 매치됐기 때문이다. **이름이 어딘가에 있다는 것과 그 함수를 호출한다는
것은 다르다**"*. 그대로 따라 **호출 형태 + 임포트문** 둘 다 못 박았고 생존 변이 2건이 즉시 죽었다.

공허진리 클래스 대응 **6번째**이고(W2c 사후적발 → #497 가드 masking → #543 검사 비공허 →
#554 자기 골든 선제 → #552 R3 자체 적발 → **#558 선대 기록 재사용**), 처음으로 **기록이 재사용된**
사례다. 기록이 남지 않았다면 나는 같은 함정에 두 번째로 빠졌을 것이다.

→ **함의**: 자체 적발한 함정은 반드시 **그 파일 헤더**에 남겨라. 다음 사람이 읽는다.
