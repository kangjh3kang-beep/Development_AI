## 2. 변경 내용

`is_valid_pnu` 를 **모든 자리에 배선**한다. 새 함수를 만들지 않는다 — **있는 것을 안 쓴 것**이다.

- 단방향 10건 · 길이만 6건 → `is_valid_pnu(...)`
- `_land_info`(P10) → 유효할 때만 외부 호출
- `parcel_excel_service.py:401` · `project_pipeline.py:1843`(이미 옳음)도 **같은 함수로 통일** —
  옳은 구현이 두 벌이면 다음 사람이 어느 쪽을 복사할지 모른다

### 회귀가 아닌 근거

- `is_valid_pnu` 는 `^\d{19}$` 이고, **진짜 19자리 숫자 PNU 의 거동은 모든 자리에서 동일**하다
  (§3 모집단 A 가 그것을 잰다).
- 걸러지는 값은 전부 **애초에 쓸 수 없는 값**이다 — 자르면 가짜 코드가 되고, 외부로 보내면 실패한다.
- 각 자리에 **이미 폴백 경로가 있다**(`return None` · `continue` · `"pending"` · `reason` 문구).
  새 경로를 만들지 않았다.

## 4. ★검증하지 못한 것

- **라이브에서 이 경로들이 오염값으로 실제 호출된 적이 있는지는 미측정**이다.
  P7·P8 은 *"오염값이 존재하고, 그것이 가드를 통과한다"* 까지이고,
  *"통과해서 건축물대장 API 에 `"store"` 가 실제로 나갔다"* 는 **관측하지 않았다.**
- **외부 API 벤더 로그**는 볼 수 없다 — PII(성명)가 외부에 남았는지 **확인 불가**.
- `_land_info`(P10) 수정은 **단위 테스트로만** 잠근다. VWorld 실호출은 하지 않는다.
- `decision_brief_service.py:434` 등 **길이만 6건은 현재 관측된 오염값(6자·26자)에 걸리지 않는다** —
  즉 **잠재**다. 「지금 새고 있다」고 주장하지 않는다.
- 성명이 PNU 칸에 들어간 **상류(토지조서 파싱)** 는 여전히 **미측정**이다(`#941` 과 동일).
