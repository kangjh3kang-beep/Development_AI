## 2. 변경 내용과 그것이 회귀가 아닌 근거

- `_fetch_ordinance_xml` 의 **두 호출부**에 `raise_unless_expected_xml` 을 배선. **형제
  `_fetch_from_moleg_api` 와 동일한 형태**이고 상수도 그대로 재사용한다(새로 만들지 않는다).

  ★형제가 그 한계를 이미 주석에 적어 뒀고, **같은 문장을 여기에도 적었다**(호출부가
  *"조회 실패"* 와 *"조례 없음"* 을 구분하게 만드는 것은 **별건**).
- 회귀 아님 근거: 조례 관련 **561 passed**(`-k "ordinance or moleg or slope"`) · 정상 경로
  두 번째 모집단 락으로 **과잉 억제 아님**을 같은 실행에서 증명.

## 3. ★검증하지 못한 것 / 내가 틀린 것

1. **★내 첫 판정이 틀렸다 — 낡은 트리에서 읽었다.** 처음에 *"헬퍼가 JSON 전용이라 XML 경로를
   만들어야 한다"* 고 보드에 CLAIM 했는데 **거짓**이다. 공유메인 워크트리가 **8커밋 뒤처져**

   재측정하고서야 알았다. 보드에 정정을 올렸다.
   ★볼트에 *"도구가 「없다」고 답하면 트리 지연부터 의심하라"* 가 적혀 있고 **알면서 밟았다.**
2. **BCR/FAR 소비처 수 미측정** — 인계서는 11개라 적었으나 **내가 세지 않았다.**
3. **프로덕션 상태 미측정** — 168 컨테이너의 `MOLEG_API_KEY`/IP 등록 상태를 확인하지 않았다.
   즉 *"지금 라이브에서 이 경로가 실제로 실패 중인가"* 는 **모른다**.
4. **화면 폴백은 그대로다** — 이 PR 은 오귀속을 **관측 가능**하게만 만든다. 사용자가 보는
   *"국가기준 25도 폴백"* 문구는 여전히 조회 실패와 조례 부재를 **구별하지 않는다**.
5. **`gosi_search_service`·`regulation_monitor` 는 안 봤다** — 둘 다 JSON 이고 배선돼 있다는

# 6. 독립 적대 리뷰 — **REQUEST CHANGES 를 받았고 봉합했다**

## 6-1. ★H2 — 내가 고친 결함의 **한 층 아래**가 그대로 열려 있었다

`guarded_functions()` 가 «가드를 가진 **함수 이름의 집합**» 이라, **한 함수에 XML 호출이
둘인데 가드가 하나**면 통과했다. 리뷰어가 「무가드 Step 3」 변이로 **SURVIVED** 를 실증했다.

★**이 PR 이 고친 것이 "형제 **함수**가 무방비"였는데, "같은 함수의 형제 **호출부**가 무방비"는
  남아 있었다.** 계획서 §5 가 *"다섯 번째가 생기면 자동 감시"* 라 선언했지만
  **같은 함수 안의 다섯 번째는 감시되지 않았다.**

→ 판정 축을 **함수 → 호출부 개수**로 내렸다(`guard_counts()`, `XML 수 <= 가드 수`).
  재판정: 리뷰어의 그 변이 → **CAUGHT**(`{'_fetch_ordinance_xml': {'xml': 3, 'guard': 2}}`).

## 6-2. ★M2 — **형제가 둘인데 틀린 쪽을 근거로 댔다**

*"형제와 동일하므로 `except Exception` 이 `MolegDrfError` 를 삼켜도 된다"* 고 적었는데,
형제는 **둘**이고 다른 하나는 **이미 옳게** 한다:

| 형제 | 처리 |
|---|---|
| `_fetch_from_moleg_api` | 광범위 `except` 에 삼킨다 — **같이 틀렸다**(내가 고른 쪽) |
| `gosi_search_service` | **사유를 반환값에 싣는다** — ★정답 기준선 |

그리고 **헬퍼 자신이 명문으로 요구**한다: *"`MolegDrfError` 는 일반 예외와 **다른 타입**이어야
한다 … 뭉치면 다시 침묵이 성공으로 읽힌다."*

→ **전용 `except MolegDrfError` 분기**를 넣어 로그에서 「조회 실패」와 「조례 없음」을 가른다
  (*"조례 부재 아님"* 문구 · 두 모집단 락으로 확인).
→ ★사유가 **호출부까지** 닿는 것은 `resolve_slope_criteria` 의 계약 변경이 필요해 **별건**이고,
  **부채를 초록 안에 보이게** 남겼다(`test_reason_should_reach_the_caller` · `xfail(strict=True)`).
