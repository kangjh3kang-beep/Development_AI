## §3 ★검증하지 못한 것

- **`(행없음)` 분기의 부분 반증**: `analysis_fields` 가 세 모집단(행 없음 / dict 아님 / **dict 인데 `state` 빈 값**)을 한 라벨로 접는다. ③의 경우 **axes 가 읽히는데도 버리고 원인을 단정**한다(*"연속 미실행"*). ★**라이브 도달은 미측정** — 현 생산자는 항상 `state` 를 쓴다(`analyzer.py:605`). **이 PR 범위 밖**으로 두고 좌표만 남긴다.
- **`growth_schedule` 키가 라이브 `active_flags` 에 없다**(실측). `schedule_verdict` 가 현재 `unknown` 인 원인이 **미배포인지 `/heal-log` 필터인지 안 갈랐다.**
- **`analyze_period_min`(4번째 인자) 프로덕션 소비처 0** — 셸이 3개만 넘긴다(`:142`). `(행없음)` 사유의 ` · analyze 주기 %s분` 은 실전에서 **항상 빈 문자열**이다. 이 PR 에서 안 고친다(범위).
- **C 의 부작용 미측정**: 게이트 밖으로 꺼내면 그 절이 **항상** 출력된다. 출력량이 늘어 사람이 덜 읽게 되는지는 **안 쟀다**. ★그래서 `kind` 는 그대로 두어 **exit code 빈도는 불변**으로 묶는다.
