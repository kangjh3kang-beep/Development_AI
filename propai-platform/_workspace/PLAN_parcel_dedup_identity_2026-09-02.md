## §2 두 방향으로 동시에 틀렸다

    ① 접힘  같은 동 단위 주소를 공유하는 **서로 다른 필지**가 한 건으로 사라진다
    ② 중복  **같은 필지**가 표기 차이로 두 건이 되고, 보강이 표기를 수렴시킨 **뒤에도** 안 접힌다

★②가 더 조용하다 — 사용자는 «중복제거를 했다» 는 화면 문구를 보고 «중복이 없다» 고 읽는다.

## §3 변경 내용

- **2단계** `GlobalAddressSearch` 4곳(847·979·1148·1158) → `parcel-entry-identity` 경유
- **3단계** 보강 수렴 직후 `dedupeByIdentity` 재적용 (**전제 4가 근거**)
- **4단계** 계약 테스트에 **행위 축 스윕** 추가(«그 카드를 렌더하는 파일» → «정체성을 비교하는 파일»)
- **★4단계가 찾아낸 형제** `SatongMapShell` 2곳 — `(a.pnu && b.pnu===a.pnu) || b.address===a.address`
  는 **PNU 가 달라도 주소만 같으면 참**이었다(필지 A 삭제 → 필지 B 패널이 닫힘)

★**단순 치환을 하지 않았다.** `entryIdentityKey` 동일성으로 바꾸면 한쪽만 PNU 를 가진 정상
상황에서 키가 갈려 **유령 패널 결함(R1 HIGH)이 되살아난다.** 그래서 `isSameParcel` 을 따로 뒀다:
**둘 다 유효 PNU 면 PNU 가 결정하고, 한쪽이라도 없으면 주소로 판단**한다.

★규칙을 호출부에 인라인으로 두지 않았다 — `#941` 이 *"구현이 두 벌이면 한쪽만 고쳐진다"* 로
값을 치른 자리다.

## §4 잠금

- **모듈 4모집단** A 안 접힘 / B 수렴 후 접힘 / C 앵커 없음 보존 / D 오염 PNU 는 앵커 아님
- **배선(컴포넌트)** 실사용 경로 그대로 — 검색 스텁이 **실제 `onSelect` 를 부른다**
  (빈 div 로 두면 그 경로가 전혀 안 태워진다). 관측점은 지도 스텁의 `data-parcels`
- **음성 대조군** 해소가 안 되면 **접지 않는다**(과잉 병합 금지) — 두 모집단이 **다른 수**를 낸다
- **스윕(4단계)** 모집단은 프로덕션 소스 전수에서 파생. 검출기를 **양성·음성 양방향**으로 검증

## §5 ★검증하지 못한 것

1. **라이브 프로브 미실시.** 이 PR 은 단위·컴포넌트 락까지다. 실제 엑셀 업로드로 재현하지 않았다
2. **상류(토지조서 파싱)는 여전히 미측정** — `#941` 의 정직 절을 그대로 승계한다(하류만 막는다)
3. **이미 저장된 중복 행은 남는다** — 마이그레이션 없음. 읽는 쪽이 접을 뿐이다
4. **`SatongMapShell` 2곳은 라이브 확인 안 했다** — 스윕이 찾아낸 것이고 단위 락만 있다
5. **검출기의 상한** — `===` 형태만 본다. `==`·`localeCompare`·`Set` 외 자료구조는 **안 잡는다**
6. **로컬 회귀에서 `loadLeaflet` 3건이 빨갛다** — `leaflet` 패키지가 **양쪽 워크트리 모두에 없는**
   기존 환경 갭이고 이 PR 은 그 파일을 건드리지 않는다. CI 는 신규 설치라 무관할 것으로 **보나
   확증은 CI 결과로 한다**(추론이라고 적는다)
