## 4. 규율 (반드시 지켜라)

1. **리뷰 보고의 "범위"도 실측하라** — R2/R3 지적 4건이 범위가 틀렸다. 그대로 실행했으면
   정상 코드를 나쁘게 바꿨다.
2. **"실측했다"는 말도 검증 대상이다** — 내가 "실측된 오답 4건"이라 쓴 것 중 1건만 참이었다.
   실측의 **범위**(어떤 진입점으로 무엇을 호출했나)를 함께 적어라.
3. **목록형 골든은 새 항목을 못 잡는다** — 생산물을 **실행으로 전수 열거**하는 형태로 써라.
4. **변이 생존은 두 가지 뜻이다** — "가드가 약하다" vs "그 코드가 아무 일도 안 한다".
   변이 상태의 **산출값**으로 구분하라. 후자면 코드를 **철회**하라.
5. **배선은 grep보다 컴파일러** — 인자를 필수로 만들면 우회 불가하다.
6. **커밋 먼저 → 변이 → 원복.** 미커밋 상태 `git checkout --`는 작업을 날린다.
   새 파일(untracked)은 `git checkout`이 안 먹는다.
7. **CI Backend 잡은 pytest 앞에 ruff를 돌린다** — 로컬 테스트만으론 안 걸린다.
8. **"안 보인다"를 결함으로 판정하기 전에 그게 언제·어떻게 렌더되는 구조인지 봐라.**
   UX 진단 가설 8개 중 3건이 셀렉터/오프캔버스 아티팩트였다.
9. **배포 판정은 "출력이 갈리는 입력"으로.** 버전 문자열·health로는 못 한다.
10. 브라우저 검증 시 ref 클릭이 이 앱에 안 닿는다 → **DOM `element.click()`(eval)**.
    검증 후 스토리지·세션 와이프.
