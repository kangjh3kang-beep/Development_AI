# 판정 불가(동적 세그먼트) — 고아로도 소비로도 **세지 않는다**. 눈에 보이게 남긴 목록이다.
#
# 프론트에 ``<부모경로>/${...}`` 형태의 **마지막 세그먼트 동적 호출**이 있어서,
# 이 리터럴 라우트가 그 호출로 실제 불리는지 정규식으로는 확정할 수 없다.
# 조용히 "소비"로 넘기면 진짜 고아가 숨고, 고아로 세면 없는 결함을 만든다.
#
# 【★2026-08-21 — 13건 중 **9건이 자동으로 결론났다**. 사람 판정이 아니라 도구를 고쳤다】
# 이 파일의 종전 머리글은 *"결론이 나면 이 파일에서 지우고 확정 고아 기준선으로 옮겨라"* 라고
# 지시했다. **그 지시는 실행 불가였다** — 그대로 하면 래칫 2개가 깨진다(실측):
#   · `test_판정불가가_양방향으로_잠긴다` → `removed` 단언 실패(도구는 여전히 13건을 낸다)
#   · `test_기준선이_줄면_알려준다`     → 도구가 고아로 안 세는 항목이 기준선에 들어와 실패
# 두 래칫 모두 **사람의 결론이 아니라 도구의 분류**와 대조하기 때문이다. 그래서 사람이 내린
# 판정은 **어디에도 착지할 수 없었다.** → 사람 메모를 남기는 대신 **도구에 메서드 게이트**를
# 넣었다(`scripts/orphan_routes.py::call_method_at`). 근본은 이것이었다:
#   **분류기가 라우트의 HTTP 메서드를 갖고 있으면서 쓰지 않았다.**
#   `` `/blockchain/escrow/${id}` `` 를 **GET** 으로 부르는 화면은 **POST** 라우트인
#   `/escrow/fund` 를 부를 수 없다. 메서드를 보자 9건이 확정 고아로 내려갔다.
# ★게이트는 한 방향이다 — **메서드를 확실히 읽었고 다를 때만** 배제한다. 못 읽으면 남긴다.
#
# 【남은 4건 — 왜 여전히 판정 불가인가】
#   · /market/report/{pdf,docx,pptx} → **진짜 소비**. `fmt: "pdf"|"pptx"|"docx"` 유니온이고
#     호출부도 `fetch(..., {method:"POST"})` 라 라우트(POST)와 **메서드가 일치**한다
#     (MarketInsightsWorkspaceClient.tsx:777). 도구가 가를 수 없는 것이 맞다.
#   · /underwriting/history → 호출부가 `endpoint={`/underwriting/${projectId}`}` 로
#     **프롭에 경로만 넘긴다** — 메서드가 그 자리에 없어 도구는 읽지 못한다.
#     ★사람 판정(2026-08-21): 프론트는 `POST /underwriting/{project_id}` 만 부른다
#       (UnderwritingSection.tsx:124 · workspace-extended-panels.ts:191). `GET /history` 를
#       부르는 곳은 전수 조회에서 **없다** → 실질 고아일 가능성이 높다. 다만 도구가 스스로
#       확정하지 못하므로 **줄은 남긴다**(사람 메모로 조용히 지우면 래칫이 거짓말한다).
#
